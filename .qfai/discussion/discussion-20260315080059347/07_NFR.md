# 07_NFR

## Non-Functional Requirements

| NFR-ID   | Category        | Title                                   | Description                                                                                                                                                                                                                  | Measurable Target                                                | Source             |
| -------- | --------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------ |
| NFR-0001 | Compatibility   | 既存 UI Contract 後方互換性             | 既存の `CON-UI-XXXX` YAML フォーマットとの後方互換性を維持する。新フィールドは optional とし、既存ファイルが新バリデーションで破壊されないこと。                                                                             | 既存 UI Contract YAML の 100% が新バリデーションに PASS          | SRC-0001, SRC-0019 |
| NFR-0002 | Extensibility   | プラットフォーム拡張性                  | 新しいプラットフォーム（VR/AR、車載等）の UI/UX 基準を追加する際に、コアロジックの変更なしにルール追加のみで対応できること。                                                                                                 | 新プラットフォーム追加時のコア変更行数 = 0                       | SRC-0019           |
| NFR-0003 | Extensibility   | ベストプラクティス/アンチパターン拡張性 | 新しいルールの追加がファイル追加のみで可能であり、既存ルールエンジンの変更が不要であること。                                                                                                                                 | 新ルール追加時のエンジン変更行数 = 0                             | SRC-0019           |
| NFR-0004 | Usability       | HTML Mock 可読性                        | HTML+CSS Visual Mock がブラウザで直接開いてプレビュー可能であり、Design Token のフォールバック値によって外部依存なしで表示されること。                                                                                       | ブラウザでの表示率 100%（外部依存 0）                            | SRC-0019           |
| NFR-0005 | Usability       | Design Token YAML 可読性                | Design Token YAML が人間にとって読みやすく、IDE のシンタックスハイライトで正しく表示されること。                                                                                                                             | YAML lint PASS, コメント付き                                     | SRC-0019           |
| NFR-0006 | Performance     | バリデーション速度                      | UI/UX 関連のバリデーション（Design Token + HTML mock + UI Contract 整合性チェック）が通常の `qfai validate` 実行時間を 2 秒以上増加させないこと。                                                                            | 追加実行時間 < 2s                                                | SRC-0019           |
| NFR-0007 | Accessibility   | WCAG 2.2 AA 準拠チェック                | 自動チェック可能な WCAG 2.2 AA 基準（コントラスト比、タッチターゲットサイズ等）を検出できること。                                                                                                                            | WCAG 2.2 AA 自動チェック可能項目のカバー率 ≥ 80%                 | SRC-0009, SRC-0019 |
| NFR-0008 | Maintainability | ドキュメント自己整合性                  | UI 定義 3 点セット（Design Token + HTML Mock + Mermaid）と UI Contract の間に不整合がある場合、`qfai validate` がエラーとして検出すること。                                                                                  | 不整合検出率 100%                                                | SRC-0019           |
| NFR-0009 | Portability     | Git フレンドリー                        | すべての UI 定義ファイル（Design Token YAML, HTML Mock, Mermaid, UI Contract YAML）がテキストベースで、Git の diff/merge で有意義な差分表示が可能であること。                                                                | バイナリファイル 0                                               | SRC-0019           |
| NFR-0010 | Reliability     | レビュー再現性                          | 同一の成果物に対して同一のルールセットで UI/UX 自動チェックを実行した場合、結果が毎回同一であること。                                                                                                                        | 再現率 100%                                                      | SRC-0019           |
| NFR-0011 | Quality         | リサーチ品質                            | 各専門家サブエージェントが実施するリサーチが、対象プラットフォーム・ドメインに適した最新（直近 2 年以内）のベストプラクティス/アンチパターンを網羅していること。リサーチ結果にソース・信頼度・適用条件が明記されていること。 | リサーチ項目のソース明記率 100%、直近 2 年以内の情報参照率 ≥ 80% | SRC-0020           |
| NFR-0012 | Usability       | 統合レビュー品質                        | 統合レビュアーのレビュー結果が、個別専門領域の評価だけでなく、サービス全体のユーザー体験の一貫性・使いやすさを評価する観点を含むこと。                                                                                       | 統合レビュー項目の 100% に「サービス全体への影響」記述あり       | SRC-0020           |
