# 07_NFR — 非機能要件定義

## 非機能要件一覧

### NFR-0001: 保守性 — TypeScript 型安全

| 項目 | 内容 |
|---|---|
| **ID** | NFR-0001 |
| **タイトル** | TypeScript 型安全の徹底 |
| **カテゴリ** | 保守性（Maintainability） |
| **優先度** | must |
| **ステータス** | draft |
| **SRC** | SRC-0001, SRC-0002 |
| **目標（測定可能）** | - `any` 型の新規追加 **ゼロ件**<br>- `@ts-ignore` / `@ts-expect-error` の新規追加 **ゼロ件**<br>- `pnpm check-types` エラー **ゼロ件**<br>- 型アサーション（`as`）は型ガードによる narrowing で置き換え可能な場合は使用禁止 |
| **検証方法** | `pnpm check-types` CI 通過。コードレビューで `any` / `@ts-ignore` を確認 |
| **違反時の対応** | PR をブロック。コメントで修正箇所を指摘 |
| **関連 REQ** | REQ-0001〜REQ-0009 全件 |

### NFR-0002: 信頼性 — バリデータは fail-closed

| 項目 | 内容 |
|---|---|
| **ID** | NFR-0002 |
| **タイトル** | バリデータの fail-closed 動作保証 |
| **カテゴリ** | 信頼性（Reliability） |
| **優先度** | must |
| **ステータス** | draft |
| **SRC** | SRC-0001, SRC-0006 |
| **目標（測定可能）** | - 新規バリデーションルールが warning-only パスを持つことを **禁止**（0件）<br>- 制約違反に対してバリデータが `Error` または `ValidationError` を返すことを **100%** のネガティブテストで確認<br>- `console.warn` への fallback は **禁止**<br>- エラーメッセージは具体的（どのフィールドが何の値でなぜ違反か）で **50 文字以上** |
| **検証方法** | ネガティブフィクスチャテスト（REQ-0009）GREEN。コードレビューで warning パスを確認 |
| **違反時の対応** | PR をブロック。warning-only コードを即 fail-closed に修正 |
| **関連 REQ** | REQ-0001, REQ-0002, REQ-0003, REQ-0004, REQ-0006, REQ-0007 |

### NFR-0003: テスト容易性 — 各 WS のネガティブフィクスチャカバレッジ

| 項目 | 内容 |
|---|---|
| **ID** | NFR-0003 |
| **タイトル** | ネガティブフィクスチャカバレッジの保証 |
| **カテゴリ** | テスト容易性（Testability） |
| **優先度** | must |
| **ステータス** | draft |
| **SRC** | SRC-0001, SRC-0006 |
| **目標（測定可能）** | - WS-1: ネガティブテストケース **最低3件**<br>- WS-2: ネガティブテストケース **最低1件**<br>- WS-3: 各8カテゴリに対するネガティブテストケース **最低8件**<br>- WS-4: ネガティブテストケース **最低2件**<br>- 全テストスイートが CI で GREEN<br>- 各テストは期待エラーメッセージを文字列照合で確認 |
| **検証方法** | `pnpm test` 全件 GREEN。テストファイルのネガティブケース件数をコードレビューで確認 |
| **違反時の対応** | 不足件数分のテストを追加してから PR をマージ |
| **関連 REQ** | REQ-0009 |

### NFR-0004: 一貫性 — runtime と validator のセマンティック契約の共有

| 項目 | 内容 |
|---|---|
| **ID** | NFR-0004 |
| **タイトル** | runtime と validator が同一のセマンティック契約を共有 |
| **カテゴリ** | 一貫性（Consistency） |
| **優先度** | must |
| **ステータス** | draft |
| **SRC** | SRC-0001, SRC-0002 |
| **目標（測定可能）** | - `terminationReason` の enum 値定義は runtime と validator で **同一ソース** から参照（コピー禁止）<br>- `finalDecision` / `reviewerSignoff.status` のマッピングは **1箇所** に定義（DRY）<br>- `assertConcreteArtifactRefs()` ヘルパーは `l2Evidence.ts` または `prototypingEvidence.ts` の **1ファイル** に定義され、全カテゴリで再利用<br>- `declaredRef` バリデーション正規表現は **1箇所** に定義 |
| **検証方法** | コードレビューで重複定義がないことを確認。`grep` で enum / regex の重複を検索 |
| **違反時の対応** | 重複定義を共通モジュールへ移動 |
| **関連 REQ** | REQ-0001, REQ-0004, REQ-0005, REQ-0006, REQ-0007 |
