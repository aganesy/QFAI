# 08 Glossary

## Terms

| Term                              | Definition                                                                                                                                                                                                                                                  | Context                                                                                          | Source   |
|-----------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------|----------|
| concrete artifact ref             | A repo-root relative path to a specific file (with optional line number `#L12` or anchor fragment `#section-id`). Must have a recognized file extension (`.md`, `.json`, `.png`, `.html`, etc.). Absolute paths, directory paths, bare filenames, and synthetic tokens are not concrete artifact refs. | Used in all leaf-field evidenceRefs arrays across the prototyping evidence bundle                | SRC-0001 |
| leaf field                        | An evidence field nested inside an array element (e.g., `runtimeGate.ui[i].declaredRef`, `l1.axes[j].evidenceRefs[k]`, `reviewerLogs[l].evidenceRefs[m]`). Leaf fields are the deepest ref-bearing fields in the prototyping evidence structure. Rev8 closed top-level fields; rev9 closes leaf fields. | Used to distinguish the rev9 target scope from the rev8 scope                                   | SRC-0001 |
| runtimeGate.ui[]                  | The screen-level ledger inside the `runtimeGate` summary. Each row represents a single UI screen's runtime gate evidence. Contains `declaredRef` (which spec declaration this screen corresponds to), `renderEvidenceRefs[]` (render evidence), and `browserQaEvidenceRefs[]` (Browser QA evidence). | `prototypingEvidence.ts` validates this structure; rev9 adds leaf-level concrete-ref enforcement | SRC-0001 |
| declaredRef                       | A leaf field in a `runtimeGate.ui[]` row that identifies which spec declaration was observed. Must be a concrete artifact ref pointing to the relevant spec file and location. Required (not optional) after rev9.                                           | `runtimeGate.ui[].declaredRef`; previously optional/unchecked; rev9 makes it required + concrete | SRC-0001 |
| renderEvidenceRefs[]              | A leaf array in a `runtimeGate.ui[]` row containing concrete artifact refs to render evidence artifacts (e.g., screenshots, DOM snapshots). Must be non-empty and all entries must be concrete artifact refs.                                                | `runtimeGate.ui[].renderEvidenceRefs[]`; rev9 enforces non-empty + concrete                     | SRC-0001 |
| browserQaEvidenceRefs[]           | A leaf array in a `runtimeGate.ui[]` row containing concrete artifact refs to Browser QA evidence artifacts (e.g., QA report JSON files). Must be non-empty and all entries must be concrete artifact refs.                                                 | `runtimeGate.ui[].browserQaEvidenceRefs[]`; rev9 enforces non-empty + concrete                  | SRC-0001 |
| axis-level evidenceRefs           | The `evidenceRefs[]` field on each element of `fullHarness.iterations[].l1.axes[]` and `l2.axes[]`. Contains concrete artifact refs to axis-level evaluation evidence. Must be non-empty and all entries concrete. Previously checked as string arrays only. | `l1/l2.axes[].evidenceRefs[]`; rev9 adds concrete-ref enforcement                               | SRC-0001 |
| reviewer-level evidenceRefs       | The `evidenceRefs[]` field on each element of `fullHarness.reviewerLogs[]`. Contains concrete artifact refs to reviewer evidence artifacts. Must be non-empty and all entries concrete. Previously accepted synthetic tokens like `"reviewer:1"` silently.   | `reviewerLogs[].evidenceRefs[]`; rev9 adds concrete-ref enforcement                             | SRC-0001 |
| synthetic token                   | A string used as a placeholder or human-readable label that does not resolve to a real artifact. Examples: `"a"`, `"b"`, `"reviewer:1"`, `"specs: all covered"`. Forbidden in all evidence ref fields after rev9.                                           | Any evidenceRefs or declaredRef field; rev9 closes the leaf-field loophole                      | SRC-0001 |
| self-ref                          | A ref that points to `prototyping.json` itself (e.g., `.qfai/evidence/prototyping.json#/...`). Self-refs are circular and forbidden in all evidence ref fields.                                                                                              | All evidenceRefs fields; already enforced at top-level by rev8; now enforced at leaf level by rev9 | SRC-0001 |
| isConcreteArtifactRef             | Helper function in `pathUtils.ts` (created in rev8) that returns `true` if the given string is a valid concrete artifact ref, `false` otherwise. Rev9 reuses this function without modification for all new leaf-field validation.                          | Used by `prototypingEvidence.ts` for all leaf-field checks in WS-1                              | SRC-0001 |
| package-wide strict traceability  | The state where every ref-bearing leaf field in the prototyping evidence bundle has been formally validated as a concrete artifact ref. Rev8 achieved top-level strict traceability. Rev9 achieves package-wide strict traceability by closing the leaf-field gaps. | The target state of `packages/qfai` at v1.7.15 completion                                      | SRC-0001 |
