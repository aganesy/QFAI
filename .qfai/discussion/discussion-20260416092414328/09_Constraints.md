# 09 Constraints

## Technical Constraints

| ID   | Constraint                                                                                                                                                                                                 | Rationale                                                                                                              | Impact                                                                                                                              |
|------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| TC-1 | All concrete artifact refs must use POSIX path separator `/`. Windows `\\` is forbidden in any value written to `declaredRef`, `renderEvidenceRefs[]`, `browserQaEvidenceRefs[]`, `axes[].evidenceRefs[]`, or `reviewerLogs[].evidenceRefs[]`. | Cross-platform reproducibility. A ref with `\\` would fail `isConcreteArtifactRef()` and produce non-deterministic audit artifacts. | `assertConcreteArtifactRef()` in `execution.ts` already rejects `\\`; new test cases explicitly cover Windows separator in `browserQaEvidenceRefs`. |
| TC-2 | `prototypingEvidence.ts` leaf-field validation must reuse `isConcreteArtifactRef()` from `pathUtils.ts`. No independent regex or grammar implementation may be introduced.                                  | DRY principle and grammar drift prevention. Parallel implementations would create a single-point-of-failure gap if the grammar changes. | New validation code imports from `pathUtils.ts`; no independent pattern definition in `prototypingEvidence.ts`.                     |
| TC-3 | `runtimeGate.ui[].declaredRef` is a required field. All existing evidence bundles without this field will fail validation after rev9.                                                                       | Backward compatibility is explicitly abandoned (design doc §0 and §3-2). Rev9 is a breaking change.                   | Any consumer that previously passed `ui[]` rows without `declaredRef` must add the field. No migration shim is provided.           |
| TC-4 | All new code in `packages/qfai` must satisfy TypeScript strict mode. No `@ts-ignore`, no bare `any` in new code, no `as unknown as T` without justification.                                               | Existing policy (CLAUDE.md, QFAI AGENTS.md). Type safety is a first-class constraint.                                 | All new validator extension code must have explicit types. `ui[]` row type must be named (not inline); leaf array types must be `string[]` not `string[] | undefined | null`. |
| TC-5 | Leaf arrays (`renderEvidenceRefs[]`, `browserQaEvidenceRefs[]`, `axes[].evidenceRefs[]`, `reviewerLogs[].evidenceRefs[]`) are required and must not be `undefined`, `null`, or empty. If a runtime builder cannot populate them, it must throw. | Fail-closed policy (design doc §3-2). Empty or absent leaf arrays silently pass if not validated, defeating the purpose of the contract. | Builder code must not return evidence bundles with null or omitted leaf arrays. Runtime failures at build time are preferable to silent validation gaps. |

## Operational Constraints

| ID   | Constraint                                                                                                                                                                                 | Rationale                                                                                               | Impact                                                                                                                                        |
|------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| OC-1 | Test suite must pass before PR merge. Commands: `pnpm vitest run --project validators` and `pnpm vitest run --project core`. Both must exit with 0.                                       | CI gate. PR merge is blocked until all tests pass.                                                      | All new negative test cases, fixture replacements, and closure test extensions must be authored and passing before merge.                     |
| OC-2 | Format, lint, and type checks must pass: `pnpm format:check && pnpm lint && pnpm check-types`. All three must exit with 0.                                                                | CI gate. Code quality baseline established in earlier cycles.                                           | All new code must be formatted (Prettier), lint-clean (ESLint), and type-correct (TypeScript strict) before PR submission.                    |
| OC-3 | This change ships as a single PR. WS-1 through WS-4 must all be in the same PR; partial shipment is not allowed.                                                                          | Single PR closure policy (design doc §0). Splitting the PR would leave the system in an intermediate partially-strict state. | All workstreams must be completed and reviewed together.                                                                                      |
