# 09_Constraints

## 制約事項

### 技術的制約

| ID     | 制約                                        | 影響                                                               | 緩和策                                                |
| ------ | ------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------- |
| CON-01 | サブエージェントはClaude Code Agent SDK依存 | エージェントの振る舞いはプロンプト指示のみで制御（コード実装なし） | SKILL.md内のプロンプト指示を精緻に定義する            |
| CON-02 | review-roster.yml のスキーマは固定          | 新レビュアーは既存スキーマに準拠する必要がある                     | 既存フィールド（id, name, scope, must_check等）を踏襲 |
| CON-03 | レビュー順序はロースター順で固定            | 全否定・パターン倍増の実行順序はロースター内の位置で決まる         | 適切な位置（既存10名の後）に配置する                  |
| CON-04 | FAIL→全ロースター再実行のコスト             | 12レビュアーの全再実行はコンテキストウィンドウを大量消費する       | NFR-0007の無限ループ防止策を併用する                  |

### 運用上の制約

| ID     | 制約                                      | 影響                                     | 緩和策                                           |
| ------ | ----------------------------------------- | ---------------------------------------- | ------------------------------------------------ |
| CON-05 | 全否定の「全て間違い」スタンスは修正困難  | 有意義な指摘と無意味な否定の区別が難しい | レビュー結果に「具体的代替案」の記載を必須とする |
| CON-06 | パターン倍増の「2倍」基準が曖昧になりうる | 何を「1パターン」と数えるかの定義が必要  | パターンカウントルールを明示的に定義する         |

- 該当なし（内部ツール開発のため）
