# 08_Glossary

## 用語集

| 用語                     | 定義                                                                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 全否定エージェント       | Devil's Advocate Agent。現状のすべてが間違っているという前提でレビューを実施し、自身が考えるあるべき姿を強制的に提案するサブエージェント |
| パターン倍増エージェント | Pattern Doubler Agent。成果物中のパターン数（US, AC, BR, EX, TC等）を現状の2倍に増やすことを目標にレビューするサブエージェント           |
| ブロッキング力           | レビュアーがFAILを出した場合に、即修正→ロースター先頭から全レビュアー再実行を強制する権限                                                |
| ロースター               | Review Roster。レビュアーの順序付きリスト。`review-roster.yml` で定義される                                                              |
| RCP (Review Cycle Pack)  | レビュー周回ごとに生成されるアーティファクト一式（review*request.md, R??*\*.md, summary.json）                                           |
| こじつけ                 | 全否定・パターン倍増エージェントの行動原則。論理的に完全でなくても、自分の意見を通すために強引な論理展開を行うこと                       |
| 屁理屈                   | 全否定・パターン倍増エージェントの行動原則。些末な点を誇張して問題提起し、改善提案の根拠とすること                                       |
| デリゲーションマップ     | `agent-selection.md` に定義される役割→タスクの委任対応表                                                                                 |
| Simulation mode          | サブエージェントが利用不可の場合にユーザー承認のもとで模擬実行するモード                                                                 |
| Capability Probe         | サブエージェントの利用可否を確認するための事前テスト                                                                                     |
| パターン                 | specs内の個別項目（User Story, Acceptance Criteria, Business Rule, Example, Test Case）の総称                                            |
| 無限ループ防止           | 全否定エージェントのFAIL→修正→再FAIL が際限なく繰り返されることを防ぐメカニズム                                                          |
