# 09 Constraints

## Technical Constraints

| ID   | Constraint                                                                                                                                                                                      | Rationale                                                                                            | Impact                                                                                                         |
|------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------|
| TC-1 | All artifact refs in output must use POSIX path separator `/`. Windows `\\` is forbidden in any value written to `declaredRef`, `evidenceRefs`, or any traceability ref field.                 | Cross-platform reproducibility. A ref containing `\\` would fail on Linux/macOS CI and produce non-deterministic audit artifacts. | `toRepoRelativeArtifactRef()` must normalize path separators to `/` regardless of host OS (`path.posix` or manual normalization). |
| TC-2 | `pathUtils.ts` must not import from `execution.ts` or from any module that transitively imports `execution.ts`. `pathUtils.ts` is a leaf module.                                                | Circular import prevention. If `pathUtils.ts` imports `execution.ts` and `execution.ts` imports `pathUtils.ts`, TypeScript compilation may silently produce `undefined` for circularly imported values. | Helper functions must be implemented without depending on execution-layer modules. Types shared between helpers and execution must be defined in a neutral location (e.g., a types file). |
| TC-3 | `runtimeGate.evidenceRefs` is a required field for full-harness UI-only output. Existing evidence bundles without this field will fail validation after rev8.                                   | Backward compatibility is explicitly abandoned (design doc §0 and §3-2). Rev8 is a breaking change.  | Any consumer of `validatePrototypingEvidence()` that previously passed evidence without `runtimeGate.evidenceRefs` must add the field. No migration shim is provided. |
| TC-4 | All new code in `packages/qfai` must satisfy TypeScript strict mode. No `@ts-ignore`, no `any` in new code, no `as unknown as T` without justification.                                        | Existing policy (CLAUDE.md, QFAI AGENTS.md). Type safety is a first-class constraint.               | Helper types must be explicit. `toRepoRelativeArtifactRef` parameter type must use a named interface (`ArtifactRefOptions`). Return types must be explicit.                              |

## Operational Constraints

| ID   | Constraint                                                                                                                                                                                      | Rationale                                                                                            | Impact                                                                                                         |
|------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------|
| OC-1 | Test suite must pass before PR merge. Commands: `pnpm vitest run --project validators` and `pnpm vitest run --project core`. Both must exit with 0.                                            | CI gate. PR merge is blocked until all tests pass.                                                    | New test files (`prototypingExecution.productionPath.test.ts`) must be authored and passing before merge. Extended test cases in existing files must not break existing passing tests. |
| OC-2 | Format, lint, and type checks must pass: `pnpm format:check && pnpm lint && pnpm check-types`. All three must exit with 0.                                                                     | CI gate. Code quality baseline established in earlier cycles.                                         | All new code must be formatted (Prettier), lint-clean (ESLint), and type-correct (TypeScript strict) before PR submission. |
