## Goal and Completion Criteria

- **Goal**: Close the final 2 blocking issues from the v1.7.15-08 audit within a single PR: (1) `specCoverage.evidenceRefs` generates absolute path refs that violate the `isConcreteArtifactRef` contract; (2) top-level `runtimeGate.evidenceRefs` is entirely unvalidated. Additionally, unify traceability ref grammar across all 3 layers, and add execution→validate closure regression tests.

- **Measurable completion criteria** (4 DoD conditions from design doc §5):
  1. `specCoverage.evidenceRefs` and `specs[].coverageRefs[].declaredRef` contain only repo-root relative concrete artifact refs; no absolute paths, directory paths, or synthetic tokens exist in the output.
  2. `runtimeGate.evidenceRefs` is parsed and validated by `prototypingEvidence.ts`; field absence, empty array, absolute path, self-ref, and synthetic token each produce validator errors.
  3. Top-level summary, iteration evidence, and per-spec `coverageRefs` all use the same ref grammar (generated by shared helpers, not parallel implementations).
  4. `prototypingExecution.productionPath.test.ts` contains at least one positive closure test (`runPrototypingExecution()` output passes `validatePrototypingEvidence()`) and at least one negative injection test (absolute path in specCoverage/runtimeGate causes validation failure).

## Key Issues

- **Issue 1 (WS-1)**: `specCoverage.ts` generates `declaredRef` and `evidenceRefs` values using absolute file paths (e.g., via `path.resolve()` → direct assignment). The validator's `isConcreteArtifactRef()` already forbids absolute paths, so the package's own builder output violates the package's own validator contract.
- **Issue 2 (WS-2)**: `runtimeGateBuilder.ts` / `execution.ts` write top-level `runtimeGate.evidenceRefs` to the output bundle, but `prototypingEvidence.ts` has no schema, parse, or validation for this field. Any malformed value passes undetected.
- **Issue 3 (WS-3)**: Three traceability layers — top-level summary, iteration evidence, per-spec `coverageRefs` — use divergent ref grammar implementations; a shared helper is needed to prevent future grammar drift.
- **Issue 4 (WS-4)**: The regression that allowed Issues 1 and 2 to survive was the absence of an end-to-end execution→validate closure test; unit tests alone do not catch builder/validator contract mismatches.
