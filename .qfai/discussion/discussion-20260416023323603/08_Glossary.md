# 08 Glossary

## Terms

| Term                      | Definition                                                                                                                                                                            | Context                                                                                | Source   |
|---------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------|----------|
| concrete artifact ref     | A repo-root relative path to a specific file (with optional line number or anchor fragment). Must have a recognized file extension (`.md`, `.json`, `.png`, `.html`, etc.). Absolute paths, directory paths, and synthetic tokens are not concrete artifact refs. | Used in `specCoverage.evidenceRefs`, `runtimeGate.evidenceRefs`, `iterations[].evidenceRefs.*`, `specs[].coverageRefs[].declaredRef` | SRC-0001 |
| repo-root relative ref    | A path starting from the repository root, using POSIX `/` separators, pointing to a real file. Does not start with `/` or a drive letter. Example: `.qfai/specs/spec-001/40_screen_contracts.md#L12` | All traceability ref sites after WS-1/WS-3                                             | SRC-0001 |
| synthetic token           | A string used as a placeholder or human-readable label that does not resolve to a real artifact. Examples: `"specs: all covered"`, `"routes: all observed"`. These are forbidden in all evidence ref fields. | Validator rejects these in all 5 traceability ref sites                                | SRC-0001 |
| self-ref                  | A ref that points to `prototyping.json` itself (e.g., `.qfai/evidence/prototyping.json#/specCoverage`). Self-refs are circular and forbidden in all evidence ref fields.              | Validator rejects in `runtimeGate.evidenceRefs` and all evidenceRefs fields            | SRC-0001 |
| traceability layer        | One of three levels where evidence refs appear in a prototyping evidence bundle: (1) top-level summary fields (`specCoverage.evidenceRefs`, `runtimeGate.evidenceRefs`); (2) iteration evidence (`iterations[].evidenceRefs.*`); (3) per-spec coverage (`specs[].coverageRefs[].declaredRef`). | All three layers must use the same ref grammar after WS-3                              | SRC-0001 |
| pathUtils.ts              | New helper module at `packages/qfai/src/core/prototyping/pathUtils.ts` that centralizes ref normalization and validation helpers. Acts as a leaf module (no imports from `execution.ts` or other prototyping modules that import `execution.ts`). | Created in WS-1; shared by builders (WS-1) and validators (WS-2/WS-3)                | SRC-0001 |
| specCoverage.evidenceRefs | The list of concrete artifact refs in the top-level `specCoverage` summary of a prototyping evidence bundle. Before WS-1, this could contain absolute paths; after WS-1, only repo-relative concrete artifact refs are allowed. | `buildSpecCoverageSummary()` output; validated by `prototypingEvidence.ts`             | SRC-0001 |
| runtimeGate.evidenceRefs  | The list of concrete artifact refs in the top-level `runtimeGate` summary of a prototyping evidence bundle. This is a new formal field in rev8; previously unvalidated. After WS-2, it is a required field and fully validated by `prototypingEvidence.ts`. | `runtimeGateBuilder.ts` output; validated by `prototypingEvidence.ts` after WS-2      | SRC-0001 |
| closure test              | An end-to-end test that runs `runPrototypingExecution()` and passes the resulting output to `validatePrototypingEvidence()`, verifying that the execution pipeline is self-consistent. The positive case confirms zero validation errors; the negative injection case confirms that malformed refs cause validation failure. | `prototypingExecution.productionPath.test.ts` (new file in WS-4)                      | SRC-0001 |
| toRepoRelativeArtifactRef | Helper function in `pathUtils.ts` that converts an absolute file path to a POSIX repo-root relative concrete artifact ref. Takes `{ repoRoot, absolutePath, line?, anchor? }` and returns a string. Throws on invalid input (outside repo, directory, mutually exclusive line+anchor). | Used by all ref-producing builders in WS-1/WS-3                                       | SRC-0001 |
| assertConcreteArtifactRef | Helper function in `pathUtils.ts` that throws if the given string is not a valid concrete artifact ref. Used in `execution.ts` as an early-detection gate before bundle write.        | Used by `execution.ts` in WS-2/WS-3                                                   | SRC-0001 |
| isConcreteArtifactRef     | Helper function in `pathUtils.ts` that returns `true` if the given string is a valid concrete artifact ref, `false` otherwise. Used by `prototypingEvidence.ts` for all evidence ref validation. | Used by validator in WS-2/WS-3                                                        | SRC-0001 |
