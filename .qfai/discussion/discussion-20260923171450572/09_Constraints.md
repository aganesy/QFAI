## Risks These Constraints Create

For the architecture review and for `/qfai-sdd`.

- **Default `active` meets add-only manifests.** Under D7 an upgraded adopter gets `active`, and DTC-10 means a phase the project already declares keeps its customized reviewer set. That is not drift by itself; the run fails closed only where a blocking reviewer the built-in plan requires is absent (DPOL-12 (c)). What the operator sees and can do then (OQ-0011) decides whether the default reads as broken.
- **D10 trusts `verify.json`.** The core writes nothing that proves tests ran; an agent with write access can produce the file. The independent qa-gatekeeper review is the check, as today. REQ-0063 at least binds the file to this run's verify stage instance.
- **Two trust levels have no proof behind them in 1.13.0.** Nothing produces a `host_observed` result: with host hooks rejected (D10), a submitted `host_observed` counts as agent-reported and nothing is gated on it. `decision` cannot prove an answer came from a human rather than from an agent relaying one; its refusals are structural (REQ-0018). A `human_decision` is bound to a question the core opened. The defence is the host's structured question tool plus independent review, the footing today's `Approved By` rule stands on. Both are accepted limits, as D10's departure from design 05 §10 is.
- **No schema validator is installed (DTC-2).** Hand-written parsers for six contracts can drift from the shipped schemas. Tests that validate every shipped example against both the parser and the schema close that gap only if a validator is available to the tests.
- **Windows is untested in CI (DTC-16).** Journal publish and lock are the parts most likely to differ, and they are the parts NFR-0010 depends on.
- **Hash chains detect accidents, not tampering.** A writer with the same file rights can rewrite the journal (design 05 §4). Stronger enforcement belongs to host permissions and CI, which the core does not claim.
