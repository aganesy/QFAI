# 10 Policy

The policies a run must hold whatever route it takes. The pack is cli-only, so there is no visual design direction to align with (`01_Context.md` `## Design Direction`).
"Design" is SRC-0001; `D1` to `D16` are the session's decisions in `99_delta.md`. Where a decision amends the design, the policy says so.

## Authority Policy

The operator is asked on exceptions, not on every stage.

| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| DPOL-01 | A run asks the operator only for a material decision or a fact only the operator holds. It always stops on data loss, a breaking change to a public contract, loosening an authorization boundary, sending a secret outside, an effect on production, dropping a requirement or adding work outside the scope, and an approval that has gone stale on resume.                                                                                                                                                                                                                  | Every other question is answered by the request or by the repository, and asking it spends the operator's attention for nothing. | REQ-0008, REQ-0009; design 03 §8                                                |
| DPOL-02 | Authority has three kinds: `request_scope`, `human_decision` and `project_policy`. Declining it ends the run with nothing written outside the run directory. ## Quality Policy

| ID      | Policy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                 | Source                                          |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| DPOL-08 | Review stays independent. Each work order carries the run's history of authors, recommenders and reviewers. An agent never reviews what it wrote or recommended, a renamed role is not a second reviewer, and no reviewer is dropped to save tokens. The existing ledger tiers and reviewer sets apply unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Independence is the check the whole chain rests on; a faster run that loses it is not an improvement.                                               | REQ-0040; design 02 AD-07                       |
| DPOL-09 | A stage that did not run is never a pass. It is recorded as `not_applicable` with a reason, or as `reused` with a valid receipt whose obligations, dependencies, policy, tool and environment still match. `unrun` never becomes `PASS`, an `unknown` receipt is never `valid`, and only a failure at the intended assertion is `expected_red`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | A skipped stage reported as passed hides exactly the obligation it was supposed to check.                                                           | REQ-0035, REQ-0036; design 02 AD-06             |
| DPOL-10 | A stage handed on with debt names, for every residual finding, its code and path, cause, owning spec, detecting command, resolving owner and blocking extent. Debt with no known owner is not handed on, and a run carrying unresolved debt cannot complete.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Debt nobody owns is a failure with a different label.                                                                                               | REQ-0037                                        |
| DPOL-11 | `finish` runs validation itself and records it as `cli_observed`. Tests and lint are accepted from the `verify.json` this run's verify stage wrote, plus an independent qa-gatekeeper review. A receipt from another run, another spec or a shared file is never this run's. Nothing in 1.13.0 produces a `host_observed` result, so a submitted one counts as agent-reported and gates nothing. A gate is not narrowed to the diff, lowered in severity or rewritten mid-run, and a failure is not waived because it was already there.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | **Amends design 05 §10 (D10).** Today's footing for repository gates was judged enough; what the core can observe, it observes.                     | D10; REQ-0060, REQ-0062, REQ-0063; design 04 §9 |
| DPOL-12 | `active` is the default on fresh install and on upgrade; `off` and `shadow` stay available in `qfai.config.yaml`. A runtime invariant violation, a missing host capability or policy drift takes the run out of automatic chaining. Policy drift is one of three things: (a) the policy, a manifest or the workflow-plan digest changes during a run; (b) an installed skill or plan does not declare the orchestrated contract the plan needs, such as a stage skill without its orchestrated-mode reference or a plan naming an unknown stage; (c) a role the built-in plan requires as a blocking reviewer is absent from the routing manifest. A run's own authorized edit to a policy or manifest file is an output of the run, which REQ-0029 keeps apart from its inputs, and does not fire (a). A customization, including one made through `qfai-configure`, that keeps the required roles is not drift, and the run stays `active`. The run never continues with less checking and never rewrites the project's configuration to recover; the stop clears when the named cause is removed or the operator sets `off`. The exact check list is settled at `/qfai-sdd` (OQ-0011). | **Amends design 02 AD-11 (D7).** The default is the user's choice; failing closed is what keeps it safe where the installed project does not match. | D7; REQ-0059, REQ-0065; OQ-0011                 |

## Security Policy

- Authentication: none is added. The CLI runs locally as the operator's user and does not authenticate agents. The journal's hash chain detects accidental corruption or a mixed-up file, not tampering by a writer with the same rights (design 05 §4); stronger enforcement is left to host permissions and CI.
- Authorization: `## Authority Policy` above.
- Data protection:
  - Text from a tool, a log, a file, a web page or a quotation is data, never authority. It cannot start a change, widen the scope or answer a question put to the operator (REQ-0003).
  - No untrusted string reaches a shell. The skill hands the CLI structured data, and every process the new code starts is spawned with an argument array and no shell (REQ-0023, NFR-0013; `09_Constraints.md` DTC-7).
  - Reading more never widens the scope envelope (REQ-0012).
- Secret management:
  - Tracked evidence in `.qfai/evidence/workflow/<runId>/` holds no conversation text, secret, token or absolute local path (NFR-0014).
  - Private input, where a run needs it at all, stays in the git-ignored `.qfai/runs/<runId>/` (REQ-0024).
  - Sending a secret outside always stops for the operator (DPOL-01).

## Compliance Policy

- Applicable standards: the repository rules that govern what ships — distributed surface, repository language, interface clarity and user questions (`.agents/rules/`). `09_Constraints.md` LC-1 to LC-3 hold the rest.
- Audit requirements:
  - every human answer is recorded with the question, the options offered, the answer and who gave it (REQ-0018);
  - the journal is the canonical record of a run, and the snapshot can be rebuilt from it (REQ-0026);
  - evidence a ledger or a triage row cites is tracked, so a fresh clone can check it (REQ-0024).
- Data retention:
  - `.qfai/runs/` is working state; the project decides when to delete it;
  - tracked evidence stays in git history;
  - a repair never deletes earlier evidence (`99_delta.md` `## Consequences for the Design Package`, AC-05).

## Development Policy

- Branching strategy: work pull requests come from feature branches. The release edits are made on `feature/v1.13.0` only (`09_Constraints.md` OC-6), and no agent merges, tags or publishes without an explicit instruction.
- Code review requirements:
  - `REVIEW.md` governs. Every finding, nit-level included, is posted inline.
  - The pack's reviewers include `architecture-reviewer` and `product-surface-reviewer` (`01_Context.md` `## Stakeholders`).
  - A change to a skill, the constitution or a manifest is made in `packages/qfai/assets/init/` and regenerated with `pnpm sync:ssot` (DTC-4).
- Testing requirements:
  - every source change has tests; fault seeds, schema, state-machine, ownership, migration and receipt tests run on every pull request with no network and no paid model (NFR-0009);
  - the routing eval runs on a real model as a manual release gate (D8);
  - Windows results exist before release (NFR-0011, OQ-0012);
  - existing tests for manual invocation, `--auto` and `verify.json` keep their meaning (DSC-006).
- Sourcing: a decision about where a capability comes from — a schema validator, a lock, a hash — runs rungs 2 to 5 of `.agents/rules/minimal-implementation.md` at `/qfai-sdd` and records what each returned.

## Operational Policy

- Deployment strategy: the change ships in qfai 1.13.0 through `qfai init` and its upgrade. A fresh install gets the latest templates, an unmodified shipped asset is updated once its provenance matches, and a user-modified asset or manifest is never overwritten. A modified manifest stays `active` unless it meets a drift trigger of DPOL-12, which fails the run closed (REQ-0064, REQ-0065).
- Monitoring requirements:
  - `status` reports a run read-only and writes nothing (REQ-0019);
  - measured runs record the NFR-0004 fields, with `null` where a host exposes nothing;
  - activation and execution quality are re-verified when a model, a skill description or a host's invocation behaviour changes (NFR-0018).
- Incident response:
  - a run that cannot continue safely fails closed (DPOL-12) or stops with a named integrity error, never reports success (NFR-0010);
  - the operator's way back to manual operation is `off` in `qfai.config.yaml`, set by the operator;
  - a support claim for a host is withdrawn when its adapter test fails (REQ-0058).
