# Evidence Requirements

## Mandatory evidence (per cycle, per screen)

For every declared screen in `.qfai/contracts/ui/*.yaml`, collect all 4 artifacts for every cycle `<n>`:

- screenshot: `.qfai/evidence/prototyping/iterations/<n>/<screen-id>.png`
- HTML snapshot: `.qfai/evidence/prototyping/iterations/<n>/<screen-id>.html`
- accessibility snapshot: `.qfai/evidence/prototyping/iterations/<n>/<screen-id>.snapshot.txt`
- Playwright CLI command log: `.qfai/evidence/prototyping/iterations/<n>/<screen-id>.commands.json`

## Per-cycle artifacts

Every cycle MUST also produce these cycle-scoped artifacts:

- Playwright CLI command plan: `.qfai/evidence/prototyping/iterations/<n>/playwright-commands.json`
- Review input bundle: `.qfai/evidence/prototyping/iterations/<n>/review-bundle.json`
- Evaluator output: `.qfai/evidence/prototyping/iterations/<n>/evaluator-review.json`

## Canonical latest paths

The canonical latest screenshot and HTML MUST mirror the newest cycle's artifacts for the same `<screen-id>`:

- `.qfai/evidence/prototyping/screenshots/<screen-id>.png`
- `.qfai/evidence/prototyping/html/<screen-id>.html`

If either artifact is missing:

- the screen is scored `0` for the cycle
- the cycle is incomplete
- rerun is mandatory

Optional evidence is not allowed.

## Capture rules

- AI evaluator sub-agent executes the Playwright CLI command plan generated by QFAI.
- Paths are assigned by QFAI via `playwright-commands.json`. Do not invent paths.
- Use stable `screen-id` names from the canonical UI contracts.
- Overwrite stale evidence with fresh evidence from the current cycle (canonical latest) while preserving iteration history under `iterations/<n>/`.
- Do not reuse an older screenshot, HTML snapshot, accessibility snapshot, or command log after a fix.
- If capture fails, record the failure in work evidence and stop pretending the screen was evaluated.

## Mode invariant

Evidence requirements are identical for all modes (low-cost / standard / full-harness) per spec-0017 REQ-0001. Modes differ only by `maxCycles` (1 / 3 / 20). Choosing a lower mode does NOT reduce evidence obligations.

## Validate gate expectations

`qfai validate --profile prototyping --fail-on error` must be able to confirm, for every cycle:

- every declared screen has all 4 per-screen artifacts
- the cycle has `playwright-commands.json`, `review-bundle.json`, `evaluator-review.json`
- canonical latest paths mirror the newest cycle
- `review-bundle.json` has all 5 required fields (screens, axisDefs, designSystemChecklist, previousScore, commandPlanRef)
- `evaluator-review.json` `scores[].evidenceRefs[]` entries are concrete paths to existing files (no placeholders)
- `prototyping.json` `maxCycles` matches the mode (QFAI-PROT-MODE-001)
- `bestOfHistory`, `breakthrough`, and `reviewerGate` sections are present and populated
