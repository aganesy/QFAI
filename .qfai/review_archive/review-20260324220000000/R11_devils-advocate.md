# R11 Devil's Advocate（devils-advocate）

## 結果: PASS

## 前提: 「現状すべてが間違っている」

以下の観点から各スペックの前提・結論・設計判断に対して全否定的挑戦を行った。

### 挑戦 1: 「DDP 必須化はオーバーエンジニアリングではないか」

- **反論試行**: QFAI は CLI ツールである。CLI ツールに UI 方向性パック（ビジュアルテーゼ、インタラクションテーゼ等）を必須化するのは過剰な形式主義ではないか。
- **検証結果**: spec-0019 の In Scope に「SKILL.md 更新（DDP 読み取り順序の下流 skill への反映）」とあり、DDP は QFAI が生成する成果物（discussion-pack, spec-pack）に対する品質基準である。QFAI 自体の UI ではなく、QFAI が処理する対象プロジェクトの UI 品質を担保する仕組みである。BR-0019-0006 で「UI 非関連の artifact には適用しない」と明記されており、CLI コマンド仕様のみの discussion-pack には DDP チェックがスキップされる（EX-0019-0012）。適用範囲が適切に制限されている。
- **判定**: 反論棄却。適用範囲の制限により過剰な負荷は発生しない。

### 挑戦 2: 「スコアカード閾値 70 の根拠が薄い」

- **反論試行**: spec-0022 BR-0022-0005 で各次元の閾値を 70 としているが、この数値の根拠が spec 内に記載されていない。恣意的な数値ではないか。
- **検証結果**: 確かに閾値 70 の数値的根拠は spec-0022 内に明示されていない。しかし、これは v1.6.5 の初回導入時の保守的な閾値であり、spec-0022 の Escalation Hook に「スコアカード閾値の厳格さと開発速度のバランス判断」が Trade-off として記載されている。また、AC-0022-0003 で「閾値（70）」がハードコードされているが、BR-0022-0005 のルール自体は閾値の調整を阻害しない構造になっている。
- **判定**: 指摘は有効だが FAIL には至らない。閾値の根拠補足を推奨するが、初回導入の保守的設定として許容。

### 挑戦 3: 「Mermaid SSOT はスケーラビリティに問題がある」

- **反論試行**: spec-0020 で Mermaid をフロー定義の SSOT としているが、大規模アプリケーション（100 画面以上）では Mermaid の可読性が著しく低下する。フリーテキストや外部ツールを全面禁止するのは視野が狭い。
- **検証結果**: spec-0020 delta の Rejected で「フリーテキストによるフロー記述」を「機械パース不可能」として却下し、「Figma/draw.io 等の外部ツール」を「CLI 完結性に反する」として却下している。Mermaid のサブグラフ機能により画面群をモジュール分割可能であり、spec-0020 EX-0020-0005 でサブグラフの使用例が示されている。大規模化は現時点の QFAI のスコープ外であり、必要に応じて将来のバージョンで対応可能。
- **判定**: 反論棄却。現時点のスコープでは Mermaid SSOT が適切。

### 挑戦 4: 「コードオンリーレビュー禁止は開発速度を殺す」

- **反論試行**: spec-0021 BR-0021-0004 でコードオンリーレビューを全面禁止しているが、小さな CSS 修正やタイポ修正にまでレンダリング結果の添付を要求するのは非効率ではないか。
- **検証結果**: spec-0021 の Out of Scope に「自動 VRT ハードゲート — v1.6.6 に延期」とあり、現時点では手動レンダリング確認が必要。しかし、DR-0033 で「コードレビューだけでは UI の美的品質を評価できない」として明確に却下されている。小修正の閾値定義は確かに不足しているが、v1.6.5 のスコープでは「レンダリング結果の添付」を最低限の品質担保として位置付けるのは合理的。
- **判定**: 指摘は部分的に有効だが FAIL には至らない。小修正に対する閾値の明確化を将来の改善として推奨。

### 挑戦 5: 「spec-0019 の EX-ID 不正は品質への疑念を呼ぶ」

- **反論試行**: spec-0019 の EX-0019-0019-0020 〜 EX-0019-0019-0024 の ID 不正は、仕様作成プロセス自体の品質に疑念を投じる。ID フォーマットすら守れないのであれば、内容の正確性も疑わしい。
- **検証結果**: ID 不正は 5 件のみであり、トレーサビリティ連鎖（US→AC→BR→EX→TC）自体は破綻していない。TC-0019-0006 等で EX-Ref として参照されており、内容の紐付けは維持されている。形式的な ID 修正は容易であり、内容の正確性とは独立した問題。
- **判定**: 反論棄却。形式的な修正で解消可能な軽微な問題。

## 総合判定

5 つの挑戦のいずれも FAIL に至る根拠を見出せなかった。挑戦 2（閾値根拠）と挑戦 4（コードオンリーレビュー禁止の閾値）は有効な指摘だが、v1.6.5 初回導入の文脈では許容範囲内。**PASS** とする。
