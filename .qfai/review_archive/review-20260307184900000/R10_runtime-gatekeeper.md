# R10: Runtime Gatekeeper レビュー

## レビュアー情報

- ID: runtime-gatekeeper
- 名前: Runtime Gatekeeper
- スコープ: sdd

## チェック項目

### 1. 運用準備とランタイムリスク制御の検証

- **終了コード規約**: NFR-0061 で終了コード規約（0=成功, 1=失敗）が定義されている。spec-0002 の AC-0002-0002/0005/0006/0007 で --fail-on オプションとの組み合わせが検証される設計。
- **CI/CD 環境制約**: OC-01「CI/CD 環境で 2分以内に完了」が明示されており、パフォーマンス NFR（NFR-0001: 10秒、NFR-0002: 60秒）と整合性がある。
- **エラーメッセージの運用品質**: NFR-0040 で全 Issue に code, message, suggested_action の 3要素が要求されており、運用時のトラブルシュートに必要な情報が提供される設計。
- **GitHub Actions 統合**: spec-0002 の AC-0002-0008/0009 で `--format github` オプションによる ::error/::warning 形式出力が定義されており、CI パイプラインとの統合が設計されている。

### 2. 緩和策とロールバック前提の検証

- **ウェイバーシステム**: spec-0002 で suppress / downgrade の 2種類のウェイバーが定義されており、バリデーションルールの柔軟な緩和が可能。NFR-0011「ウェイバー適用による意図しない Issue 消失なし」で安全性が保証される設計。
- **--dry-run によるロールバック回避**: spec-0001 の AC-0001-0008/0009 で --dry-run オプションにより変更前のプレビューが可能。
- **--force の保護対象**: spec-0001 の AC-0001-0006/0007 で --force 実行時も skills.local/ が保護される設計。ユーザーカスタマイズの喪失リスクを軽減。
- **レガシー退避**: spec-0001 の AC-0001-0012/0013 で非推奨ファイルの退避（削除ではない）が設計されており、データ喪失リスクを最小化。
- **破壊的変更の管理**: DL-02「破壊的変更は v2.0 まで保留」の制約により、後方互換性が維持される設計。

## 所見

- CLI ツールとしてのランタイムリスクは限定的であり、適切に管理されている。
- ウェイバーシステムと --dry-run / --force の保護設計により、運用時の安全性が確保されている。
