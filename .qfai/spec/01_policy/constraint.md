# Constraints

## Technical Constraints

| ID    | Constraint                                                                                                                                                                       | Rationale                                                                 | Impact                                                                                                                               |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| TC-01 | Node.js 20.19.0 or later.                                                                                                                                                        | The floor `engines.node` declares in both `package.json` files.           | Code and shipped workflows use nothing the floor lacks; the `node-floor` CI job runs the suite on exactly that version.              |
| TC-02 | A validator is a deterministic async function that returns its findings; the same inputs give the same findings.                                                                 | `qfai validate` results must be reproducible and comparable between runs. | Constrains every validator. Inputs beyond the project root and the configuration, such as the platform, are passed in by the caller. |
| TC-03 | Downstream execution skills read the current story tree and its contracts rather than a discussion pack as their normative input.                                                | The discussion pack is upstream discovery evidence.                       | `/qfai-sdd` translates the accepted requirements into `.qfai/spec/`; later skills consume those artifacts.                           |
| TC-09 | UI contracts use `.qfai/spec/03_contract/ui/*.yaml` when a project has a UI surface.                                                                                             | The story tree contains the current contract home.                        | Downstream evaluator and validator inputs resolve the new contract path.                                                             |
| TC-10 | The `qfai prototyping` command and the removed runtime or full-harness engine are not reintroduced as a public contract.                                                         | Prototyping stays skill-first.                                            | Limits the public CLI surface.                                                                                                       |
| TC-12 | `/qfai-sdd` authors root `DESIGN.md` from the brand direction the discussion pack records; its tokens are read from that file, never copied, and it is never a discussion input. | Prevents early convergence.                                               | Separates the discussion, SDD and prototyping responsibilities.                                                                      |
| TC-67 | `packages/qfai/src/core/paths/assistantPaths.ts` is the single source for the assistant tree's directory names and paths.                                                        | `qfai init`, validation and the asset readers must agree on one layout.   | Callers use its helpers instead of spelling `.qfai/assistant/<layer>/` themselves.                                                   |

## Operational Constraints

| ID    | Constraint                                                                                                                                                                                                                   | Rationale                                                                                                                                                                                                                               | Impact                                                                                                                                                                                                                                                                                      |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OC-01 | `/qfai-prototyping` is the only public prototyping path.                                                                                                                                                                     | Prevents misuse.                                                                                                                                                                                                                        | Keeps the CLI surface simple.                                                                                                                                                                                                                                                               |
| OC-02 | `/qfai-verify` includes `qfai validate --fail-on error` and the review artifact in its completion gate.                                                                                                                      | The reviewer gate is mandatory.                                                                                                                                                                                                         | Constrains verification.                                                                                                                                                                                                                                                                    |
| OC-03 | A downstream validation never treats a discussion artifact as a substitute for a missing contract.                                                                                                                           | Prevents fail-open validation.                                                                                                                                                                                                          | A missing contract is an error.                                                                                                                                                                                                                                                             |
| OC-62 | `qfai validate` reports `W-SKILL-DOC-BROKEN-REF` when a shipped skill document references a path, finding code, exit code, schema field or CLI flag that no longer exists.                                                   | Documentation that names removed paths and skills costs adopters time, and the defect returns with every rename.                                                                                                                        | The validate lane checks skill Markdown against the live validator and CLI surface.                                                                                                                                                                                                         |
| OC-65 | `packages/qfai/scripts/check-pack-locations.mjs` rejects a `review-*/` or `discussion-*/` directory outside the allowed roots (`tmp/`, `.qfai/review/<ts>/`, `.qfai/discussion/<ts>/`) and runs in `pnpm ci:lint`.           | Enforces rule 6 of `.agents/rules/root-additions-policy.md` when a pull request is opened.                                                                                                                                              | The lane checks staged and changed directories only, so older packs are not reported again.                                                                                                                                                                                                 |
| OC-70 | In this repository `.qfai/assistant/` links into `packages/qfai/assets/init/.qfai/assistant/`. Shipped `rule/`, `skill/`, `agent/` and `prompt/` files are edited in the asset tree; project context lives in `.qfai/spec/`. | A shipped file has one authored source.                                                                                                                                                                                                 | `pnpm sync:ssot` recreates the links, and `scripts/link-assistant-tree.mjs --check` in `pnpm ci:lint` fails where a regular file stands in for a link.                                                                                                                                      |
| OC-72 | Every gate runs on a pull request, from the lint aggregate or the test matrix. A gate placed only in `pnpm ci:gate`, which only the release workflow runs, blocks no pull request.                                           | A check no pull request runs is documentation, not a gate.                                                                                                                                                                              | A new gate is verified by its invocation path and by a planted violation that turns a pull request red.                                                                                                                                                                                     |
| OC-73 | Which status check a merge requires is a repository setting. No pull request can read or change it, and no agent changes it.                                                                                                 | Branch protection lives outside the tree, and a skipped job reports success to it.                                                                                                                                                      | `.github/required-status-contexts.json` declares the job expected to carry the requirement (`ci-pass`), and the workflow hygiene lane holds the workflows to that declaration. Whether the live setting matches is open (OQ-0022); changing it is a hand-off to a repository administrator. |
| OC-74 | The release workflow's file name, `.github/workflows/release.yml`, is registered with npm trusted publishing. It is never renamed, moved or deleted; its contents may change.                                                | npm binds trusted publishing to the repository and the workflow file name, outside this repository.                                                                                                                                     | No test or guard catches a rename; the next publish fails. A change to release automation keeps the file name.                                                                                                                                                                              |
| OC-75 | A GitHub Actions job can depend only on jobs in its own workflow file. No shipped workflow file references another shipped file, and a job that aggregates other jobs sits in the same file as them.                         | An adopter may lack any one shipped file — never installed, or removed on purpose — and a reference to a missing file makes the referencing workflow fail to parse. Without cross-file references a partial install is only incomplete. | The shipped set spans several independent files, and test layers are separate jobs inside one file.                                                                                                                                                                                         |
| OC-79 | No guard is weakened to land a change. A change to the distributed-surface forbidden-pattern set updates all three guards and `.agents/rules/distributed-surface.local.md` in one pull request with no template edits.       | A partial update leaves the three guards disagreeing, and whichever runs first decides.                                                                                                                                                 | A new finding code uses a letters-only prefix and three digits, and is registered in the validate command's expectation table.                                                                                                                                                              |
| OC-80 | A cost or parallelism claim ships only on captured before-and-after numbers, quoted in the pull request description. A measured negative result is recorded, not retried until it agrees.                                    | The evidence tree is not tracked, so numbers kept only there cannot be reviewed. Retries would hide the races that parallelism changes risk.                                                                                            | Parallelism changes land one runner project per pull request, each with three consecutive green aggregate results before merge and no retry setting.                                                                                                                                        |

## Business Constraints

| ID    | Constraint                                                                                             | Rationale                                                                                     | Impact                                                                         |
| ----- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| BC-02 | A breaking change ships with a `CHANGELOG.md` entry that says what breaks and how an adopter migrates. | Adopters upgrade from the published package and learn of a break only from its release notes. | A release that carries a breaking change is not ready until that entry exists. |
