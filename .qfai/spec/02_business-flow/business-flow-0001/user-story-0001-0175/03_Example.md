# Examples

## Examples

| EX-ID           | AC-Ref          | Input                                                                                                                                                                                                                                             | Expected                                                                                                                                                                                                                                                                               |
| --------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EX-0001-0175-01 | AC-0001-0175-01 | Given a SKILL.md with no `## Default Autopilot Policy` section OR a SKILL.md whose section is present but missing one or more required buckets (heading-only / partial population) When the Reviewer Gate checks it                               | Then it emits `R-AUTOPILOT-POLICY-MISSING` (severity error) with `justification:` naming the SKILL.md path and either the absent section or the missing bucket(s) by name; a SKILL.md that lists all three buckets (auto-decide / ask-user / hard-required) passes without the finding |
| EX-0001-0175-02 | AC-0001-0175-02 | Given a run started with `--auto`, in which a skill meets an `ask-user` item (a destructive operation), a `hard-required` input (the business flow it works on) and an `auto-decide` item (ID numbering) When each item comes up                  | Then the destructive operation waits for a `human_decision` that answers it, the business flow is satisfied by `request_scope` or the run's binding, the ID numbering needs no authorization, and `--auto` satisfies none of the three                                                 |
| EX-0001-0175-03 | AC-0001-0175-03 | Given a `/qfai-implement` work order whose `target` is `{kind: "flow", flowId: "BF-0001"}`, and a direct `/qfai-implement` invocation that names no flow in a tree where none can be resolved When each reaches its `hard-required` business flow | Then the work order's binding counts as the supplied flow and nothing is asked, while the direct invocation stops at preflight and reports the missing flow                                                                                                                            |
