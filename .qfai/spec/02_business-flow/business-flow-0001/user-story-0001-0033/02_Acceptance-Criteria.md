# Acceptance Criteria

## Criteria

```gherkin
Feature: Managed `.gitignore` block
  # AC-0001-0033-01
  Scenario: `qfai init` appends the QFAI managed block to the root `.gitignore`
    Given an empty project directory
    When `qfai init` runs
    Then the root `.gitignore` carries one marker line (`# ── QFAI managed (generated by qfai init) ──`)
    And it contains `.qfai/report/*`, `.qfai/evidence/*` and `.qfai/review/*`
    And no line ignores `.qfai/deliberation/` or a path under it, so a deliberation record is tracked
    And the lines a user wrote outside the block are preserved
    And it contains no line that negates `.qfai/evidence/` or a path under it

  # AC-0001-0033-02
  Scenario: A rerun rebuilds a managed block that lacks a governance negation
    Given a managed block in `.gitignore` that lacks one governance negation and is followed directly by a project line
    When `qfai init` runs, and then runs again
    Then exactly one marker line remains
    And the missing negation is back, after every ignore line of the block
    And the ignore lines the block held are kept, and one the project removed from it is not added again
    And the project line stays below the negations
    And the second run leaves `.gitignore` byte-identical

  # AC-0001-0033-04
  Scenario: The managed block does not repeat an ignore the project already has
    Given a `.gitignore` with no managed block whose own lines already ignore the repository-root `tmp/` staging directory, as `/tmp/` or as `tmp/`
    When `qfai init` runs, and then runs again
    Then the managed block holds no `/tmp/` line and the file ignores `tmp/scratch.txt` through the project's line alone
    And one output line names the lines left out of the block
    And the second run leaves `.gitignore` byte-identical
    And when the project's own lines do not ignore that directory, for instance because a later `!/tmp/` cancels them, the block carries `/tmp/`

  # AC-0001-0033-05
  Scenario: A `.gitignore` that init creates also ignores the installed dependencies
    Given a project directory with no `.gitignore`
    When `qfai init` runs, and then runs again
    Then the created `.gitignore` starts with `node_modules/` and a blank line, outside the managed block and above it
    And one output line says the file was created with `node_modules/` and the QFAI entries
    And the second run leaves `.gitignore` byte-identical
    And a `.gitignore` that already existed does not gain `node_modules/`
```
