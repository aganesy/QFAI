# Examples

## Examples

| EX-ID           | AC-Ref          | Input                                                                                                                                                                                                                                                                                                          | Expected                                                                                                                                                                                                                                                                                                                                          |
| --------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EX-0001-0215-01 | AC-0001-0215-01 | Given an orchestrated verify work order for stage instance `verify-1`, and a verify run whose gates pass When the stage writes `.qfai/report/verify.json` with `status: "PASS"` and `scope: "full"` and returns                                                                                                | Then its `artifactRefs` name that `.qfai/report/verify.json` with the digest of the file this stage wrote. Its `reviewResults` hold the qa-gatekeeper verdict, from a reviewer instance that authored nothing in the run. Its `gateResults` are reported as information only, since `finish` decides the gates                                    |
| EX-0001-0215-02 | AC-0001-0215-02 | Given two reports already on disk when the verify stage starts: a `.qfai/report/verify.json` with `status: "PASS"` whose `flowId` names `BF-0002`, and a `verify.json` in another run's per-stage report copy When the verify stage returns                                                                    | Then neither file is named in `artifactRefs`. The stage runs its own gates, writes its own `.qfai/report/verify.json` and names that file                                                                                                                                                                                                         |
| EX-0001-0215-03 | AC-0001-0215-03 | Given a verify stage whose required `validate` gate ran and passed, and whose required E2E gate could not start because the browser the harness needs is not installed When the stage returns                                                                                                                  | Then its `outcome` and its `testObservation` are reported as two separate fields. The E2E gate is reported `unrun`, never as a pass, and `verify.json` does not record `status: "PASS"`                                                                                                                                                           |
| EX-0001-0215-04 | AC-0001-0215-04 | Given the verify stage of a run that returns `accepted_with_debt` When it writes `verify.json`                                                                                                                                                                                                                 | Then the file carries only fields from `status`, `scope`, `flowId`, `recordedAt`, `summary` and `gates`. `status` is `PASS` or `FAIL`, and `scope` is `prototyping`, `atdd` or `full`. No field named `outcome` or `testObservation` is written, and neither `accepted_with_debt` nor any other stage-result value appears as a value in the file |
| EX-0001-0215-05 | AC-0001-0215-05 | Given the final gates report three findings verify did not cause: a business rule that cites no example (a story or contract gap), an E2E test that asserts on the wrong page (an acceptance-test defect), and a unit test failing on production code (an implementation defect) When the verify stage returns | Then the outcome is `needs_repair`, and `debts` lists the three findings with the resolving owners `qfai-sdd`, `qfai-atdd` and `qfai-implement`. Verify changes no story, contract, test or production file to clear any of them                                                                                                                  |
| EX-0001-0215-06 | AC-0001-0215-05 | Given a verify stage whose required E2E gate cannot start because its database container is absent When the verify stage returns                                                                                                                                                                               | Then the outcome is `blocked`, with the blocker `stage-blocked` and `operator` as the one who clears it. `debts` holds no entry for the missing environment, and no repair is routed for it                                                                                                                                                       |
| EX-0001-0215-07 | AC-0001-0215-06 | Given workflow mode `active` and a work order for stage instance `verify-1` and operation `verify-full` When `/qfai-verify` receives it and the run, stage instance and work-order IDs all match the issued order                                                                                              | Then it runs the final gates for that work order only, and says nothing to the operator. When it is selected in the same mode with no work order and not by name, it edits nothing and passes the request to `qfai-run`. `qfai-verify/SKILL.md` holds exactly one line citing `references/orchestrated-mode.md`                                   |
| EX-0001-0215-08 | AC-0001-0215-07 | Given `qfai-verify/references/orchestrated-mode.md` When the first table under its `## Operations` heading is read                                                                                                                                                                                             | Then the `Operation` column holds exactly `verify-full`, in one backticked cell, and no other operation                                                                                                                                                                                                                                           |
