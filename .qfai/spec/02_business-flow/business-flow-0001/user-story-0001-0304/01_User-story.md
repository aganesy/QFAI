# US-0001-0304: Review an implemented screen for missing states and a weak structure

## User Story

As a project lead whose agents build business screens, I want the product-surface review to check every screen for the structure and state patterns QFAI already names, so that a screen with no empty, error or success state, or a data-heavy screen with no table, does not pass review only because no acceptance criterion names the part.

## Non-goals

- A change to which findings may block a review.
- A new anti-pattern entry.
