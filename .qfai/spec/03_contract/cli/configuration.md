# Configuration Contract

- Contract scope: project overrides written by `/qfai-configure` and consumed by QFAI commands
- Migration origin: `spec-0009`
- Used-by: `/qfai-configure`, `qfai init`, `qfai validate`, and skill routing

## Ownership boundary

`qfai.config.yaml` contains only values a project changes from package
defaults. `/qfai-configure` observes existing source and test paths before it
proposes glob changes. It does not edit application source or tests as part of
configuration. A glob with no matching test is not accepted as evidence of
coverage. The configured `paths.specsDir` and `paths.contractsDir` select the
story and contract roots; the migration contract governs moving an existing
spec pack to them.

The package holds default skill routing and review profiles. An override in
`routing:` or `reviewProfiles:` replaces the matching default entry whole;
individual fields are not merged. The agent card frontmatter is the only
definition of an agent. The init contract owns the shipped default values
and the initial file, and `assistant-routing.md` owns runtime resolution.

## Workflow mode

`workflow.mode` in `qfai.config.yaml` selects how `npx qfai workflow`
treats a free-text change request. It takes `active`, `shadow` or `off`,
and an absent key means `active`. `qfai init` writes no such key, so a
project that never sets it runs `active`.

- Any other value is a configuration issue, which `qfai validate` reports
  (`.qfai/spec/03_contract/cli/qfai-validate.md#workflow-mode-setting`).
- What each mode does is stated in
  `.qfai/spec/03_contract/cli/qfai-workflow.md`.
