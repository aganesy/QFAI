# CLI-0004: Delivery Workflow

## Ownership boundary

This contract decides the handoff along the delivery chain of
`/qfai-implement` and `/qfai-verify`: the acceptance tests each business flow
and criterion needs, the one-example-at-a-time TDD cycle, the gates each skill
runs for the flow it completes, what implementation reads from the prototype
handoff, and what each skill does as a stage of a route.

`cli-0014-qfai-validate.md` decides the findings, the flow scope and what
counts as a test. The package's test-layer rule decides which layer a test
belongs to. `cli-0011-qfai-prototyping.md` decides the prototype handoff
fields, and `cli-0015-qfai-workflow.md` decides the routes and the reviews
around these stages.

## Business rules

| BR-ID | Statement | Examples |
| --- | --- | --- |
| BR-0004-0001 | The traceability chain has five stages: discussion, specs, tests, code and verification. | EX-0001-0001-01 |
| BR-0004-0002 | configure -.-> discussion(optional) → sdd → prototyping(optional) → implement → verify, with no cycle. | EX-0001-0003-01 |
| BR-0004-0003 | Six stages, Stage 1 (discussion) to Stage 6 (verify), and a policy check. The policy check is not a stage: it runs once per run, at its start, before the first stage, as `common-policy-check`, and no stage runs it again; Stage 1 (discussion) and Stage 4 (prototyping) are optional, and Stage 5 (implementation) writes the acceptance tests with empty bodies and runs TDD one EX at a time. | EX-0001-0004-01 |
| BR-0004-0004 | Test volume counts and ratios guide planning only. Implementation writes, with `qfai atdd scaffold`, an E2E test for each in-scope BF and an integration or API test for each in-scope AC, whatever the volume signal. | EX-0001-0067-01 |
| BR-0004-0007 | Normal-Path-Only Test Cases Are Incomplete - A BF or AC that has only normal-path (happy-path) test cases is incomplete where its active obligations (AC, EX, BR or contract) make an error, boundary or edge case meaningful. - `test-design-analyst` and `qa-gatekeeper` read the annotated tests for those cases and return `REVISE` naming the missing case and its owner. - A failure case is not invented for an obligation that declares none. | EX-0001-0072-01 |
| BR-0004-0008 | Worker-Scoped Session-Reuse Rule Set - The guidance MUST state all seven rules as distinct statements: (1) never sign in per test; (2) never share one account across parallel workers; (3) key the cached session by the pair of worker index and actor; (4) tear the cache down at worker exit; (5) re-authenticate and rewrite the cache when a restored session is rejected; (6) a test that mutates its own account creates a dedicated one; (7) test-level parallelism costs more workers, not more sign-ins. - The guidance MUST state the companion rule in the same artifact: when an environment identifier is injected by the caller, the harness MUST NOT provision or tear down that environment. - The transferable asset is the rule set, not a fixture. The guidance is authored as a `/qfai-implement` reference artifact under the skill's `references/` directory and MUST be cross-linked from the `implement-credentials` step, so the rules are reachable without reading the whole skill. | EX-0001-0074-01 |
| BR-0004-0009 | Backend-Agnostic, Vocabulary-Frozen Prose - The guidance MUST NOT name a browser backend, MUST NOT contain an install command, and MUST NOT pin a version. A worked example is permitted only when presented as one illustration among possible backends, with nothing named, installed or pinned. - The guidance is prose only: it MUST NOT introduce a validator, a finding code, a test layer or an annotation token. The layer token set, the allowed annotation forms and the ATDD finding-code set stay unchanged from baseline — the layer vocabulary does not grow. - The guidance artifact ships under the distributed asset tree, so it MUST carry no internal spec / capability / decision / open-question identifier and no version marker beyond the canonical package version. | EX-0001-0074-02 |
| BR-0004-0010 | Script-Naming Rule Is Adopter-Only and Layer-Scoped - A credential-free lane and a credentialed lane MUST be reachable by different script names, so a lane that structurally cannot touch the network stays distinguishable from one that must. This is recorded as adopter guidance; QFAI keeps its own script names and adopts no renaming. - The guidance MUST state that QFAI's own suite has zero credentials and that none of this is dogfooded here, rather than implying the rules were verified by execution in this repository. - The guidance obliges the E2E / API / Integration layers only. It MUST NOT introduce a unit or component obligation — unit and component tests belong to `/qfai-implement` (RJ-0008-0001). | EX-0001-0074-03 |
| BR-0004-0012 | Serial-by-Default Processing - Items are processed one test at a time by default. - Parallel processing requires explicit user approval and delivery-planner authorization. - delivery-planner denies parallel dispatch when two items write the same fixture or mock file or mutate the same fixture instance; a shared read-only fixture that neither item writes is not a deny on its own. - On the story tree, the items are the EXs in scope that no test annotates, taken one at a time in ascending EX ID order. No ledger file records them or their order. | EX-0001-0093-01, EX-0001-0091-05 |
| BR-0004-0013 | Test-First Enforcement - A failing test MUST be written before any production code. - Production code written before a failing test exists is rejected. | EX-0001-0091-01 |
| BR-0004-0015 | Minimal Code Principle - Write the minimum production code to make the failing test pass. - Speculative generalization is prohibited. | EX-0001-0091-02 |
| BR-0004-0018 | Design System Input Determinism - `/qfai-implement` reads the token tables (color / typography / radius / shadow) from root `DESIGN.md` itself. - It MUST treat them as input only — it does not regenerate token tables from per-iter HTML, and no copy of them is written for it to read. | EX-0001-0096-01 |
| BR-0004-0019 | Contracts and Gate Commands Come From the Contract Directory - `/qfai-implement` reads contracts from `<paths.contractsDir>`, the key every reader of the contract directory goes through (`cli-0009-qfai-init.md`). - On the story tree, the Test, Lint, Typecheck and Build commands MUST come from the Standard commands section of `<paths.contractsDir>/tech.md`, which is their only home. A command found in no such section is not invented. | EX-0001-0091-03 |
| BR-0004-0020 | A Test Exception in Force Skips an Example - On the story tree, an EX named by a `decisions.md` row whose Content opens `Test exception:` is exempt from next-test selection only while that row's Status is DONE, as `cli-0014-qfai-validate.md` reads such rows. - The exception reaches only the EX IDs the row names. An ID the tree does not define exempts nothing. | EX-0001-0094-02, EX-0001-0091-04, EX-0001-0056-07 |
| BR-0004-0021 | Shipped Rule Restates the Chain Without TC or a Ledger - On the story tree, § 2 of the shipped rule `minimal-implementation.md` MUST restate the traceability chain of the constitution's Article V rather than spell a chain of its own, with no TC hop and no execution ledger among the obligations it keeps. | EX-0001-0091-06 |
| BR-0004-0022 | An Observation Is an Example Row - On the story tree, the shipped rule `minimal-implementation.md` MUST define an observation as an EX row in a story's `03_Example.md`, located by resolving `paths.specsDir` from `qfai.config.yaml`, in place of a test-case row in `<paths.specsDir>/spec-*/06_Test-Cases.md`. | EX-0001-0091-07 |
| BR-0004-0023 | Scoped Validate Gate Per Business Flow - On the story tree, `/qfai-implement` invoked by name runs `qfai validate` once, at completion, as `qfai validate --profile tdd --fail-on error --flow BF-NNNN`, scoped to the flow the invocation owns. Inside a route it runs no validate: the route's verify stage does. | EX-0001-0094-05 |
| BR-0004-0025 | Consume the Producer-Owned Prototype Handoff - `/qfai-implement` MUST read `finalArtifact`, `procurement` and `implementationNotes` from `.qfai/prototype/final/handoff.json`. - The prototyping contract owns the handoff fields and the record of where each image came from. Implementation MUST NOT impose the retired exactly-four-field set or require `mustPreserve`, `mayAdapt` or `mustNotCopy`. | EX-0001-0095-01 |
| BR-0004-0026 | - Verify is always full-scan. - A validation error prevents Verify from passing. | EX-0001-0156-01, EX-0001-0156-03 |
| BR-0004-0027 | - The code review is part of the completion gate: a `REVISE` verdict blocks completion until every finding of that review is fixed or answered; no reviewer is rerun. | EX-0001-0157-01 |
| BR-0004-0028 | - Validate remains the source of deterministic schema/evidence findings. | EX-0001-0156-02 |
| BR-0004-0029 | - `full-harness` wording is artifact vocabulary and does not restore a removed runtime or CLI entrypoint. - The package surface exposes no removed compatibility namespace or category. | EX-0001-0156-02, EX-0001-0158-01 |
| BR-0004-0031 | - On the story tree, `references/articles.md` MUST restate the constitution's Article V chain rather than spell one of its own, with no TC hop and no `tdd/test-list.md`. - Its Tests hop MUST split by layer as `cli-0014-qfai-validate.md` states what counts as a test: a BF from E2E tests, an AC from integration or API tests, an EX from any selected test file. | EX-0001-0159-02 |
| BR-0004-0032 | - On the story tree, `references/context-load.md` MUST read the spec tree from `<paths.specsDir>` and contracts from `<paths.contractsDir>`, never from a literal `.qfai/specs/` or `.qfai/contracts/` path. - `tech.md` MUST be read from `<paths.contractsDir>`, and the product facts from the policy files `objective.md`, `initiative.md` and `principle.md` under `<paths.specsDir>/01_policy/`, in place of `.qfai/assistant/catalog/`. | EX-0001-0158-02 |
| BR-0004-0033 | - On the story tree, the decision sources `SKILL.md` names MUST be the rows of `decisions.md`, cited by `DEC-NNNN`, in place of a spec's `07_Decisions.md` and `_policies/08_Decisions.md` (`DR-*`). - A row with Status REJECTED MUST be read as a rejected option. | EX-0001-0158-03 |
| BR-0004-0034 | - With the `rule/ skill/ agent/ prompt/` assistant tree, `/qfai-verify` MUST read the constitution from `.qfai/assistant/rule/`. | EX-0001-0159-03 |
| BR-0004-0035 | - With the `rule/ skill/ agent/ prompt/` assistant tree, `/qfai-verify` MUST take routing and review profiles from the built-in defaults, with each matching `qfai.config.yaml` override replacing its default entry. - An agent's entry (`kind`, `owned_artifacts`, `tool_profile`, `permission_profile`, `specialization_tags`) MUST be read from its card frontmatter, not from `agent-catalog.yml`. | EX-0001-0159-04 |
| BR-0004-0036 | In workflow mode `active`, `/qfai-implement` and `/qfai-verify` each make the stage-skill entry check that `.qfai/assistant/rule/shared-skill-operating-baseline.md#workflow-run-entry-check-mandatory` states: selected not by name, the skill edits nothing and passes the request to `qfai-run`. Run as a stage of a route, it runs only the steps the plan names. | EX-0001-0200-01, EX-0001-0208-07 |
| BR-0004-0046 | A diagnosis returns exactly one verdict of `missing-test`, `defective-test`, `regression`, `expectation-differs`, `as-specified`, `not-ours`, `duplicate`, `needs-info`, `surface-conflict`, `check-gap` and `product-race`. Its `matchedIds` name the BF, AC or EX IDs of the flow that the next stage acts on, and its `reproductionRef` names the record of the reproduction. | EX-0001-0201-02, EX-0001-0215-01 |
| BR-0004-0047 | When a diagnosis finds a missing test on behaviour an existing AC states, `/qfai-implement` appends no `Change request:` row. The line of `SKILL.md` that sends discoveries to `/qfai-sdd` as a change request states this carve-out, and every other scope gap still goes there as a change request. | EX-0001-0201-03, EX-0001-0201-04 |

| BR-0004-0050 | A test fix names the ID the expectation checks before and after the fix and re-runs the test. The fixed test annotates the same IDs as before, and no story, contract or `decisions.md` file changes. | EX-0001-0203-01 |
| BR-0004-0051 | A test fix after which the expectation would check a different ID is not made: the session stops and names `qfai-sdd` as the owner of the change. | EX-0001-0203-02 |
| BR-0004-0052 | A test fix is served by `/qfai-implement` whatever layer the diagnosis's first matched ID names, as `rule/test-layers.md` maps BF to E2E tests, AC to integration or API tests, and EX to every other test. | EX-0001-0203-03 |
| BR-0004-0059 | Within each built-in plan, the stages whose steps `qfai-discussion`, `qfai-sdd`, `qfai-prototyping` and `qfai-verify` own run in the order configure, discussion, sdd, prototyping, implement, verify.
