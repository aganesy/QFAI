# CLI-0015: `qfai workflow`

## Ownership boundary

This contract decides the `npx qfai workflow` command: its one operation,
`plan`, the input it reads and the plan it returns. It holds the route catalog,
the decision rules that choose a route, and the decision points, release points
and branch points a plan declares. It also decides how the session follows a
plan: what it shows the user, which decisions it asks and which it takes, the
two reviews of a change route, how an approval is recorded, and how a stage skill takes a request.

The plan files and the shipped schemas are decided by the workflow files
contract (CLI-0020). What `qfai init` installs for this command is decided by
the `qfai init` contract (CLI-0009), the drift gate that reads `Change
request:` rows by the `qfai validate` contract (CLI-0014), and how a
story-authoring stage records what the user approved by the story-tree
authoring contract (CLI-0019).
