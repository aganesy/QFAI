# Assistant Routing Contract

- Contract scope: assistant cards, skill routing, review profiles, and handoff boundaries
- Owning flow: `BF-0001`
- Used-by: all routed skills and the assistant validators

## Ownership boundary

The shipped agent card frontmatter is the only agent definition. Package
defaults define routing and review profiles. A project may replace a matching
default entry through `qfai.config.yaml`; it may not supply a second agent
catalog or a partial field merge. The installed package is required to read
those defaults. A missing package is an explicit stop with an install command,
not a reason to reconstruct routing from a stale project copy.

The installed package's `assets/init/.qfai/assistant/skill/*/SKILL.md` files
are the shipped skill inventory. No fixed skill count or retired skill name is
an inventory rule. A route may select only a skill present in that inventory;
the skill's `SKILL.md` and the resolved package defaults state its role and
review obligations.

The orchestrator delegates according to the resolved route and obtains every
blocking review required by the profile. Review and implementation belong to
different agents when the profile requires that separation. Handoff records
preserve task state and the next action. `qfai-validate.md` owns machine
findings for missing cards or broken routing; `qfai-init.md` owns the shipped
assistant tree and host integration links. The decision-record CLI owns its
query surface.
