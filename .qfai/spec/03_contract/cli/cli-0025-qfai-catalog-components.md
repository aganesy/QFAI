# CLI-0025: `qfai catalog components`

## Ownership boundary

This contract decides which files `qfai catalog components` reads, what it counts as a component, which fields it records, the file it writes, its `--check` mode, its `--brief` mode, which reads the committed catalogue and the `.qfai/catalog/design.tokens.json` and `.qfai/catalog/theme.css` that `qfai catalog design` writes, and how it exits. It also decides what the shipped implementation guidance tells an agent about the catalogue, and which interactive widgets the shipped procurement rule asks to record their accessibility behaviour in it.

The warnings `qfai validate` raises from the committed catalogue belong to the `qfai validate` contract (CLI-0014). Where a screen region comes from belongs to the shipped procurement rule.

The shape and the starter entries of the base component catalogue QFAI ships beside that rule, which a catalogued component names in its `@pattern`, are decided here too.

## Business rules

| BR-ID | Statement | Examples |

| BR-CLI-0025-0001 | `qfai catalog components` takes `--check`, `--brief` and `--root`. It reads the `.tsx` and `.jsx` files the `uiux.surfacePaths` globs select from the root, except under `node_modules` and except a file whose name holds `.test.`, `.spec.` or `.stories.`, with the `typescript` package resolved from the project root. A component is a top-level `function` or `const` whose name starts with an upper-case letter, whose function, or the first function a wrapping call such as `memo(...)` or `forwardRef(...)` receives, holds a JSX element or fragment, and that is exported on its declaration, by name in an `export { ... }` list with no module specifier, or by `export default` of its name. A class component is not listed, nor is a `let`, `var` or `using` binding. | EX-0001-0307-01, EX-0001-0307-02, EX-0001-0307-03, EX-0001-0307-13, EX-0001-0307-22 |
| BR-CLI-0025-0002 | Each component records `name`, its repository-relative `file` with forward slashes, and `props`, taken from the first of these that resolves: the member names, in declaration order, of the first parameter's type when it is a literal, an interface or type alias the same file declares, with the members of the same-file interfaces an interface extends, or an intersection of those; the names an object destructuring of the first parameter binds, rest element aside; the members of the first type argument of the `const`'s own annotation; the members of the last type argument of the outermost wrapping call that has type arguments. A props type nothing in the file declares gives no `props` key. The last `/** ... */` block before the declaration, `//` line comments after it aside, supplies `source`, `reason`, `states` (split on `,`), `pattern` and `a11y` from the tags `@source`, `@reason`, `@states`, `@pattern` and `@a11y`. A line opening with one of these tags and then a space or its end starts that tag; a line opening with another `@word` and then a space or its end ends it; any other line continues the current tag, its lines joined by single spaces. An empty tag gives no key. | EX-0001-0307-01, EX-0001-0307-02, EX-0001-0307-13, EX-0001-0307-14 |
| BR-CLI-0025-0003 | The command writes `.qfai/catalog/components.yaml`: two header comment lines, then `components:` as a list sorted by `file` and then by `name`, each entry's keys in the order `name`, `file`, `props`, `variants`, `source`, `reason`, `states`, `pattern`, `a11y`, `tokens`, `realizes`, with no timestamp, so the same source gives the same bytes. That is the file's format: each entry holds a string `name` and `file` and, where present, `props`, `states`, `tokens` and `realizes` as lists of strings, `variants` as a mapping from names to lists of strings, and `source`, `reason`, `pattern` and `a11y` as strings; a committed file that is not a `components:` list of such entries is not a component catalogue. It prints one line naming the file and the number of components, with the number of files and the number with no `@source`, or saying that `uiux.surfacePaths` selects no `.tsx` or `.jsx` file, and exits 0. A read or write failure exits 1. Before replacing the catalogue, the command measures the rendered UTF-8 bytes. Above 8388608 bytes it exits 1, names the limit, tells the reader to shorten catalogue tags in selected component doc comments or narrow `uiux.surfacePaths`, and leaves any existing catalogue intact. Output at the limit is written normally. | EX-0001-0307-04, EX-0001-0307-17, EX-0001-0307-30, EX-0001-0307-39 |
| BR-CLI-0025-0004 | With `--check` the command writes nothing. It exits 0 when the committed file holds the text it would write, CRLF line ends read as LF, and otherwise exits 1 with one line naming the file and saying it does not exist or is out of date, with the command to run. A committed catalogue above 8388608 bytes is unreadable. The read uses the verified descriptor and requests no byte past the limit plus one, even when the file grows. The command exits 1 naming the file and limit and saying that nothing was compared. A catalogue at the limit is compared normally. | EX-0001-0307-05, EX-0001-0307-29 |
| BR-CLI-0025-0005 | When a `.tsx` or `.jsx` file is selected and `typescript` cannot be resolved, fails to load, or offers no `createSourceFile`, the command prints one line naming `typescript` and the number of files it could not read, writes no catalogue, and exits 1. | EX-0001-0307-06 |
| BR-CLI-0025-0006 | The shipped implementation UI guidance tells the implementer to read `.qfai/catalog/components.yaml` before writing a region, to reuse a listed component that realises it, and, on authoring a shared component, to write its doc comment with the five tags and run `qfai catalog components`. The procurement ladder's reuse rung and the test-first implementation step point to that guidance. | EX-0001-0307-12 |
| BR-CLI-0025-0007 | The shipped procurement rule lists the interactive widgets that come from a catalogue or headless library when one is available, skipping the rung that composes from primitives: dialog, alert dialog, drawer or sheet, menu and menu button, tabs, combobox and autocomplete, listbox and select, tooltip, popover, toast, date picker, and disclosure and accordion, each with its WAI-ARIA Authoring Practices pattern. It says that such a widget, when authored, records that pattern and the keyboard behaviour it implements in its component's `@a11y` tag, with a test covering that behaviour, and that the region's procurement record names them. | EX-0001-0310-06 |
| BR-CLI-0025-0008 | The command writes the catalogue only inside the project. Before and after it creates `.qfai/catalog`, it checks every directory on the path from the root: a symbolic link, a junction included, or an entry that is not a directory, or a catalogue path that is a link or not a file, stops it with one line naming the file and that path, writing nothing and leaving any existing catalogue as it was, and it exits 1. Only a catalogue that is not there counts as absent: one whose metadata cannot be read for another reason stops it the same way, the line naming the catalogue and the cause. Otherwise it writes the text to a new temporary file it creates exclusively in `.qfai/catalog` and renames that file onto the catalogue, leaving no temporary file behind. With `--check` it runs the same check before it reads the catalogue, and one that fails stops it with one line naming the file and that path, saying that nothing was compared, and it exits 1. | EX-0001-0307-18, EX-0001-0307-19, EX-0001-0307-23, EX-0001-0307-24, EX-0001-0307-25 |
| BR-CLI-0025-0009 | Before it scans, the command reads `qfai.config.yaml`. When the file does not parse or holds a value the loader reports as an error, it prints one line naming the file and saying that no catalogue was written, or under `--check` that nothing was compared, then one line per error, and exits 1 without scanning, comparing or writing, so an existing catalogue is as it was. | EX-0001-0307-20, EX-0001-0307-21 |
| BR-CLI-0025-0010 | Without `--check` the command scans and writes the catalogue only while it holds `.qfai/tools/state/component-catalog.lock`, a file it creates exclusively with a record of its process once every directory on the path to the lock, which sits under the `.qfai/tools/` that `qfai init` keeps out of Git, is checked before and after it is created in the same way as the directories on the path to the catalogue, and removes once it is done while the file still holds its record, so a run that scanned an earlier revision of the source never replaces the catalogue a run that scanned a later one wrote. A run that finds the lock held scans and writes nothing and exits 1 with one line naming the catalogue, saying any existing catalogue is as it was and that another run is writing it, to be retried once it finishes, when the process the lock records is running or its record is still being written, and otherwise that the lock is to be removed by hand; the lock is left as it was. When the lock no longer holds the run's record at the end, the run leaves it in place and exits 1 with one line that says the catalogue was written, or why it was not, and that the lock was left. | EX-0001-0307-26, EX-0001-0307-27 |
| BR-CLI-0025-0011 | Each component also records `realizes`: the business-rule IDs cited on standalone comment lines in its leading comments and its declaration: the whole function, or its own declarator of a `const` list. A line counts when it holds only optional spaces, a comment marker such as `//`, `/*` or `*`, optional spaces and `QFAI:` followed by a `BR-UI-`, `BR-API-` or `BR-DB-` ID, followed by a space, the end of a block comment or the end of the line: the implementation citation that validation counts. The IDs are listed once each, sorted, as the last key of the entry; a component that cites none has no `realizes` key. An ID inside a single-line string, or after code on the same line, including a comment that follows the previous statement on its last line, is not recorded. | EX-0001-0307-31, EX-0001-0307-32, EX-0001-0307-34 |
| BR-CLI-0025-0012 | The shipped implementation UI guidance tells the implementer that a component that realises a UI business rule carries the rule's `QFAI:BR-UI-` comment line inside its declaration or on its leading comment lines, so the catalogue's `realizes` lists the rule, and to look for a listed component whose `realizes` holds the rule before writing a region for it. | EX-0001-0307-33 |
| BR-CLI-0025-0013 | Each component whose props come from a type also records `variants`, right after `props`: a mapping from each property member, in the order `props` lists it, whose type is a union of string literal types, its `undefined` and `null` members aside, or a reference to a type alias the same file declares that is such a union, to those literal values in the order they are written. A member whose type is imported, mixes a string literal with another kind of type or is a single literal records no variant, a prop an object destructuring binds records none, and a component with no such member has no `variants` key. | EX-0001-0307-35, EX-0001-0307-36, EX-0001-0307-37 |
| BR-CLI-0025-0014 | Each component also records `tokens`: the CSS custom property names, leading `--` kept, that its own text references through `var(--name`, in a string, a template literal, a style object or a Tailwind arbitrary value such as `bg-[var(--color-brand)]`. Its own text is its leading comments, from the line after the previous statement's last line when that line also holds code, and the whole function, or its own declarator of a `const` list from that declarator's first character, so a reference after the previous statement on its last line is not recorded. The names are listed once each, sorted, as the key before `realizes`; a component that references none has no `tokens` key, and a theme utility class such as `bg-brand` is not resolved to its variable. | EX-0001-0307-38, EX-0001-0307-39 |
| BR-CLI-0025-0015 | QFAI ships a base component catalogue, `.qfai/assistant/rule/references/base-components.yaml`, which `qfai init` writes with the assistant tree. It holds only `components`, a list with one entry for each part most products need before a project has built it: `error-summary`, `field-with-error`, `step-indicator`, `confirm-step`, `skip-link`, `sticky-action-bar`, `status-message` and `empty-state`. Each entry has exactly the keys `id`, `purpose`, `anatomy`, `role`, `accessibleName`, `keyboard`, `focus`, `states`, `content`, `runtime` and `sources`, in that order. The `id` is kebab-case, unique in the file and usable as a component's `@pattern`. `anatomy`, `keyboard`, `content` and `sources` are non-empty lists of text, `states` maps each state the part has to how it renders, and `runtime` has exactly `serverRendering`, `csp` and `noScript`. Each source is a native element written as `native <element>` or an `https://` page a reader can open. The file describes the parts and mirrors no external registry. | EX-0001-0307-41, EX-0001-0307-42 |
| BR-CLI-0025-0016 | The shipped implementation UI guidance tells the implementer that, before building a part the base catalogue describes and `.qfai/catalog/components.yaml` does not list, it reads the part's entry, builds the part once as a shared component that meets it and names the entry's `id` in the component's `@pattern`, and gives the component `@source authored` with an `@reason` naming that `id`, since an entry describes a part and is not an installed catalogue. The base catalogue's header comment says the same. The procurement ladder's reuse rung names the base catalogue and the same `@pattern` use. | EX-0001-0307-43 |
| BR-CLI-0025-0017 | With `--brief` the command reads `.qfai/catalog/components.yaml` as committed, and no configuration or source, writes nothing, and prints to stdout a line naming the catalogue, then one line per listed component in the catalogue's order: its name and file, then every other key it holds, `pattern`, `states`, `props` and `a11y` first and the rest in the order the entry gives them, a list as its items joined by commas and a mapping as `key: a \| b` pairs. When `.qfai/catalog/design.tokens.json` exists, a last line gives its token count, or says it does not parse, and names `.qfai/catalog/theme.css` when that exists. It exits 0. A catalogue that does not exist, is not a component catalogue or cannot be read prints one line naming it, with the command to run or the cause, and exits 1. A `design.tokens.json` or `theme.css` that exists but cannot be read prints one line naming that file and the cause, and exits 1. `--brief` with `--check` is a usage error: the command prints `qfai catalog components: give --brief or --check, not both.` with its usage and exits 2. | EX-0001-0307-44, EX-0001-0307-45, EX-0001-0307-47 |
