# CLI-0008: `qfai doctor`

## Ownership boundary

This contract holds the rules for `qfai doctor`: the checks it runs on a
project, how it groups and reports them, the exit code it returns, and the
writes `--clean` and `--autoremediate` make when the operator asks for them.

Which workflow files QFAI ships, and that it keeps no record of them, belong
to the shipped-workflows contract. Doctor reads the workflow files on disk and
compares each installed shipped workflow with the copy in the package,
and reports a difference without rewriting the file. What `qfai init`
installs belongs to the init contract, and the findings `qfai validate` raises
belong to the validate contract.

## Business rules

| BR-ID | Statement | Examples |
| --- | --- | --- |
| BR-0008-0001 | Without `--format`, doctor prints its diagnosis as text: the root, the config path and whether it was found, the checks and the summary. `--format json` prints one JSON document whose top-level keys include `root`, `config`, `checks` and `summary`. Without `--out`, stdout then carries that document alone, and every line about a side effect goes to stderr. | EX-0003-0001-01, EX-0003-0005-01 |
| BR-0008-0002 | Doctor reports whether `qfai.config.yaml` was found. When it is present, `config.found` is `true` and `config.configPath` names the file. When it is absent, `config.found` is `false` and the `config.search` check is a `warning`. When the configuration loader reports issues, the `config.load` check is `error`, `details.issues` lists them, and the check message names each issue, without the source excerpt a YAML parse error appends and cut in the middle to at most 500 displayed characters, so the text output carries them too. Directory checks resolve `paths.specsDir` and `paths.contractsDir` from `qfai.config.yaml`, defaulting to `.qfai/spec` and `.qfai/spec/03_contract`, and a configured non-default directory that does not exist is reported as a `warning` whose `details.path` names the resolved path. | EX-0003-0001-03, EX-0003-0001-05, EX-0003-0001-07, EX-0003-0001-08, EX-0003-0002-01 |
| BR-0008-0003 | When `--root` is not given, doctor searches from the start directory upward for `qfai.config.yaml` and takes the directory holding it as the root. | EX-0003-0001-02, EX-0003-0001-06 |
| BR-0008-0004 | Without `--fail-on`, doctor applies `validation.failOn` from `qfai.config.yaml`, whose shipped default is `error`. `error` exits 1 when error > 0; `warning` exits 1 when warning + error > 0; `never` always exits 0. A diagnosis below the threshold exits 0. | EX-0003-0012-01, EX-0003-0012-02, EX-0003-0012-03, EX-0003-0012-04 |
| BR-0008-0005 | With `--out <path>`, the report is written to that file instead of stdout, under every `--format`. Stdout carries only the line `doctor: wrote <absolute path>`. A relative path resolves against the working directory, and missing parent directories are created. The file is written on every invocation that passes `--out`, with or without `--clean` or `--autoremediate`, and `--dry-run` does not suppress it. | EX-0003-0005-02, EX-0003-0005-03, EX-0003-0005-04 |
| BR-0008-0006 | The summary holds the counts `ok`, `info`, `warning` and `error`, each equal to the number of checks at that severity. | EX-0003-0001-04 |
| BR-0008-0007 | `qfai doctor --profile prototyping` probes launchers in order: (1) `node_modules/.bin/playwright`, including the Windows `playwright.cmd`, `playwright.bat` and `playwright.ps1` variants, then (2) `npx --no-install playwright --version`, whose `--no-install` keeps the probe from installing anything, then (3) the deprecated `playwright-cli`, including its `.cmd` and `.bat` variants. The first stage that resolves is reported as the launcher. | EX-0003-0006-01, EX-0003-0006-05 |
| BR-0008-0008 | `playwright-cli`, including its `.cmd` and `.bat` variants, is the third probe stage and still resolves as a launcher. Past its `1.10.0` sunset, resolving it emits `D-DEPRECATED-PROBE` at severity `error`, and the message carries `sunset: 1.10.0` and the install hint `npm i -D playwright`. | EX-0003-0006-02 |
| BR-0008-0009 | When no probe stage resolves a launcher, the check is an `error` whose text names the probe order it tried and the install hint `npm i -D playwright`: not `npx playwright install`, `pnpm` or `yarn`, and never a vague phrase such as "install playwright manually". | EX-0003-0006-03 |
| BR-0008-0011 | The text summary splits findings into two groups under the headers "errors blocking the active profile" and "warnings advisory of drift", and those header strings are stable identifiers. The first group holds the `error` findings and the second every `warning` and `info` finding. JSON output carries no group key; a consumer derives the group from each check's `severity`. | EX-0003-0007-02 |
| BR-0008-0014 | Among its writes, `qfai doctor --autoremediate` (a) runs `npm install` for the `runtimeDependencies` of the manifest `--profile <skill>` names and (b) runs the `--clean` run-log prune. The install phase runs only when `--profile <skill>` names a manifest; without it the phase is skipped and doctor says so. Interactive confirmation is required by default, and `--yes` skips it. When `--clean` and `--autoremediate` are both passed, only the autoremediate pass runs. | EX-0003-0009-01, EX-0003-0009-06 |
| BR-0008-0015 | When a standard CI environment is detected, `--autoremediate` is off: doctor prints the line `autoremediate disabled in CI`, rewrites no `.gitignore`, runs no remediation and exits 0 without building the diagnosis. A standard CI environment is any `CI` value other than `false`, `0` or empty, compared trimmed and case-insensitively, or `GITHUB_ACTIONS=true`. `--clean` is not turned off in CI. `--dry-run` previews the remediation plan and performs no install, `.gitignore` write or run-log removal. | EX-0003-0009-02, EX-0003-0009-03, EX-0003-0009-04, EX-0003-0009-05, EX-0003-0009-07 |
| BR-0008-0016 | `qfai doctor --profile <skill>` reads `<paths.skillsDir>/<skill>/manifest.json`, probes `node_modules/.bin/...` and `node_modules/<name>/` for each `runtimeDependencies` entry, and reports a missing dependency with its install command. The path comes from `paths.skillsDir`, so a project that relocates its skill tree keeps its manifest resolved. | EX-0003-0010-01, EX-0003-0010-03 |
| BR-0008-0017 | A manifest whose `runtimeDependencies` is an empty array produces no probe finding. Authoring the manifest schema and linting the shipped manifests are outside doctor; the probe is doctor's part. | EX-0003-0010-02 |
| BR-0008-0023 | Doctor resolves configured paths from `qfai.config.yaml`. An absent configured `paths.srcDir`, `paths.testsDir` or `paths.outDir` that is not the shipped default produces a warning for its own key with `details.path` naming the resolved path and guidance to configure or create it. When nothing is at the path and the path is the shipped default, the check is `info` and carries one line saying why: `the project has no source yet`, `the project has no tests yet` or `the first qfai validate creates it`. A broken link at that path stays a `warning`. A missing `validate.json` is an `info` check that says to run `qfai validate`; a `validate.json` that is not a readable file, such as a directory or a broken link, is a `warning`. None of this writes to `qfai.config.yaml`. A configured deprecated `paths.promptsDir` or default directory with content beyond the shipped `.gitkeep` produces a `paths.promptsDirDeprecated` warning with the legacy path and migration guidance to `skillsDir`. The absent default and the shipped empty directory do not warn. | EX-0003-0003-01, EX-0003-0003-02, EX-0003-0004-01, EX-0003-0004-02, EX-0003-0004-03, EX-0003-0004-04, EX-0003-0003-05, EX-0003-0003-06 |
| BR-0008-0024 | In a newly initialized project with Playwright installed, the `prototyping.playwrightCli` check of `qfai doctor --profile prototyping` is `ok` and contributes no `[error]` line. Other prototyping checks, such as the UI contract checks, are not covered: a project with no UI contract reports them as errors. Warnings remain advisory under the default `--fail-on` behavior. | EX-0003-0006-04 |
| BR-0008-0025 | `qfai doctor` reports a `workflows.docsLane` check. When `.github/workflows/qfai-docs.yml` is absent from the project, whether it was never installed or was removed after install, the check is `error` and its message names the file and the packaged copy to restore it from. When the file is present the check is `ok`. The document-schema lane is required, so removing the file is not a way to turn the check off. | EX-0003-0011-14, EX-0003-0011-15 |
| BR-0008-0026 | `qfai doctor` accepts `--profile <name>`, `--format` with `text` or `json`, `--out <path>`, `--fail-on` with `error`, `warning` or `never`, `--clean`, `--autoremediate`, `--dry-run` and `--yes`. Without `--profile` it runs the profile-agnostic checks only. A profile name such as `prototyping` adds that profile's runtime preconditions, and a skill name such as `qfai-prototyping` adds the runtime dependencies its manifest declares. | EX-0003-0001-01, EX-0003-0006-01, EX-0003-0010-01 |
| BR-0008-0027 | Doctor is read-only by default: without `--clean` or `--autoremediate` it changes nothing in the repository, and the `--out` file is its only write. No probe runs an install command or `playwright install`; an install hint is printed as text for the operator to act on. Doctor probes no network reachability, which belongs to the gate of the profile that needs it. | EX-0003-0006-03, EX-0003-0005-02 |
| BR-0008-0028 | `--autoremediate` writes only these paths: the managed block of `<root>/.gitignore`, when the block is missing or stale and never in a detected CI environment; `<outDir>/run-<ts>/` removed, under the same rules as `--clean`; and, for `--profile <skill>`, `node_modules/`, `package.json` and `package-lock.json` through `npm install <name>`, which runs without `--no-save`. Widening this set is a contract change. | EX-0003-0009-01, EX-0003-0009-03 |
| BR-0008-0029 | The `.gitignore` rewrite writes nothing when the managed block already holds the marker, every required governance negation after any ignore line it undoes, and no retired legacy line. A repeat `--autoremediate` on a repository whose block is current, whose dependencies are installed and whose run logs are all within the TTL writes nothing: `.gitignore` stays byte-identical and the run leaves no diff. | EX-0003-0009-03 |
| BR-0008-0030 | The install runs `npm install <name>` without `--ignore-scripts`, so the package's `preinstall`, `install`, `postinstall` and `prepare` scripts run with the operator's privileges and can write outside the paths doctor lists. That is why `--autoremediate --profile <skill>` is an action the operator confirms rather than one to schedule unattended. An operator who needs the listed paths to be the whole story installs the dependency with `npm install <name> --ignore-scripts` and runs doctor without `--autoremediate`. | EX-0003-0009-01 |
| BR-0008-0033 | `--dry-run` applies to `--clean` and `--autoremediate` alike. It runs every read-only check the live pass runs, reports in the future tense only the changes that pass would make, such as `would remove -> <run id>`, and writes nothing. A count a dry run prints is what a live run would change, never what was changed. | EX-0003-0009-05 |
| BR-0008-0034 | `--clean` removes each `<outDir>/run-<ts>/` older than `report.staleTtlDays`, which is 14 days when unset, that is outside the newest `report.keepLatestRuns` and is not the run `validate.log` points at. `report.staleTtlDays: 0` turns pruning off, and `report.keepLatestRuns: 0` is read as 1. A run log is the one thing doctor deletes, and nothing else is deleted on any flag. | EX-0003-0008-06, EX-0003-0008-07 |
| BR-0008-0035 | The run-log prune runs only when the config loaded without issues and no other project root in the repository resolves `paths.outDir` to the same directory. Otherwise the prune is skipped with its reason reported. A removal that fails is reported per run id and makes doctor exit non-zero, whatever `--fail-on` says. | EX-0003-0008-08 |
| BR-0008-0036 | `qfai doctor --profile prototyping` reports a `prototyping.designMdReadiness` check titled `Root DESIGN.md readiness`, whose `details.designMd` names root `DESIGN.md`.
