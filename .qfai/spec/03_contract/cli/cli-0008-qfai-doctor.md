# CLI-0008: `qfai doctor`

## Ownership boundary

This contract holds the rules for `qfai doctor`: the checks it runs on a
project, how it groups and reports them, the exit code it returns, and the
repairs `--clean` and `--autoremediate` make when the operator asks for them.

The file states and the provenance record of the shipped GitHub Actions
workflows belong to the shipped-workflows contract, and doctor only reads them.
What `qfai init` installs belongs to the init contract, and the findings
`qfai validate` raises belong to the validate contract.

| BR-0008-0002 | Doctor reports whether `qfai.config.yaml` was found. When it is present, `config.found` is `true` and `config.configPath` names the file. When the configuration loader reports issues, the `config.load` check is `error` and `details.issues` lists them. Directory checks resolve `paths.specsDir` and `paths.contractsDir` from `qfai.config.yaml`, defaulting to `.qfai/spec` and `.qfai/spec/03_contract`, and a configured non-default directory that does not exist is reported as a `warning` whose `details.path` names the resolved path.                                                                                           | EX-0003-0001-03, EX-0003-0001-05, EX-0003-0001-07, EX-0003-0002-01                  |

| BR-0008-0012 | `qfai doctor --clean` moves each review pack under `.qfai/review/<ts>/` whose age is strictly greater than the TTL to `.qfai/review/_archive/<ts>/`, creating `_archive/` when a pack is eligible and skipping it when packs are listed, so a rerun moves nothing more. A pack git tracks also stays when `.qfai/review/_archive/` is git-ignored, because the move would take it out of version control.                                                                                                                                                                                                      | EX-0003-0008-01, EX-0003-0008-03, EX-0003-0008-04, EX-0003-0008-05                  |

| BR-0008-0014 | Among its writes, `qfai doctor --autoremediate` (a) runs `npm install` for the `runtimeDependencies` of the manifest `--profile <skill>` names, (b) runs the `--clean` archive and run-log prune, and (c) writes missing default-keyed fields to `qfai.config.yaml`. User-authored values are never overwritten. When `--clean` and `--autoremediate` are both passed, only the autoremediate pass runs.                                                                                                                                | EX-0003-0009-01, EX-0003-0009-06                                                    |

| BR-0008-0017 | A manifest whose `runtimeDependencies` is an empty array produces no probe finding. | BR-0008-0018 | `qfai doctor` compares each shipped workflow installed under the adopter tree's `.github/workflows/` with the copy in the installed package, by content after line-ending normalization, as `skills.integrity` does for skills. | BR-0008-0027 | Doctor is read-only by default: without `--clean` or `--autoremediate` it changes nothing in the repository, and the `--out` file is its only write. | BR-0008-0028 | `--autoremediate` writes only these paths: the managed block of `<root>/.gitignore`, when the block is missing or stale and never in a detected CI environment; `qfai.config.yaml`, by appending a default-keyed field such as `review:` that the parsed document lacks; `.qfai/review/review-<ts>/` renamed into `.qfai/review/_archive/` and `<outDir>/run-<ts>/` removed, under the same rules as `--clean`; `.qfai/review/.legacy-packs` and a `revision_form: "legacy"` field in a named pack's `.qfai/review/review-<ts>/summary.json`; and, for `--profile <skill>`, `node_modules/`, `package.json` and `package-lock.json` through `npm install <name>`, which runs without `--no-save`. | BR-0008-0033 | `--dry-run` applies to `--clean` and `--autoremediate` alike.
