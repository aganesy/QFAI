# CLI-0017: `qfai workflow`

## Ownership boundary

This contract decides the `npx qfai workflow` command: its seven operations, the
payloads they read and return, how a run moves between states, what stops a run
and when `finish` reports it complete. It also decides what the operator sees of
a run through `qfai-run`, and how a stage skill takes a request or a work order.

Where a run's files live, the shape of its local records and of its
authorization record, the plan files and the shipped schemas are decided by the
workflow files contract (CLI-0022). What `qfai init` installs for this command
is decided by the `qfai init` contract (CLI-0011), the drift gate that reads the
`Change request:` rows a run appends by the `qfai validate` contract (CLI-0016),
and how a story-authoring stage writes its triage rows by the story-tree
authoring contract (CLI-0021).
