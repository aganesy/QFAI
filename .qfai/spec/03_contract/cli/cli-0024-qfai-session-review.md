# CLI-0024: `qfai session-review`

## Ownership boundary

This contract decides which local agent transcripts `qfai session-review` reads, what it counts in them, what its report may hold, where the report goes, and how the command exits.

What the session review does with the report, and when it runs, is decided by the `qfai init` contract (CLI-0009), which owns the shipped session-feedback rule.

## Business rules

| BR-ID | Statement | Examples |
| --- | --- | --- |
| BR-0024-0001 | `qfai session-review` takes `--agent claude\|codex\|all`, `--session <id>`, `--since <value>`, `--format md\|json`, `--out <path>` and `--root`. With no selection it reports, for each chosen agent, `all` by default, the session whose transcript file changed last. `--session` reports the session with that ID. `--since` reports every session whose transcript file changed at or after the instant it names: an ISO 8601 date the calendar has, read as midnight UTC, or an ISO 8601 date and time with `Z` or an explicit offset. The report goes to standard output; `--out` writes it to that file instead, a relative path resolved against the root, and the command writes no other file. Finding no session prints one line saying so, naming the `--since` value when one was given and transcripts exist, and exits 0. `--session` with `--since`, any other `--since` value, an unknown `--agent` or `--format` value, or a `--session` ID no transcript of the chosen agents holds is a usage error and exits 2. A transcript, `.agents/rules/reminders.json` or the `--out` file that is there but cannot be read or written, or a `reminders.json` that is not a JSON object, prints one redacted line on standard error, prints no report and exits 1. | EX-0001-0294-05, EX-0001-0294-06, EX-0001-0294-07, EX-0001-0294-08, EX-0001-0294-23 |
| BR-0024-0002 | A Claude Code transcript is `<id>.jsonl` in `projects/<slug>/` under `CLAUDE_CONFIG_DIR`, or under `.claude` in the home directory when that is unset, where the slug is the absolute root with every character other than an ASCII letter or digit replaced by `-`, and whose first record that carries a `cwd` names the root, since two roots can share a slug. When that directory holds none, the transcripts of every project directory whose name starts with the slug's first 100 characters, compared without regard to letter case on Windows, are read up to their first record that carries a `cwd`, and those whose `cwd` is the root are the project's. A Codex transcript is a `sessions/YYYY/MM/DD/rollout-*.jsonl` file under `CODEX_HOME`, or under `.codex` in the home directory, whose first record, `session_meta`, names the root as its `cwd`; only that record is read to decide, and its `id` is the session ID. Paths are compared with forward slashes and no trailing slash, and without regard to letter case on Windows. A directory that is not there holds no transcript. | EX-0001-0294-01, EX-0001-0294-02, EX-0001-0294-03, EX-0001-0294-04 |
| BR-0024-0003 | A transcript is read line by line from the local disk, with CRLF line ends read as line ends. A line that is not a JSON object is skipped and counted as malformed. A Codex message is read only by the content kind the rollout marks it with. The command opens no network connection, and no source file it reaches imports a network module. | EX-0001-0294-15, EX-0001-0294-17 |
| BR-0024-0004 | Per session the report counts: each hook context shown that is one of the texts, full or brief, in the project's `.agents/rules/reminders.json`, under that text's key, where a text several keys carry is keyed by the leading `-`-separated words those keys share, else by the keys joined with `+`; a hook context that holds one or more of those texts inside other text, such as a host's prefix or several reminders joined, once under each text's key; each other hook context that starts with `QFAI` and a space under the key of the texts that start with the same words up to the first `(`, `:` or `.`, keyed as for a shared text, or under the key `unregistered` when no text does, while any other hook context is not counted; each file under `.agents/rules/`, `.agents/skills/`, `.qfai/assistant/`, `.claude/rules/` and `.claude/skills/` that a file read or a shell command names, with `.` and `..` resolved first, by its repository-relative path, with its reads, its repeats, and the result bytes of the reads that named that file and no other path; each failed tool call, per tool name, with the `QFAI-` finding codes its result carries; each `qfai` command run as the first word of a shell command, directly or through `npx`, `pnpm`, `pnpm exec`, `yarn`, `yarn exec` or the local bin, the line split at `;`, `&` other than one inside a redirection such as `2>&1` or `&>`, `\|`, `(`, `)` and line breaks that stand outside quotes, with the text from an unquoted `#` that starts a word to the end of its line read as a comment, by command and subcommand, with the count of each exit status, where the call's status is given only to a call that ran one `qfai` command as its last command, or ran one followed directly by an `echo` that is not in single quotes and prints `$?`, `${?}` or `$LASTEXITCODE` once, whose status is the number in the output's last line where that line is the echo's words with the number in the variable's place, and a call that ran several or ran another command after it, or one still running in the background, counts as unknown and a Codex shell call's status is the structured `exit_code` field of its own result, else the command executions the rollout records for the call, else the status line of the header Codex writes above the output, never a status or `exit_code` field its output prints; the structured-question calls and the questions they carry; and the typed user turns. A typed user turn is a message the user wrote, including text written beside a tool result in the same record, not a tool result, text in one of the hosts' own wrapper tags, such as a system reminder, a task notification or a command record, an interruption notice or injected `AGENTS.md` instructions. Each typed turn that matches a correction word is listed by its number among the typed turns and its matched words. The English words, matched as whole words in any letter case, are `actually`, `do not`, `don't`, `i meant`, `i said`, `incorrect`, `instead`, `not what`, `revert`, `should not`, `shouldn't`, `stop`, `undo` and `wrong`; twelve Japanese words of the same kind are matched as written. | EX-0001-0294-09, EX-0001-0294-10, EX-0001-0294-11, EX-0001-0294-12, EX-0001-0294-13, EX-0001-0294-14, EX-0001-0294-25, EX-0001-0294-26 |
| BR-0024-0005 | The report holds only agent names, session IDs, counts, byte sizes, turn numbers, exit statuses, repository-relative paths, reminder keys, tool names, finding codes, command names and matched words, and no message text, snippet or tool output. Every string it emits, and every error line, passes a fixed redaction set covering GitHub, OpenAI-style and AWS access keys, Slack tokens, JSON Web Tokens, bearer tokens, PEM private keys, `password=` values and e-mail addresses. The project root, the directories `CLAUDE_CONFIG_DIR` and `CODEX_HOME` name and the home directory, in either slash style and on Windows also in the Git Bash `/c/...` form, are written as `<root>`, `$CLAUDE_CONFIG_DIR`, `$CODEX_HOME` and `~` where they end at a path-segment boundary. A heading or table cell is kept on one line. | EX-0001-0294-16 |
| BR-0024-0006 | The report lists sessions by agent and then by session ID, and each list inside a session in a fixed order, and carries no wall-clock time, so the same transcripts give byte-identical reports whatever order the file system lists them in. Each session is headed `<agent>-<session ID>`. With `--format json` the report is one JSON object whose `sessions` array holds, per session, `name`, `agent`, `sessionId`, `records`, `malformedLines`, `typedTurns`, `reminders` and `reads` and `toolErrors` and `qfaiCommands` as arrays, `questions` with `calls` and `items`, and `corrections` with `turn` and `words`. | EX-0001-0294-08, EX-0001-0294-18, EX-0001-0294-22 |
