# Delivery Workflow Contract

- Contract scope: the `/qfai-atdd`, `/qfai-implement`, and `/qfai-verify` skill chain
- Owning specs: `spec-0008`, `spec-0011`, and `spec-0014`
- Used-by: implementation and quality-gate agents

## Ownership boundary

ATDD supplies E2E evidence for BF obligations and integration or API evidence
for AC obligations. Implementation selects an EX without an annotated test,
adds the test, and advances through Red, Green, and Refactor with evidence.
Verification reads the configured gate commands from `tech.md` and reports
their actual result. Each skill invokes `qfai validate --flow BF-NNNN` for the
business flow it is completing; the validate contract owns the finding and
test-annotation semantics. An exception only covers the row it names while
its decision is in force; it does not excuse related obligations by inference.

The test-layer policy is the package's `rule/test-layers.md`. It maps BF to
E2E, AC to integration or API, and EX to every other test. This contract
records the handoff among the three skills and does not duplicate command
syntax or the test-layer policy's full guidance.

For a UI implementation, the prototype handoff payload is DCON-008. The
prototyping contract owns its fields and production, including
`imageSources[]`; implementation reads the final artifact and design-system
input from that payload. This workflow does not define a second handoff
schema.
