# CLI-0026: `qfai catalog design`

## Ownership boundary

This contract decides what `qfai catalog design` reads from root `DESIGN.md`, the token file and the theme it writes, its `--check` mode and how it exits. It also decides the optional `data_display` section of the `DESIGN.md` front matter, which tokens it writes from `visual.layout`, and what the shipped implementation guidance tells an agent about the two files.

The warnings `qfai validate` raises from the committed files belong to the `qfai validate` contract (CLI-0014). The rest of the `DESIGN.md` schema belongs to the shipped DESIGN.md specification.

## Business rules

| BR-ID | Statement | Examples |
| --- | --- | --- |
| BR-0026-0001 | `qfai catalog design` takes `--check` and `--root`, and reads the front matter of `DESIGN.md` at the root with the same parser the root `DESIGN.md` parse check uses. | EX-0001-0312-01 |
| BR-0026-0002 | The command writes `.qfai/catalog/design.tokens.json` as two-space JSON in the Design Tokens Community Group 2025.10 format, with a root `$description` saying it is generated: a `color` group with one `color` token per colour key, hyphenated, whose value is an sRGB object with `components` rounded to four places, `alpha` when not 1, and a six-digit lower-case `hex`; a `semantic` group of alias tokens `surface.default`, `surface.muted`, `surface.overlay`, `text.default`, `text.muted`, `border.default`, `primary.default`, `status.danger`, `status.warning` and `status.success`; `font.family` as `fontFamily` lists split on the commas outside quotes, each name without its quotes and escapes; `font.size` and `font.weight` as `dimension` and `fontWeight`; `spacing.base` and one `spacing` step per scale entry, the base times the entry, with a `.` in the name written `-`; `radius`; and `shadow` as shadow objects, whose offsets and spread may be negative. Component values are rounded to four places; an alpha keeps its precision, and a spacing step is computed on the decimal digits of the base and the step, so `0.1rem` times 3 is `0.3 rem`. A length outside `px` and `rem`, or a colour or shadow this cannot read, such as one with a negative blur, has no token type the format states, so it is left out of the token file and kept only in the theme. | EX-0001-0312-01, EX-0001-0312-02 |
| BR-0026-0003 | The command writes `.qfai/catalog/theme.css`: one comment line saying it is generated, then one Tailwind 4 `@theme` block with, in token-file order, `--color-<key>` for each colour, `--color-<path>` holding `var(--color-<key>)` for each semantic alias whose name, `default` dropped, differs from its colour's, `--font-<family>`, `--text-<size>`, `--font-weight-<weight>`, `--spacing` for the base, `--radius-<key>`, `--shadow-<key>`, `--breakpoint-<name>`, `--container-<width>` and `--spacing-target-min`, each holding the value as `DESIGN.md` writes it. | EX-0001-0312-01, EX-0001-0312-03 |
| BR-0026-0004 | Every length-valued field, each type-scale size, `spacing.base`, radius, breakpoint and content width, must be one CSS length, `0` or a number with a length unit such as `px`, `rem`, `em`, `%` or `vw` in any case, or the parse fails. From the optional `visual.layout` of the shipped DESIGN.md specification, each `breakpoints` entry becomes a `layout.breakpoint.<key>` dimension token and each `content_max_width` entry a `layout.content-max-width.<key>` dimension token, and `target_min_px` becomes the `layout.target-min` dimension token in `px`; `table_narrow` describes behaviour no token type states, so neither file carries it. Every `DESIGN.md` value the theme writes into a CSS declaration (each colour, font family stack, type-scale size, `spacing.base`, radius, shadow, breakpoint and content width) fails the parse, naming its path, when it holds `;`, `{`, `}`, `/*` or `*/`, ends in a backslash, or leaves a parenthesis, bracket or quote open or closes one it did not open, and a `visual.typography.weight` outside 1 to 1000, the numeric font weights the 2025.10 format states, a theme-bound value holding a number too long to read as one or with more digits than a number states exactly, such as `9007199254740993`, a `visual.spacing.scale` step whose length, the base times the step, is too large to compute, a `visual.spacing.scale` step given twice, which would name two tokens alike, and a `visual.layout.target_min_px` too large to write without an exponent fail it too. `DESIGN.md` may also hold an optional `data_display` section with `locale`, `currency`, `number` and `date`, each a non-empty string with no surrounding whitespace, and any other key or value fails the parse; its values ride in `$extensions.dev.qfai` of the `data-display` group, with a `$description`. | EX-0001-0312-03, EX-0001-0312-04 |
| BR-0026-0005 | The same `DESIGN.md` front matter gives the same bytes in both files. The command prints one line naming both files and the number of tokens, and exits 0. A read or write failure exits 1. Both files are written to temporary files beside them and then renamed into place, so when an existing file cannot be read, the command writes nothing, and when either cannot be written, it removes the temporary files, puts back a file it already replaced, says so in one line and exits 1 with both files as they were. | EX-0001-0312-01 |
| BR-0026-0006 | With `--check` the command writes nothing. It exits 0 when both committed files hold the text it would write, CRLF line ends read as LF, and otherwise exits 1 with one line for each file that is missing or differs, naming it and saying it does not exist or is out of date, with the command to run. | EX-0001-0312-05 |
| BR-0026-0007 | When `DESIGN.md` is absent or its front matter does not parse, the command prints one line saying which, with the parse message, writes nothing, and exits 1, with or without `--check`. | EX-0001-0312-06 |
| BR-0026-0008 | The shipped implementation UI guidance names both files and `qfai catalog design`, tells the implementer to import the theme and use its variables instead of copying a value, and names `QFAI-DCAT-001` to `QFAI-DCAT-003`. The shipped DESIGN.md specification says what the command writes from `visual.layout` and lists the `data_display` section. | EX-0001-0312-10 |
