# 04 Business Rules

## Purpose

- Decompose AC into explicit business rules.
- Every BR must reference one or more AC IDs.

| BR-0006-0018 | Precedence resolution algorithm | AC-0006-0017, AC-0006-0018 | Mode resolution evaluates sources in strict order: (1) if CLI `--mode` flag is present and valid, use it (source=`cli-override`); (2) else if discussion artifact contains a valid `prototyping.recommended_mode`, use it (source=`discussion-recommendation`); (3) else use system default `standard` (source=`default`). | BR-0006-0019 | Missing discussion artifact behavior | AC-0006-0018 | When no discussion artifact is found or the artifact lacks a `prototyping.recommended_mode` field, the system emits an informational note (not an error) and falls back to system default `standard`. | BR-0006-0020 | Mode logging output structure | AC-0006-0019 | Every prototyping run must output a structured mode resolution log containing: `mode_source` (one of: `cli-override`, `discussion-recommendation`, `default`), `recommended_mode` (from discussion artifact or `null`), `effective_mode` (the mode actually executed), `rationale` (from discussion artifact, `"CLI override"`, or `"system default"`), and `evidence_expectations` (evidence levels the effective mode produces, e.g., `"L1/L2"` for low-cost). Static and non-visual runtime evidence is collected normally. | qfai_prototyping_mode_switch_ux_proposal.md §9 | - |
| BR-0006-0022 | Valid mode sources enumeration | AC-0006-0019 | The `mode_source` field in mode resolution output must be exactly one of: `cli-override`, `discussion-recommendation`, `default`.
