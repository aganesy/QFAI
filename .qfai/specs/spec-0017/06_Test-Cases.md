# 06 Test Cases

## Purpose

- Verify examples and acceptance criteria with explicit refs.
- Cover not only normal paths but also error paths, boundary values and edge cases.
- Every one of the 34 acceptance criteria carries at least one `normal` row **and** at least one
  `error` or `boundary` row. A criterion covered only by a happy path cannot falsify the
  requirement it belongs to, and every gate in this spec has a failure direction that is itself
  load-bearing.

## How `Level` was derived

Each row's `Level` is derived per
`.qfai/assistant/catalog/test-layers.md#layer-derivation-procedure-normative`: find the single
assertion whose removal would let a wrong implementation pass, restrict it to the parent business
rule's obligations, and read the layer off what that assertion observes. One oracle per row; a
multi-valued `Level` is illegal, and every row stays within L1-L3.

Applied to this spec the derivation lands in two places, and the `Falsifying oracle` column records
which one, per row:

- `unit` — the oracle observes the **return value of a rule or derivation applied to a value the
  test supplies**: a synthetic needs map, a synthetic change list, a fixture workflow document held
  as test data, or a module-level constant such as the declared rule-name list, the finding code or
  the built-in layer token set. No repository file is read for the assertion to mean anything.
- `integration` — the oracle observes **the repository's real tree or a subprocess**: the parsed
  content of a checked-in workflow, script, manifest or decision record; a guard's exit code and
  output over an on-disk tree; the result of the asset-to-root mirror synchronization and the
  tracked-tree diff. This is the majority here because this spec's subject **is** the repository's
  own file tree and the exit codes of the scripts that assert over it, which is the same reading
  `10_Plan.md` § `Test approach` records.

No row derives to L4 or L5: this spec declares no service boundary and no full-system journey, so
no obligation here is misfiled as a `TC-*` that a test directory could not carry.

This file spells the layer in the lowercase **word** form (`unit`, `integration`). That is the
spelling the layer-policy check on this file's `Level` column accepts, and the one the sibling
packs use; `tdd/test-list.md` uses the capitalized word form per the crosswalk. `unit` rows are TDD coverage
targets and each carries a `tdd/test-list.md` row; `integration` rows are not coverage targets and
discharge their obligation through the ATDD annotation gate.

## Level and Type vocabulary

Deliberately a list, not a table, so the Test Case Table below stays the **first** markdown table
in this file. `collectTestCaseIds` and the TDD coverage report both read
`parseFirstMarkdownTable`, so a table here would be parsed as the TC table, find no `TC-ID` column,
and silently disable `TDDLIST_TC_NOT_COVERED` for the whole spec. For the same reason the whole TC
set is one table and is never split into two.

`Level` values used here:

- `unit` — L1. The oracle observes inputs and return values only.
- `integration` — L3. The oracle observes real filesystem state or a subprocess result.

`Type` values used here:

- `normal` — happy path, the expected successful behaviour.
- `error` — error, failure or invalid-input path, including a planted violation.
- `boundary` — boundary value, or the just-outside-the-line case that fixes where the rule stops.

## Coverage summary

- 82 test cases against 34 acceptance criteria and 66 examples.
- Every acceptance criterion in `03_Acceptance-Criteria.md` is referenced by at least one row's
  `AC-Refs`, and every example in `05_Examples.md` by at least one row's `EX-Ref`.
- Type distribution: 37 `normal`, 17 `error`, 28 `boundary`. Every acceptance criterion carries at
  least one `normal` row and at least one `error` or `boundary` row.
- Level distribution: 11 `unit`, 71 `integration`. The skew is a property of the subject, not of
  the test design — a rule about what a checked-in workflow, script or manifest contains is only
  falsifiable against the real tree. The eleven `unit` rows are exactly the obligations whose
  oracle is a value the test supplies rather than a file it reads.

## What is deliberately not asserted by execution here

Two obligations are only partly observable today, and `07_Decisions.md` DR-0017-0002 records why.
The rows above assert what is observable now and no more:

- **The action-pin bump owner (AC-0017-0011).** The pin _form_ is fully machine-checked by
  TC-0017-0022 and TC-0017-0023. The _ownership_ half is an artifact-existence obligation:
  TC-0017-0025 reads the decision record, and TC-0017-0026 fixes the boundary that a bump owner
  stated only in a pull-request description does not satisfy it. No test asserts against a bump
  configuration, because no agent may create one at the repository root without the user (OC-3).
- **Build-artifact reuse (AC-0017-0014, AC-0017-0015).** Its observable is a bundler invocation
  count compared against a captured baseline, and that baseline does not exist yet. Both branches
  are accepting: TC-0017-0032 covers the reuse landing, and TC-0017-0034 covers a measured
  wall-clock regression with the rebuilds kept. What TC-0017-0033 and TC-0017-0035 falsify is the
  case the requirement really forbids — a change landing with **no** captured numbers at all.

Neither is dropped and neither is over-asserted into an oracle that cannot run. The bump-owner half
becomes machine-checkable the moment a user approves a bump configuration; the reuse half becomes
a measured comparison the moment the baseline is captured (`08_Open-questions.md`).

## Ownership boundary

No row asserts what a file under `packages/qfai/assets/init/root/.github/workflows/**` must
contain. Those files belong to `spec-0003`. The rows that name the shipped tree — TC-0017-0050,
TC-0017-0051, TC-0017-0052, TC-0017-0053 and TC-0017-0054 — assert the behaviour of **the lane
that scans it** under the shipped-file rules of `.qfai/contracts/cli/shipped-workflows.md` §6, and
introduce no finding code beyond the two that contract already declares.
