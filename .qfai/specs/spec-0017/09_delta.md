## Adopted

- AD-0017-0007: 4 evaluation axes are UX-centered: informationArchitecture / navigationFlow / usability / functionality
- AD-0017-0008: Layout anti-patterns lap-001..008 (with reviewer-judged lap-007 / lap-008) replace visual-aesthetic slop-* tokens
- AD-0017-0009: Convergence (exit 64) requires all 4 axes exceptional AND layoutAntiPatternsDetected empty AND designMdViolations empty
- AD-0017-0010: design-system.yaml is a deterministic mirror of DESIGN.md tokens (not extracted from final iter HTML)
- AD-0017-0011: pivotDirective rule: pivot ⇔ (3 consecutive low-IA AND latest has lap-*); continue ⇔ ≥2 axes improved; else refine
- AD-0017-0012: design-contract validators renumbered to DCON-030 (presence/structure), DCON-031 (lock hash integrity), DCON-032 (mirror correctness)

## Rejected

- RJ-0017-0003: brand-design.yaml schema strengthening
  - DO NOT reintroduce brand-design.yaml / exploration-brief.yaml / reference-pool.yaml as compliance gates
  - Temptation: "YAML is structured, easier for validators"
  - Reason: brand SSOT must be human-author-friendly (markdown). YAML schema increases maintenance load and breaks the user's editing experience. Hash-locked markdown gives equivalent fail-closed semantics.

- RJ-0017-0004: Six-axis evaluator (UX 4 + brand-compliance + craft)
  - DO NOT reintroduce subjective brand/craft axes alongside UX axes
  - Temptation: "more axes = richer feedback"
  - Reason: brand compliance is decided by `findDesignMdViolations` (deterministic gate), not by reviewer scoring. Doubling the gate creates noise and worsens central-tendency bias on the ordinal scale.

- RJ-0017-0005: LLM-judged designMdViolations
  - DO NOT delegate token compliance to LLM judgment
  - Temptation: "LLM can spot near-matches and stylistic similarity"
  - Reason: convergence gate (exit 64) must be deterministic. Token-level matching is mechanical; LLM judgment introduces flakiness in CI.
