# 02 Initiative

## Initiative

**QFAI** は、AI コーディングエージェント向けの品質第一開発キットである。`npx qfai init` でプロジェクトに導入し、仕様駆動開発（SDD）、受入テスト駆動開発（ATDD）、テスト駆動開発（TDD）の統合ワークフローをバリデーションゲートで強制する。50以上のルールでスペック→コントラクト→テストのトレーサビリティを検証し、CI/CD パイプラインに組み込める。

## Initiative overview

| Key                | Value                                                           |

| カテゴリ           | CLI ツール / 品質第一開発キット                                 |
| ターゲットユーザー | AI コーディングエージェント（Claude, GitHub Copilot, Codex 等） |

| ライセンス         | MIT                                                             |

## Assumptions

- 導入先は Node.js / npm エコシステム上のプロジェクトであり、`npx` が使える。
- 導入先の CI は GitHub Actions である。配布する workflow テンプレートはこの前提の上にある。
- スペック・コントラクト・テストはリポジトリ内にテキストとして存在する。外部の課題管理システムを SSOT とする運用は想定しない。
- AI エージェントは skill / agent 定義を読み込める。読み込めない環境では QFAI は CLI バリデータとしてのみ機能する。

## Dependencies

- Node.js / npm — 配布と実行の土台。`engines` の下限がサポート範囲を定める。
- GitHub Actions — 配布する CI ワークフローの実行主体。QFAI 自身は CI ランナーにならない。
- pnpm workspace — 本リポジトリのビルド構成。導入先には要求しない。
- Playwright (任意) — prototyping の Reviewer が UI を駆動する場合のみ。未導入でも他の機能は動作する。

### 前提 (Assumptions)

- 配布テンプレート提供の指示により `qfai init` が複数のワークフローファイルを書くことは承認済み（pack Assumption 1）。反証条件は「単一ファイル配布に戻す」指示。
- アダプタのパッケージマネージャと言語は不均一であり、いかなる配布テンプレートも pnpm / TypeScript を前提にできない（pack Assumption 2）。
- 必須ステータスチェックは集約ジョブではなく `build` である（DTC-28 で実測）。名前の保持だけでは不十分で、検証セットと無条件性の保持が同時に必要。

### 依存 (Dependencies)

- 順序依存: guard 隣接 lint ルールと asset test の co-change → 配布物の pin 変更。drift ゲート → 配布セット拡張。verdict hardening → job 追加。`REQ-0021` → `REQ-0025`。
- 未解決依存: `OQ-0021`（refresh 上書き方針）が `REQ-0022` の上書き半分を blocked にしている。`OQ-0022`（必須チェックの移設）が doc-only 実行インスタンス下限 4 → 3 を解放する。
- リポジトリ設定（branch protection / 必須チェック名）は人間操作であり、本イニシアティブのスコープ外。
