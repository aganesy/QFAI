# 06 Glossary

| Term                              | Meaning                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| discussion pack                   | `/qfai-discussion` が生成する upstream requirements/discovery artifact。`/qfai-sdd` の入力専用。                                                                                                                                                                                                                                                      |
| exploration-first                 | direction を discussion で固定せず、prototyping の探索・比較・収束で決める posture。                                                                                                                                                                                                                                                                  |
| UIUX sidecar                      | discussion pack 配下の `uiux/*.md` 群。design intent の authoring artifact であり downstream execution truth ではない。                                                                                                                                                                                                                               |
| exploration brief contract        | `.qfai/contracts/design/exploration-brief.yaml`。探索条件、must-keep interactions、brand signals の SSOT。                                                                                                                                                                                                                                            |
| evaluation rubric contract        | `.qfai/contracts/design/evaluation-rubric.yaml`。design quality / originality / craft / functionality 等の評価軸 SSOT。                                                                                                                                                                                                                               |
| evaluator calibration contract    | `.qfai/contracts/design/evaluator-calibration.yaml`。good critique / blandness fail / originality fail 例の SSOT。                                                                                                                                                                                                                                    |
| selected direction contract       | `.qfai/contracts/design/selected-direction.yaml`。winning direction と carry-forward rules の SSOT。                                                                                                                                                                                                                                                  |
| design-system contract            | `.qfai/contracts/design/design-system.yaml`。winner から抽出された downstream design-system checklist の SSOT。                                                                                                                                                                                                                                       |
| breakthrough evidence             | `.qfai/evidence/breakthrough.json`。plateau detector 判定、trigger reasons、branch 実行証跡の SSOT。                                                                                                                                                                                                                                                  |
| contract-first downstream         | `/qfai-sdd` 以降の skill / validate / verify が `specs + .qfai/contracts/**` を primary input とする posture。                                                                                                                                                                                                                                        |
| UI contract                       | `.qfai/contracts/ui/*.yaml`。declared screen / route / obligations の SSOT。                                                                                                                                                                                                                                                                          |
| direct discussion-pack validation | discussion pack root を明示的に入力して canonical UIX validators を回すこと。repo-root downstream validate と区別する。                                                                                                                                                                                                                               |
| best-of-history                   | 後続 iteration が常に最良とはみなさず、過去勝者を incumbent と比較し続ける運用。                                                                                                                                                                                                                                                                      |
| plateau detector                  | `allReviewerAxesPerfect100`, score delta, diff lines を使って breakthrough branch を機械判定で発火するロジック。                                                                                                                                                                                                                                      |
| mandatory UI evidence             | `.qfai/evidence/prototyping/screenshots/<screen-id>.png` と `.qfai/evidence/prototyping/html/<screen-id>.html`。declared screen ごとに両方必須。                                                                                                                                                                                                      |
| contract readiness                | design/ui contracts が downstream execution に必要な最小 schema を満たしている状態。                                                                                                                                                                                                                                                                  |
| historical layer                  | `07_Decisions.md`, `09_delta.md`, `_policies/08_Decisions.md`, `_policies/10_delta.md`。superseded wording を残せる層。                                                                                                                                                                                                                               |
| DESIGN.md                         | (UX-loop redesign / spec-0012) repo root の `DESIGN.md`。brand vision / visual identity (color / font / radius / shadow tokens) の SSOT。`/qfai-discussion` で著者され、`/qfai-sdd` Phase 0 で sha256 凍結される。                                                                                                                                    |
| designMdViolations                | (UX-loop redesign / spec-0012) iter HTML が `DESIGN.md` token から逸脱している箇所のリスト。`{category, expected, found, location}` の配列。`findDesignMdViolations(html, designMd)` (pure function) が出力。非空時は convergence (exit 64) を block する。                                                                                           |
| layoutAntiPatterns (lap-\*)       | (UX-loop redesign / spec-0012) UI 構造的 anti-pattern の集合 `{lap-001-orphan-page, lap-002-deadend-flow, lap-003-modal-stack-trap, lap-004-hidden-primary-action, lap-005-no-empty-state, lap-006-mystery-meat-icon, lap-007-state-not-represented, lap-008-no-back-affordance}`。検出時に informationArchitecture を `acceptable` 以下に cap する。 |
| informationArchitecture (axis)    | (UX-loop redesign / spec-0012) UX 評価軸の 1 つ。ordinal `{weak, acceptable, strong, exceptional}`。情報の階層・グルーピング・wayfinding がどれだけ user に明確かを評価する。lap-\* 検出時は `acceptable` cap。                                                                                                                                       |
| navigationFlow (axis)             | (UX-loop redesign / spec-0012) UX 評価軸の 1 つ。primary task の達成までの経路がどれだけ短く明示的かを評価する。                                                                                                                                                                                                                                      |
| usability (axis)                  | (UX-loop redesign / spec-0012) UX 評価軸の 1 つ。tap target / contrast / state visibility / error recovery の総合評価。                                                                                                                                                                                                                               |
| originality (axis) [DEPRECATED]   | (UX-loop redesign / spec-0012) 旧 4 軸の 1 つ。informationArchitecture に置換された。history-only。                                                                                                                                                                                                                                                   |
| designQuality (axis) [DEPRECATED] | (UX-loop redesign / spec-0012) 旧 4 軸の 1 つ。navigationFlow に置換された。history-only。                                                                                                                                                                                                                                                            |
| craft (axis) [DEPRECATED]         | (UX-loop redesign / spec-0012) 旧 4 軸の 1 つ。usability に置換された。history-only。                                                                                                                                                                                                                                                                 |
| slopPatternsDetected [DEPRECATED] | (UX-loop redesign / spec-0012) `iter-NN/review.json` の旧フィールド。`layoutAntiPatternsDetected` に置換された。history-only。                                                                                                                                                                                                                        |

### CHG-003 (Assistant-layer Recut + Work-log Surface, 2026-05-22)

| Term                      | Meaning                                                                                                                                                                                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| assistant-layer recut     | `.qfai/assistant/{instructions,steering,manifest}` の 3-directory split を 4 conceptual layer (Constitution / Manifest / Catalog / Steering) + Process partition に再分割する v1.9.0 の構造変更。                                                         |
| Constitution layer        | `.qfai/assistant/constitution/` — global invariants と always-loaded protocols (drift-protocol, communication, thinking, research-first-protocol, ui-definition-protocol, cli-ux-guidelines, test-layers 等)。                                            |
| Manifest layer            | `.qfai/assistant/manifest/` — per-project spine (Kiro 流: product / tech / structure / manifest)。always-loaded、プロジェクト側で fill する。                                                                                                             |
| Catalog layer             | `.qfai/assistant/catalog/` — controlled-vocabulary registries (`agent-catalog.yml`, `agent-routing.yml`, `review-profiles.yml`, `review-gate.rules.yml`, `change-classification.md`, `spec_required_files.json`)。validators / routing から loaded。      |
| Process partition         | `.qfai/assistant/process/` — pipeline / methodology / `migrations/`。stage skills が loaded。                                                                                                                                                             |
| Steering work-log         | `.qfai/steering/` (project-root、`.qfai/assistant/` 配下ではない) — AI 作業ログ surface。per-project、untracked by default、配布物外。entry は frontmatter-typed Markdown。                                                                               |
| work-log entry            | `.qfai/steering/<id>.md` の単一 Markdown ファイル。YAML frontmatter (id / status / kind / created / updated / scope / blocking / promote-to / links) + body。                                                                                             |
| kind (work-log)           | entry が表す出来事の種類。enum: `milestone` \| `decision` \| `risk` \| `consultation-needed` \| `unexpected` \| `unscoped-discovery` \| `handoff` \| `blocker` \| `scope-up` \| `scope-down` \| `spike`。`10_Policy.md` の write-trigger SSOT と 1-to-1。 |
| status (work-log)         | entry のライフサイクル。enum: `active` \| `handoff` \| `archived`。                                                                                                                                                                                       |
| scope (work-log)          | entry の適用範囲。`global` (project-wide) または `spec-NNNN` (per-spec)。                                                                                                                                                                                 |
| promote-to                | `kind: decision` entry を per-spec `07_Decisions.md` の特定 row に昇格させる宛先 path、または `null`。                                                                                                                                                    |
| promoted-to               | `status: archived` 時に promotion が完了したことを記録する back-reference field。                                                                                                                                                                         |
| drift-prevention contract | 全実装/レビュー skill が author 前に open work-log entry を読み、Reviewer Gate が出力との contradiction を `R-WORKLOG-DRIFT` で flag する契約 (REQ-0006)。                                                                                                |
| decision-promotion gate   | `kind: decision` + 非 null `promote-to` の entry を `qfai validate` が `W-PENDING-PROMOTION` で surface し続け、`07_Decisions.md` への row 追加 + entry archive の両条件で gate が閉じる仕組み (REQ-0007)。                                               |
| handoff brief             | `kind: handoff` entry body の 5 セクション構造 (State / Next action / Constraints / OQs / References)。Anthropic handoff pattern (SRC-0016W) に準拠。                                                                                                     |
| R-WORKLOG-DRIFT           | Reviewer Gate finding (severity error, advisory-failing): 新規 implementation 出力が open entry の direction と矛盾する。`justification:` 非空必須。                                                                                                      |
| R-REJECTED-READOPT        | Reviewer Gate finding (severity error, advisory-failing): 出力が active spec の `07_Decisions.md` で `Status: rejected` の option を再採用する。`justification:` 非空必須。                                                                               |
| R-HANDOFF-INCOMPLETE      | Reviewer Gate finding: `kind: handoff` entry body の 5 セクションの何れかが欠落。                                                                                                                                                                         |
| W-PENDING-PROMOTION       | `qfai validate` warning: `kind: decision` + 非 null `promote-to` の entry が promote されていない。                                                                                                                                                       |
| W-WORKLOG-SCHEMA          | `qfai validate` warning: entry frontmatter が schema に違反 (非 blocking)。                                                                                                                                                                               |
| W-WORKLOG-STALE           | `qfai validate` warning: `status: active` entry の `updated` が 90 日超。                                                                                                                                                                                 |
| W-WORKLOG-BROKEN-LINK     | `qfai validate` warning: `links` array の要素が既存 artifact に解決しない。                                                                                                                                                                               |
| D-DEPRECATED-PATH         | `qfai validate` finding: 旧 layout path への参照。deprecation window 中は warning、sunset version 以降は error。                                                                                                                                          |
| W-SKILL-DOC-BROKEN-REF    | `qfai validate` finding: `qfai-*` SKILL.md が現 layout に解決しない assistant path を参照。window 中は warning、sunset 以降は error。                                                                                                                     |
| W-USER-EDIT-PRESERVED     | `qfai init --upgrade-assistant-tree` 時に collision が発生し user-edited file が旧 path に preserve された旨を伝える warning。                                                                                                                            |
| E-WORKLOG-SECRET          | 既存 secret-pattern scan が work-log entry 内に secret 候補を検出した旨の error (hard-block)。                                                                                                                                                            |
| assistantPaths.ts         | `packages/qfai/src/core/paths/assistantPaths.ts` — 配布 assistant file の canonical relative-path を export する SSOT module。hard-coded path string literals は lint で reject される (NFR-0001)。                                                       |
| project_memory block      | `qfai-*` SKILL.md に含まれる YAML block。当該 skill が読む layer を列挙する。`qfai validate` は宣言外の path read を reject する (REQ-0010)。`constitution/` は implicitly always-loaded で列挙不要。                                                     |

### CHG-005 (qfai-prototyping defect remediation, 2026-05-24)

| Term                         | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-PROMPT-SCANNER-DRIFT       | Reviewer-Gate finding (severity error, advisory-failing per TC-71): emitted when the symmetric pair `qfai-prototyping/references/generator-prompt.md` ↔ `packages/qfai/src/core/validators/findDesignMdViolations.ts` is modified asymmetrically (one side gains a Tailwind utility, preflight literal, or `SAFE_LITERALS` entry that the other side does not mirror). `justification:` text MUST name (a) the modified file, (b) the counterpart lacking the matching change, and (c) the contract clause that remains unmatched. |
| R-CERTIFY-VERIFY-CIRCULAR    | Reviewer-Gate finding (severity error, advisory-failing per TC-71): emitted when `qfai prototyping certify` is observed reading a `verify.json` whose `profile` requires `/qfai-atdd` or `/qfai-implement` artifacts at the prototyping phase — i.e., the prototyping skill cannot complete itself because completion depends on an artifact a later phase must produce. Resolution path is `verify.json#scope` discriminator per OQ-0107=B (`scope: prototyping` reads only prototyping-phase obligations).                       |
| D-DEPRECATED-PROBE           | `qfai validate` / `qfai doctor` finding: code path probes a deprecated wrapper / binary name (e.g., legacy `playwright-cli` instead of `playwright`). Severity = `warning` during the one-minor deprecation window (qfai 1.9.x), `error` at sunset (qfai 1.10.0).                                                                                                                                                                                                                                                                  |
| D-DEPRECATED-PATH            | `qfai validate` finding (existing CHG-003 entry retained; CHG-005 extends coverage): legacy artifact path consumed (e.g., `.qfai/output/validate.json` vs new profile-suffixed `.qfai/report/validate-<profile>.json`). Same warning→error escalation as `D-DEPRECATED-PROBE`.                                                                                                                                                                                                                                                     |
| D-DEPRECATED-SCHEMA          | `qfai validate` finding: a JSON artifact (e.g., `prototyping.json`, `iterate-plan.json`) matches a legacy schema shape that the validator still tolerates inside the window. Severity = `warning` during window, `error` at sunset.                                                                                                                                                                                                                                                                                                |
| lap-009: duplicate-capture   | Layout anti-pattern: ≥2 captured screenshots (`screens[].id` distinct) share an identical PNG md5. Severity = error (OQ-0109 = advisory-failing). Implies the capture pipeline did not navigate between declared screens — typical signature of a single-page SPA where route enumeration is broken.                                                                                                                                                                                                                               |
| lap-010: missing-route       | Layout anti-pattern: an HTML SPA artifact lacks a reachable hashchange or path route resolving to a declared `screens[].id`. Severity = error (OQ-0109 = advisory-failing). Catches the "everything renders the home screen" failure mode reported by SRC-0001 / SRC-0003.                                                                                                                                                                                                                                                         |
| `--capture` / `--auto-serve` | `qfai prototyping iterate` opt-in flags that re-introduce capture infrastructure (screenshot + DOM source acquisition) and an auto-served local preview, respectively. Amend the prior decision (DR-0012-0029) that removed capture from the default path: capture is now opt-in rather than absent, with explicit user consent at the CLI surface (CHG-005).                                                                                                                                                                      |
| Capture Contract             | The per-screen block declared in `iterate-plan.json` when `--capture` is active: `{ viewport: {width,height}, deviceScaleFactor: number, waitUntil: "load" \| "domcontentloaded" \| "networkidle", htmlSourceCopy: "page.content" \| "rawSource" }`. Captures the previously-implicit acquisition parameters surfaced by SRC-0007 (capture method not specified) and SRC-0021 (`iterate-plan.json` lacks per-screen capture contract).                                                                                             |
| verify.json#scope            | Phase-gate scope discriminator in `.qfai/report/verify.json`: `"prototyping"` (only prototyping-phase obligations), `"atdd"` (only ATDD-phase obligations), `"full"` (all phases). Per OQ-0107=B resolution of the certify↔verify circular dependency: `certify` reads `verify.json#scope === "prototyping"` to gate self-completion without requiring `/qfai-atdd` or `/qfai-implement` artifacts.                                                                                                                                |
