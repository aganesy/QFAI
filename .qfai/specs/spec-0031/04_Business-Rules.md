# 04 Business Rules

## Purpose

- Decompose AC into explicit business rules.
- Every BR must reference one or more AC IDs.

## Rule Table (required)

| BR-ID        | Title                                        | AC-Refs                                                | Rule                                                                                                                                                                                            | Notes                           | NFR-Refs |
| ------------ | -------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | -------- |
| BR-0031-0001 | Premium mode is separate skill               | AC-0031-0001, AC-0031-0012                             | Premium prototyping is invoked exclusively via `/qfai-prototyping-full-harness`. It is never activated through flags, options, or configuration on the standard `/qfai-prototyping` path        | SD-0031-001 (DR-0077)           | NFR-0005 |
| BR-0031-0002 | Spec input validation before loop            | AC-0031-0001, AC-0031-0002                             | Premium mode must validate all required spec inputs before the iteration loop starts. Missing or invalid inputs produce a structured error and prevent loop initialization                      | REQ-0011                        |          |
| BR-0031-0003 | Planner/generator/evaluator decomposition    | AC-0031-0003, AC-0031-0004, AC-0031-0005               | Premium loop decomposes into three distinct phases: planner (strategy), generator (output), evaluator (scoring + decision). No phase may assume the responsibilities of another                 | REQ-0012                        |          |
| BR-0031-0004 | Planner produces structured strategy         | AC-0031-0003                                           | Planner output must contain approach, constraints, and iteration budget guidance as minimum fields. The strategy is the sole input contract to the generator                                    |                                 |          |
| BR-0031-0005 | Generator output is evaluator-scorable       | AC-0031-0004                                           | Generator output must conform to a structured schema that the evaluator can score. Free-form or unstructured output is not accepted                                                             |                                 |          |
| BR-0031-0006 | Evaluator produces tristate decision         | AC-0031-0005, AC-0031-0006, AC-0031-0007, AC-0031-0008 | Evaluator must produce exactly one of three decisions per iteration: accept (emit final), refine (feedback to generator), or pivot (replan via planner)                                         |                                 |          |
| BR-0031-0007 | Accept terminates loop and emits output      | AC-0031-0006                                           | An accept decision immediately terminates the iteration loop. The current output becomes the final output. Evidence and review generation follow                                                |                                 |          |
| BR-0031-0008 | Refine increments counter and re-generates   | AC-0031-0007                                           | A refine decision increments the iteration counter and passes evaluator feedback to the generator for the next iteration. The planner is not re-invoked on refine                               |                                 |          |
| BR-0031-0009 | Pivot increments counter and re-plans        | AC-0031-0008                                           | A pivot decision increments the iteration counter and re-invokes the planner with pivot context. The new strategy replaces the previous one for subsequent generator invocations                |                                 |          |
| BR-0031-0010 | Configurable iteration cap with default 15   | AC-0031-0009                                           | The iteration loop has a configurable maximum cap. The valid range is 5-15. The default value is 15. When the cap is reached without accept, the best output is emitted with cap-reached status | SD-0031-003 (DR-0073), REQ-0013 | NFR-0001 |
| BR-0031-0011 | Iteration cap value validation               | AC-0031-0009                                           | Configured max cap values outside the 5-15 range are rejected with a validation error before loop start. Values within range are accepted without warning                                       | REQ-0013                        | NFR-0001 |
| BR-0031-0012 | Evidence mandatory on every run              | AC-0031-0010                                           | Evidence artifacts (iteration history, scoring trace, decision log) must be generated for every premium run regardless of termination reason (accept or cap-reached)                            | REQ-0014                        |          |
| BR-0031-0013 | Review mandatory on every run                | AC-0031-0010                                           | Review summary for human reviewers must be generated for every premium run. The review includes final scoring, recommendation, and iteration summary                                            | REQ-0014                        |          |
| BR-0031-0014 | Weighted scoring with dimension independence | AC-0031-0005, AC-0031-0011                             | Evaluator uses weighted scoring across multiple dimensions. Each dimension is scored independently. The overall score is a weighted sum of dimension scores                                     | REQ-0015                        |          |
| BR-0031-0015 | Dimension floor enforcement                  | AC-0031-0011                                           | Each scoring dimension has a configurable floor value. If any dimension score falls below its floor, the evaluator cannot produce an accept decision regardless of the weighted total           | REQ-0015                        |          |
| BR-0031-0016 | Critique adapter fail-open in evaluator      | AC-0031-0005                                           | The evaluator incorporates critique adapter (spec-0029) results when available. Critique adapter failure does not block scoring; the evaluator continues with calibration-only scoring          | spec-0029 dependency            |          |
| BR-0031-0017 | Calibration pack applied in evaluator        | AC-0031-0005                                           | The evaluator applies calibration pack (spec-0030) baselines to normalize scoring. Calibration data is required; missing calibration is a pre-loop validation error                             | spec-0030 dependency            |          |
| BR-0031-0018 | Standard path isolation                      | AC-0031-0012                                           | Premium mode code paths must not be loaded or activated during standard `/qfai-prototyping` execution. Import isolation or lazy loading ensures zero overhead on the standard path              | NFR-0005                        | NFR-0005 |
| BR-0031-0019 | Cap-reached output is best-so-far            | AC-0031-0009                                           | When the iteration cap is reached, the evaluator selects the highest-scoring output across all iterations as the final output. The selection is based on weighted total score                   |                                 |          |
| BR-0031-0020 | No partial artifacts on pre-loop failure     | AC-0031-0002                                           | If pre-loop validation fails (missing inputs, invalid cap, missing calibration), no partial artifacts (evidence, review, output) are generated. Only the structured error is returned           |                                 |          |
