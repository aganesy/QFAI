# 03 Acceptance Criteria

## Purpose

- Keep acceptance scenarios in this file.
- Gherkin belongs here, not in Business Flow.

## AC Gherkin (required)

```gherkin
# AC-0033-0001: Handoff artifact written on session interruption
Scenario: Handoff artifact generated on interruption
  Given a QFAI session in progress at iteration N
  When the session is interrupted (signal, timeout, or explicit stop)
  Then a handoff artifact is written to the configured output path
  And the artifact contains planner, generator, and evaluator state at iteration N

# AC-0033-0002: Resume picks up from interruption point
Scenario: Session resumes from handoff artifact
  Given a valid handoff artifact from a previous session interrupted at iteration N
  When a new session is started with the handoff artifact as input
  Then the session resumes from iteration N
  And planner, generator, and evaluator state match the artifact contents

# AC-0033-0003: Corrupted handoff detected; starts fresh with error log
Scenario: Corrupted handoff triggers fresh start
  Given a handoff artifact with corrupted or invalid JSON content
  When a new session attempts to resume from the artifact
  Then the system detects the corruption
  And logs an error with the corruption reason
  And starts a fresh session instead of resuming

# AC-0033-0004: Minimal handoff at iteration 1
Scenario: Handoff artifact at iteration 1
  Given a QFAI session at iteration 1 with minimal state
  When the session is interrupted
  Then a valid handoff artifact is generated
  And the artifact is resumable even with minimal accumulated state

# AC-0033-0005: Handoff artifact portable (no user lock)
Scenario: Handoff artifact usable by different user
  Given a handoff artifact generated by user A
  When user B attempts to resume from the artifact
  Then the session resumes successfully
  And no user-specific information prevents resumption

# AC-0033-0006: Handoff captures planner/generator/evaluator state
Scenario: All three engine states captured in handoff
  Given a QFAI session with active planner, generator, and evaluator state
  When a handoff artifact is generated
  Then the artifact contains serialized planner state (plan, iteration, goals)
  And the artifact contains serialized generator state (outputs, context)
  And the artifact contains serialized evaluator state (scores, findings)

# AC-0033-0007: Display-only output flagged by evaluator
Scenario: Display-only implementation detected
  Given a generated output that contains only UI rendering logic
  And no functional business logic or data processing
  When the evaluator analyzes the output
  Then the evaluator flags the output as "display-only"
  And the finding includes the detection confidence and evidence

# AC-0033-0008: Stub-only output flagged and triggers refine
Scenario: Stub-only implementation triggers refine loop
  Given a generated output where all functions are stubs
  When the evaluator analyzes the output
  Then the evaluator flags the output as "stub-only"
  And the refine loop is triggered to request a real implementation

# AC-0033-0009: Partial stub (90% real, one stub method) detected with location
Scenario: Partial stub detected with precise location
  Given a generated output with 90% real implementation
  And one method containing a stub (e.g., `throw new Error('not implemented')`)
  When the evaluator analyzes the output
  Then the evaluator flags the output as "partial-stub"
  And the finding includes the method name and approximate location of the stub

# AC-0033-0010: Detection runs consistently (idempotent)
Scenario: Detection produces consistent results on repeated runs
  Given a generated output with known stub and display-only sections
  When the evaluator runs detection twice on the same output
  Then both runs produce identical findings
  And no side effects alter the output between runs

# AC-0033-0011: Handoff artifacts strip credentials (POL-003)
Scenario: Credentials stripped from handoff artifact
  Given a QFAI session with environment variables containing API keys and tokens
  When a handoff artifact is generated
  Then the artifact does not contain any credential values
  And credential placeholders or redaction markers are present where credentials were referenced
```
