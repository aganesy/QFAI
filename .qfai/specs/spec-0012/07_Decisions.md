## DEC-0012-0001: 両エージェントを単一ケイパビリティ（CAP-0012）でまとめる

| 項目     | 内容                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| ID       | DEC-0012-0001                                                                               |
| 決定日   | 2026-03-15                                                                             |
| 決定者   | QFAI メンテナー（discussion-20260315033313220 にて合意）                                |
| 決定内容 | devils-advocate と pattern-doubler の 2 エージェントを別々のケイパビリティ（CAP）に分割せず、CAP-0012 単一ケイパビリティとしてまとめる。 |
| 根拠     | 両エージェントは「レビューフローへの新規エージェント追加」という同一目的を持つ。デプロイ・管理・トレーサビリティが単一 CAP の方が効率的。個別 CAP への分割は不要な管理オーバーヘッドを生む。 |
| 代替案   | CAP-0012a（devils-advocate 専用）+ CAP-0012b（pattern-doubler 専用）への分割           |
| 棄却理由 | 管理オーバーヘッドが増加し、スコープが小さい（設定ファイル追加のみ）ため不要と判断。    |
| 影響     | spec-0012 が両エージェントを統一管理する。トレーサビリティは US/AC/BR の粒度で分離済み。 |

## DEC-0012-0002: 実行順序を既存 10 レビュアーの後に固定する

| 項目     | 内容                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| ID       | DEC-0012-0002                                                                               |
| 決定日   | 2026-03-15                                                                             |
| 決定者   | QFAI メンテナー（discussion-20260315033313220 にて合意）                                |
| 決定内容 | devils-advocate（11 番目）と pattern-doubler（12 番目）は既存 10 レビュアーの後に配置する。既存 10 レビュアーとの順序入れ替えは禁止する。 |
| 根拠     | 既存 10 レビュアーによる基本品質チェックが先行することで、全否定エージェントが「十分にレビュー済みの成果物」を否定対象とできる。パターン倍増は最後に実行することで最終形の成果物に対して倍増を適用できる。 |
| 代替案   | 全否定エージェントを最初（1 番目）に配置する案。パターン倍増を途中（6 番目）に配置する案。 |
| 棄却理由 | 最初配置案は基本品質チェック前に全否定が起動し、修正サイクルが増加するリスクがある。途中配置案は倍増後のパターンに既存レビュアーが再チェックできなくなる。 |
| 影響     | BR-0012-0002（実行順序ルール）および AC-0012-0001, AC-0012-0002, AC-0012-0011 の前提条件となる。            |
