# 01 Objective

## Objective

AI コーディングエージェントが生成するコードの品質を担保するための「品質第一開発キット（CLI ツール）」を提供する。

## Background

AI コーディングエージェントは高速にコードを生成できるが、要件の誤解・仕様からのドリフト・ハルシネーションによる品質低下が課題となっている。QFAI は SDD（仕様駆動開発）、ATDD（受入テスト駆動開発）、TDD（テスト駆動開発）を統合し、客観的なバリデーションゲートで品質を保証する。

## Success criteria

提供価値を、観測可能な成果とその測り方の対で述べる。測り方の列が空の行は
達成判定ができないため、行として成立しない。

| ID     | Criterion                                                              | How it is measured                                                                             |
| ------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| OBJ-01 | ハルシネーション検出: スペックとコードの乖離を自動検知                 | `qfai validate` が spec とコードの不一致を finding として emit し、`--fail-on error` で exit 1 |
| OBJ-02 | トレーサビリティ: 要件からテストまでの完全追跡                         | REQ → Spec → Code → Test の各リンクが validate の traceability gate を通過する                 |
| OBJ-03 | CI/CD 統合: GitHub Actions アノテーション形式出力による自動化          | 配布 workflow が adopter の CI で実行され、finding が annotation として表示される              |
| OBJ-04 | マルチツール対応: Claude Code, GitHub Copilot, Codex, Anthropic Agents | `qfai init` が各ツールの統合ディレクトリを生成し、skill/agent の integrity check が通る        |

## Stakeholders

| Role                  | Interest                                   | Impact |
| --------------------- | ------------------------------------------ | ------ |
| AI エージェント開発者 | エージェントに QFAI ワークフローを組み込む | High   |
| QA エンジニア         | バリデーションゲートで品質を保証           | High   |
| プロジェクトリード    | 仕様の一元管理とトレーサビリティ           | High   |
| CI/CD エンジニア      | パイプラインへのバリデーション統合         | Medium |
| OSS コントリビュータ  | フレームワーク改善・拡張                   | Medium |

## Scope

| In Scope                                    | Out of Scope                            |
| ------------------------------------------- | --------------------------------------- |
| CLI バリデーション・レポート                | IDE プラグイン / GUI                    |
| スペック構造検証                            | コード品質分析（lint/静的解析の代替）   |
| コントラクト定義検証                        | コントラクト自体の自動生成              |
| テストファイルアノテーション検証            | テスト自体の自動生成                    |
| ディスカッションパック構造検証              | 自然言語の意味的正確性の判定            |
| UI フィデリティ自動検証（DOM クローリング） | ビジュアルリグレッションテスト          |
| マルチツールラッパー生成                    | AI エージェント自体のホスティング       |
| ウェイバーシステム                          | ワークフロー自動実行（CI ランナー機能） |

- 注記（`CAP-0017` と Out of Scope の境界 / CHG-007）: 「ワークフロー自動実行（CI ランナー機能）」は引き続き Out of Scope である。QFAI は CI ランナーとしてワークフローを**実行**しない。
- `CAP-0017` が所有するのは QFAI リポジトリ**自身**の CI 設定（`.github/workflows/**`、リポジトリ品質ゲート script、テストランナー構成）であり、配布物ではない。
- `CAP-0003` (`qfai init`) が配布するのはワークフロー**テンプレート**であり、実行主体は常にアダプタ側の GitHub Actions である。
- したがってどちらも QFAI を CI 実行エンジンにしない。上表の Out of Scope セルは変更しない。
