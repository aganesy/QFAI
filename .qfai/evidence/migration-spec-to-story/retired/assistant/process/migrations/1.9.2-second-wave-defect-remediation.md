# Second-Wave Defect Remediation Migration Memo

> Pinned to `packages/qfai/package.json#version` = 1.9.2.
> Sunset boundary: qfai 1.10.0.
> Source discussion pack: `.qfai/discussion/discussion-20260527075558258/` (REQ-0150..REQ-0173).
> Cross-spec policy decision: `_policies/10_delta.md` CHG-006.
> Touched specs: spec-0004 / spec-0006 / spec-0008 / spec-0010 / spec-0012 / spec-0013 / spec-0014 / spec-0015.

## Purpose

- Document the second wave of structural defects in the QFAI skill / CLI surface that downstream installs of qfai@1.9.1 had to work around by hand-authoring orchestrator scripts, hand-skeletoning screens, hand-patching frontmatter, and re-confirming session inputs each run.
- Pin the old -> new mapping per capability so downstream projects on qfai@1.9.1 can plan their upgrade path during the one-minor deprecation window (qfai 1.9.x) and complete it before the sunset version (qfai 1.10.0).
- Preserve the migration record as an immutable citation target. Substantive corrections after merge MUST be authored as a follow-up memo, not in-place edits.

## Trigger

Downstream reporter projects on qfai@1.9.1 documented that, after the first-wave prototyping remediation shipped, a second class of friction remained: post-convergence screen-coverage gaps required hand-skeletoning of non-primary screens; any byte edit to the brand `DESIGN.md` invalidated all prior cycle evidence; there was no discoverable "active discussion session" across many candidate dirs; stale review packs accumulated and tripped review-profile checks; cross-skill state had no canonical handoff schema; per-skill runtime dependencies had no declared manifest; and 3-6 avoidable confirmation prompts per session eroded the autopilot benefit. This pack closes each as a backwards-compatible change with a one-minor deprecation window.

## Rule Changes (old -> new per capability)

### 1. Cycle-0 screen-coverage skeletons (spec-0012)

- Old: After convergence, non-primary screens in the declared screen union frequently lacked evidence of both kinds; operators hand-authored placeholder HTML for 6+ screens per project.
- New: `qfai prototyping iterate --cycle 0 --emit-skeletons` (opt-in) emits one token-driven placeholder HTML per declared screen, consuming the brand-token styling from the root `DESIGN.md`. After convergence every declared screen has evidence of both kinds (`screenshot`, `html`) without hand-skeletoning. The opt-in flag means the unflagged default behavior is unchanged. A `--skeleton-mode full|placeholder|stub` flag lets a project tune cycle-0 fidelity per run; the default is `placeholder`.

### 2. DESIGN.md patch zone (spec-0012)

- Old: The brand `DESIGN.md` was sha-locked at Phase 0; any later byte edit (typography line-height, accent color) invalidated all prior cycle evidence and forced full reruns for minor adjustments.
- New: `DESIGN.md` gains a front-matter `patch_zone:` block listing the line ranges or token names that may be edited. In-zone edits update only a `patchHash` field; the `majorHash` stays stable and prototyping evidence remains valid. Out-of-zone edits (or removing the block) invalidate evidence as before. Reviewer Gate emits `R-DESIGN-MD-PATCH-OUT-OF-ZONE` (severity warning) on out-of-zone edits.

### 3. Prototyping mode discriminator (spec-0012)

- Old: There was a single (convergence) prototyping behavior; shallow multi-spec exploration could not be run without forcing convergence gates that were the wrong tool for the job.
- New: `qfai.config.yaml#prototyping.mode` and `qfai prototyping iterate --mode <convergence|exploration>` are both supported; `--mode` overrides config; default is `convergence` (backwards-compatible). Under `exploration`, the axes-exceptional gate and the design-compliance error downgrade to warning, while structural and license gates stay hard error. `qfai prototyping certify` rejects sealing any iteration produced under exploration mode (Reviewer Gate `R-EXPLORATION-CERTIFY-ATTEMPT`), so the mode cannot become a back-door to a DONE claim. The per-iteration mode is recorded; the accepted iteration index references a convergence iteration only.

### 4. Stale review-pack archival and doctor autoremediate (spec-0006)

- Old: Stale `.qfai/review/<old>/` packs accumulated and tripped review-profile checks; operators hand-archived them. There was no one-shot remediation surface.
- New: `qfai doctor --clean` moves review directories older than a configurable TTL (default 14 days, `qfai.config.yaml#review.staleTtlDays`) to `.qfai/review/_archive/<ts>/`; archival never deletes and restore is a manual move. `qfai validate --profile review` treats `_archive/` as out-of-scope. `qfai doctor --autoremediate` additionally installs declared per-skill runtime dependencies, runs the TTL archive, and writes any default-keyed config fields missing from `qfai.config.yaml`. Interactive confirm is required by default; `--yes` skips it; `--dry-run` previews. CI environments default to autoremediate off and emit a clear "autoremediate disabled in CI" line.

### 5. Workshop mock href form (spec-0010)

- Old: The mock href validator and the discussion template disagreed about acceptable href forms; authors repeatedly rewrote same-origin absolute hrefs to anchor form by hand.
- New: The discussion template emits anchor-form hrefs (`#name`) by default and the skill body instructs authors accordingly. The validator continues to PASS anchor and external (`http(s)://...`) URLs and continues to reject same-origin absolute paths; it is not broadened. The template and validator are a new locked SSOT-sync pair; asymmetric edits emit `R-MOCK-HREF-DRIFT`.

### 6. Active discussion session pointer (spec-0010 writer / spec-0013 reader)

- Old: There was no discoverable active discussion session across many candidate dirs; operators and downstream skills inspected timestamps to guess the current pack.
- New: `.qfai/state.json#discussion.currentId` is the single source of truth for the active session; `qfai discussion list --active` prints it as a read view. Downstream skills read the pointer through one helper. Multiple-active ambiguity is rejected with a clear error naming the candidates and the recovery command.

### 7. ATDD scaffold bulk skeletons (spec-0008)

- Old: There was no bulk test-skeleton generator; operators hand-authored one test file per declared test case.
- New: `qfai atdd scaffold --spec <spec>` reads the spec test cases and emits one test skeleton per case (framework-appropriate path) with a TODO marker, test-framework imports, and comment references to related user stories and API contracts. `qfai validate` emits `D-SCAFFOLD-PLACEHOLDER` (severity warning) until the TODO is removed; the warning escalates to error after 3 validate cycles (configurable via `qfai.config.yaml#atdd.scaffoldEscalateCycles`). Re-running never overwrites existing non-TODO content (idempotent).

### 8. Per-skill runtime dependency manifest (spec-0006 probe / cross-skill)

- Old: Skills had no declared runtime dependencies; doctor could not tell a project which packages a skill needed installed.
- New: Every skill ships a `manifest.json` declaring `runtimeDependencies` (npm package name + semver range). `qfai doctor --profile <skill>` reads the manifest and probes for each declared dependency, reporting any missing one with its install command. An empty list emits no probe. Layer-1 lint rejects malformed manifests. The manifest and the doctor probe are a locked SSOT-sync pair; drift emits `R-SKILL-MANIFEST-DRIFT`.

### 9. SKILL.md Default Autopilot Policy (spec-0015)

- Old: There was no declared policy for which decisions an agent may make autonomously, producing 3-6 avoidable confirmation prompts per session.
- New: Every SKILL.md carries a `## Default Autopilot Policy` section with three buckets: auto-decide (formatting, ID/sequence numbering, append-vs-create on subject overlap, picking among demonstrably-equivalent options), ask-user (approval-required structural operations, destructive operations, version-pin changes, scope expansions), and hard-required (company name, brand intent, primary spec id when absent). The skill body references the section as its source of truth. Reviewer Gate emits `R-AUTOPILOT-POLICY-MISSING` (severity error) when the section is absent.

### 10. Cross-skill handoff schema and audit log (spec-0015)

- Old: Cross-skill state was carried in ad-hoc files (e.g. a prototype-handoff file) with no canonical schema; envelope-deviation confirmations left no audit trail.
- New: A canonical handoff schema lives in `packages/qfai/src/core/schemas/handoff.ts` (documented in `references/handoff.md`) with a required minimum field set and an open shape for per-skill extensions. Every producing/consuming skill reads and writes this schema. Legacy ad-hoc handoff files are accepted during the deprecation window with `D-HANDOFF-LEGACY-FORMAT` warning. Reviewer Gate emits `R-HANDOFF-SCHEMA-DRIFT` on a non-conforming write. Separately, when an `AskUserQuestion` names an envelope-deviation context (skill envelope / architectural decision / rejected-option re-adoption / scope expansion), the skill body writes a decision record under `.qfai/evidence/decisions/` (git-ignored by default); `qfai audit log` lists records with scope / operator / clause filters and a table or JSON output.

### 11. Evidence-mutation audit log (spec-0012)

- Old: Destructive mutations to per-iteration evidence (delete / overwrite) left no forensic trail; lost evidence could not be reconstructed.
- New: `iterate` and `certify` append a JSON-Lines record (`{ ts, caller, path, action, priorSize, newSize }`) to `.qfai/evidence/prototyping/mutation-log.jsonl` for every destructive mutation under a per-iteration directory; `iterate --cycle 0 --force` logs each moved file. The log is git-ignored by default. Reviewer Gate emits `R-EVIDENCE-MUTATION-UNLOGGED` when a PR introduces a code path that mutates per-iteration evidence without a mutation-log call.

### 12. surface_type auto-population (spec-0013)

- Old: Specs with a UI contract companion needed `surface_type: ui-bearing` frontmatter added by hand across many specs per project.
- New: `/qfai-sdd` adds a step that sets `surface_type: ui-bearing` for every spec that has a UI contract companion. The SDD lint emits `D-SURFACE-TYPE-MISSING` (warning during the window, error at sunset) when a spec has a UI contract but lacks the frontmatter. The downstream resolver continues to require the frontmatter as the strict signal, so no downstream behavior changes.

### 13. Primary-tasks count band and shape (spec-0013 / spec-0004)

- Old: The primary-tasks audit warning was opaque about what count it considered "too many", and only string-only task items were accepted.
- New: The recommended primary-tasks count band (3..7) is documented in the UI contract template comments and the UI contract guide, and the audit warning names the band. The audit profile accepts both the existing string-only items and a structured `{ id, label, acceptance }` form (all required, closed shape) during the deprecation window; string-only items continue to PASS.

### 14. SaaS-package lightweight verify profile (spec-0014 / spec-0004)

- Old: There was no lightweight delivery mode for SaaS-tenant projects that ship a prototype plus a design-system attestation without the full implement-class gates.
- New: `qfai validate --profile saas-package` PASSes when the prototyping-profile validate PASSes, a design-system attestation is present at `.qfai/contracts/design/design-system.yaml`, and the cross-skill handoff schema PASSes. ATDD and implement-class gates are SKIPPED with `D-SAAS-PACKAGE-VERIFY-SKIPPED` (severity info) findings naming what was skipped. `qfai prototyping certify --scope saas-package` seals the completion certificate with `scope: "saas-package"` and a `notes:` field naming what was skipped; the certificate does not claim full DONE.

### 15. New Reviewer-Gate finding codes and pack-location CI lane (spec-0015 / spec-0004 / `_policies`)

- Old: The new behaviors above had no enforcement codes, and review/discussion pack misplacement was a textual rule only.
- New: Eight new Reviewer-Gate finding codes (all severity error with mandatory non-empty justification) enforce the autopilot policy, handoff schema, mutation log, patch zone, pack location, skill manifest, exploration certify, and mock href rules. A new pack-location CI lane lints staged/changed directories for review or discussion packs outside the allowed roots (`tmp/`, `.qfai/review/<ts>/`, `.qfai/discussion/<ts>/`) and rejects misplaced packs with a finding that proposes the correct path.

### 16. Documentation realignment (`_policies`)

- Old: Reference docs and SKILL.md bodies could drift from the implementation chosen for the behaviors above.
- New: `references/iteration-loop.md`, `references/generator-prompt.md`, `references/handoff.md`, `references/evidence-requirements.md`, and each skill's SKILL.md are rewritten to match the implementation, landing in the same atomic PRs as the implementation. `qfai validate --report` verifies zero remaining stale references at HEAD after sunset (warnings during the window).

## Deprecation Window

- Window opens: qfai 1.9.2 (this memo's pinned version).
- Window scope: one minor release. All deprecation findings emit at severity warning for the duration.
- Sunset: qfai 1.10.0. From that release onward, the same finding codes emit at severity error. Legacy code paths supporting the old forms MAY be removed after sunset.
- Specific window applications: legacy ad-hoc handoff files, pre-mutation-log iterate emit, `surface_type`-absent specs, string-only primary-tasks items. The opt-in cycle-0 skeleton flag is additive — the unflagged default behavior is unchanged.
- Downstream consumers MUST upgrade past qfai 1.9.x without crossing the 1.10.0 boundary unprepared.

## Recovery Instructions for Downstream on qfai@1.9.1

No action is strictly required during the qfai 1.9.x window — old artifact shapes continue to load with deprecation warnings. To migrate cleanly before the qfai 1.10.0 sunset:

1. **Adopt the canonical handoff schema.** Replace any ad-hoc handoff file with the canonical `handoff.yaml` shape; `qfai handoff upgrade <legacy-file>` will convert one for you and preserve original fields under a `legacy:` block. Resolve any `D-HANDOFF-LEGACY-FORMAT` warning.
2. **Add per-skill manifests.** Ensure each skill directory has a `manifest.json` declaring its runtime dependencies. Run `qfai doctor --profile <skill>` (or `qfai doctor --autoremediate`) to install anything missing.
3. **Set surface_type frontmatter.** For every spec with a UI contract companion, set `surface_type: ui-bearing`. Resolve any `D-SURFACE-TYPE-MISSING` warning before sunset.
4. **Migrate primary-tasks items if you want structured form.** String-only items keep working; adopt the `{ id, label, acceptance }` form where downstream tooling needs it.
5. **Archive stale review packs.** Run `qfai doctor --clean` (or `qfai doctor --autoremediate`) to move review directories older than the TTL into `.qfai/review/_archive/`; nothing is deleted.
6. **Set the active discussion pointer.** Record the active pack via the state pointer (or `qfai discussion use <id>`) so downstream skills stop guessing from timestamps.
7. **Add the autopilot policy section.** Ensure each SKILL.md carries a `## Default Autopilot Policy` section; resolve any `R-AUTOPILOT-POLICY-MISSING` finding.
8. **Realign documentation references.** Run `qfai validate --report` and resolve any stale-reference warnings before the sunset release.

## Legacy Compatibility

- All legacy artifact shapes (ad-hoc handoff files, `surface_type`-absent specs, string-only primary-tasks items, pre-mutation-log iterate emit) remain loadable during qfai 1.9.x.
- The matching deprecation finding identifies what to migrate before sunset.
- The new Reviewer-Gate drift findings are advisory-failing from this release (no legacy-mode exemption) because they catch active drift rather than historical shape.
