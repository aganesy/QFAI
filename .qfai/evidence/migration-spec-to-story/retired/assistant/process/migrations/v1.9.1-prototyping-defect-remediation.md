# qfai-prototyping Defect Remediation Migration Memo

> Pinned to `packages/qfai/package.json#version` = 1.9.1.
> Sunset boundary: qfai 1.10.0.
> Source discussion pack: `.qfai/discussion/discussion-20260523221141355/` (`04_Sources.md` SRC-0001..0004; `06_REQ.md` REQ-0101..0130).
> Cross-spec policy decision: `_policies/10_delta.md` CHG-005.
> Touched specs: spec-0004 / spec-0006 / spec-0012 / spec-0013 / spec-0015.

## Purpose

- Document the structural defects in `qfai-prototyping` that four independent downstream installs of qfai@1.8.10 (SRC-0001 BtoB商社コーポレートサイト / SRC-0002 HealthGarden B2B greenfield / SRC-0003 発注ナビ EC / SRC-0004 Windows 11 環境一般) had to work around by hand-authoring orchestrator scripts.
- Pin the old → new mapping per capability so downstream projects on qfai@1.8.10 can plan their upgrade path during the one-minor deprecation window (qfai 1.9.x) and complete it before the sunset version (qfai 1.10.0).
- Preserve the migration record as an immutable citation target per `_policies/07_Constraints.md` OC-61. Substantive corrections after merge MUST be authored as a follow-up memo, not in-place edits.

## Trigger

Four independent reporter projects each shipped a feedback report on qfai@1.8.10 documenting that the prototyping skill could not complete a usable prototype without hand-authored orchestrator scripts. Cross-reporter consensus identified five Category-A structural defects (each cited by ≥2 reports):

| Defect class                                              | Evidence                                                       | Reports                     |
| --------------------------------------------------------- | -------------------------------------------------------------- | --------------------------- |
| Tailwind / `findDesignMdViolations` static-gate incompat. | Preflight injects literal RGB; scanner has no body-scope rule. | 3 of 4 (SRC-0001/0002/0003) |
| `countWords` splits on `\s+` — CJK collapses to 1 word.   | `prose` critiques pass trivially for Japanese/Chinese copy.    | 2 of 4 (SRC-0001/0002)      |
| `playwright-cli` probe targets a deprecated package.      | Modern Playwright installs `node_modules/.bin/playwright`.     | 3 of 4 (SRC-0002/0003/0004) |
| `prototyping.json` schema drift vs validator profile.     | `iterate` writes a shape `validate` rejects.                   | 2 of 4 (SRC-0001/0002)      |
| `certify` ↔ `verify` circular self-completion dependency. | `certify` reads `verify.json#status === "PASS"`.               | 4 of 4 (SRC-0001..0004)     |

See `discussion-20260523221141355/04_Sources.md` Reference Research Summary for the full consensus / open-question list.

## Rule Changes (old → new per capability)

### 1. Tailwind contract (REQ-0102, spec-0012)

- Old: `findDesignMdViolations.ts` scanned the entire HTML body for literal color/font/radius/shadow values and flagged Tailwind Preflight RGB injections as DESIGN.md violations.
- New: Preflight literal values are in the `SAFE_LITERALS` allowlist; the scanner's body-scope rule excludes `<style>` reset blocks. The symmetric pair (`generator-prompt.md` ↔ `findDesignMdViolations.ts`) is locked by Reviewer-Gate finding `R-PROMPT-SCANNER-DRIFT` — modifying one side without the matching update to the other emits a severity-error advisory-failing finding with `justification:` required text naming (a) the modified file, (b) the counterpart lacking modification, and (c) the contract clause unmatched.

### 2. CJK `proseCritique` (REQ-0105, spec-0012)

- Old: `countWords(value) { const trimmed = value.trim(); return trimmed.length === 0 ? 0 : trimmed.split(/\s+/u).length; }` returns 1 for any whitespace-free CJK paragraph.
- New: `Intl.Segmenter` with `granularity: "word"` is the primary segmenter (ICU-backed; cited from SRC-0003W). If the runtime lacks `Intl.Segmenter`, an OR-condition fallback using `\p{Script=Han|Hiragana|Katakana|Hangul}` Unicode property escapes (SRC-0007W) reaches the same threshold. Per-rule configurable threshold remains supported.

### 3. Playwright probe (REQ-0103, spec-0006)

- Old: `qfai doctor` `PROJECT_WRAPPER_CANDIDATES = ["playwright-cli", "playwright-cli.cmd", "playwright-cli.bat"]`; `browserTool` accepted only `"playwright-cli"`; `skills.integrity` failure was severity error.
- New: `playwright` is the primary wrapper name; legacy `playwright-cli` is accepted-with-warn through qfai 1.9.x and rejected at qfai 1.10.0. Finding code `D-DEPRECATED-PROBE` carries the deprecation. `skills.integrity` defaults to severity warning (downstream installs reported integrity failures from cosmetic skill-file edits — error severity caused false-positive blockages).

### 4. Capture (REQ-0107..0109, spec-0012)

- Old: Capture infrastructure was absent from the default `iterate` path (per the earlier removal rationale DR-0012-0029); downstream projects hand-authored capture scripts in `tmp/`.
- New: `iterate` gains opt-in flags `--capture` and `--auto-serve` that re-introduce capture infrastructure with explicit user consent. The `iterate-plan.json` Capture Contract block per declared screen is `{ viewport: {width,height}, deviceScaleFactor: number, waitUntil: "load" | "domcontentloaded" | "networkidle", htmlSourceCopy: "page.content" | "rawSource" }`. The earlier no-capture default remains the unflagged behavior — the flags are additive, not a default change.

### 5. `prototyping.json` schema (REQ-0111, spec-0012)

- Old: `iterate.ts` emitted `prototyping.json` with implicit / loose fields that the prototyping-profile validator (`QFAI-PROT-002/005/007/009`) rejected.
- New: `prototyping.json` schema is explicit (typed fields enumerated in `.qfai/contracts/cli/qfai-prototyping.md`) and validate-conformant. Legacy shape is accepted-with-`D-DEPRECATED-SCHEMA`-warn through qfai 1.9.x and rejected at qfai 1.10.0.

### 6. `certify` self-completability (REQ-0113, spec-0012; OQ-0107 = B)

- Old: `certify.ts` read `.qfai/output/verify.json#status === "PASS"`. `/qfai-verify` PASS in turn required `/qfai-atdd` and `/qfai-implement` artifacts that the prototyping phase had not produced yet — circular dependency.
- New: `verify.json` gains a `scope` discriminator (`"prototyping"` / `"full"` / `"atdd"`). `certify` reads `verify.json#scope === "prototyping"`, which only gates prototyping-phase obligations. Reviewer-Gate finding `R-CERTIFY-VERIFY-CIRCULAR` (severity error, advisory-failing) fires if `certify` is observed reading a `verify.json` whose profile requires later-phase artifacts. `scope` was previously absent so the addition is purely additive (no contract break).

### 7. `validate` output (REQ-0114, spec-0004)

- Old: `qfai validate` wrote `.qfai/output/validate.json` regardless of profile; running multiple profiles overwrote each other's reports.
- New: Output is profile-suffixed (`.qfai/report/validate.<profile>.json`). Drift findings `D-DEPRECATED-PROBE` / `D-DEPRECATED-PATH` / `D-DEPRECATED-SCHEMA` integrate with `--report`. Legacy `.qfai/output/validate.json` consumers receive `D-DEPRECATED-PATH` warnings until sunset.

### 8. Screen-id casing (REQ-0116, spec-0012)

- Old: Screen ids appeared with mixed casing (kebab in templates, camel in iterate, underscore in evidence directories).
- New: Underscore casing is canonical end-to-end (`screens[].id` → `iter-NN/spec-NNNN/<screen_id>.review.json`). The casing rule is enforced by validator and surfaced in `.qfai/contracts/cli/qfai-prototyping-iterate.md`.

### 9. `qfai doctor` skills integrity default (REQ-0104, spec-0006)

- Old: `skills.integrity` defaulted to error; cosmetic edits to skill files in downstream projects blocked init.
- New: `skills.integrity` defaults to warning; `--strict` re-elevates it to error for CI use.

### 10. Cross-cutting documentation realignment (REQ-0124, `_policies`)

- Old: `qfai-prototyping/SKILL.md` Step H referenced `/qfai-verify`; `references/handoff.md` cited `.qfai/output/validate.json`; `references/generator-prompt.md` cited `playwright-cli`.
- New: All four reference files (`SKILL.md`, `references/iteration-loop.md`, `references/generator-prompt.md`, `references/handoff.md`) realigned with the new contract surface. `qfai validate` enforces the alignment via `W-SKILL-DOC-BROKEN-REF` (warning in 1.9.x, error at 1.10.0) per `_policies/07_Constraints.md` OC-62.

## Deprecation Window

- Window opens: qfai 1.9.1 (this memo's pinned version).
- Window scope: one minor release. All `D-DEPRECATED-*` findings emit at severity `warning` for the duration.
- Sunset: qfai 1.10.0. From that release onward, the same finding codes emit at severity `error`. Legacy code paths supporting the old forms MAY be removed after sunset.
- Downstream consumers MUST upgrade past qfai 1.9.x without crossing the 1.10.0 boundary unprepared.

## Recovery Instructions for Downstream on qfai@1.8.10

No action is strictly required during the qfai 1.9.x window — old artifact shapes continue to load with deprecation warnings. To migrate cleanly before the qfai 1.10.0 sunset:

1. **Upgrade the Playwright probe.** Install or rename the binary so `qfai doctor` finds `playwright` (not `playwright-cli`). Remove any `package.json#bin` entry that aliases the deprecated name.
2. **Rename `validate.json` consumers.** Replace references to `.qfai/output/validate.json` with `.qfai/report/validate.<profile>.json`. CI matrices that previously globbed a single output should now glob per-profile reports.
3. **Remove hand-authored capture scripts.** Delete project-local capture orchestrators under `tmp/`. Re-run `qfai prototyping iterate --capture --auto-serve` (opt-in flags) to let the CLI own the capture pipeline; populate `iterate-plan.json` Capture Contract per declared screen.
4. **Adopt `verify.json#scope`.** If any CI step parsed `verify.json#status === "PASS"` to gate the prototyping phase, switch to `verify.json#scope === "prototyping"` AND `status === "PASS"`. The `scope` field is additive — older consumers that ignore it remain functional during the window.
5. **Realign skill documentation references.** Run `qfai validate --profile docs` and resolve any `W-SKILL-DOC-BROKEN-REF` warnings before the sunset release.

## Legacy Compatibility

- All legacy artifact shapes (`prototyping.json` v1 schema, `playwright-cli` binary alias, `.qfai/output/validate.json` path, `iterate-plan.json` without Capture Contract) remain loadable during qfai 1.9.x.
- The matching `D-DEPRECATED-*` finding identifies what to migrate before sunset.
- Reviewer-Gate findings `R-PROMPT-SCANNER-DRIFT` and `R-CERTIFY-VERIFY-CIRCULAR` are advisory-failing from this release (no legacy-mode exemption) because they catch active drift rather than historical shape — both apply equally to qfai@1.8.10 and qfai 1.9.1 codepaths.
