# 04 Business Rules

## Purpose

- Decompose AC into explicit business rules.
- Every BR must reference one or more AC IDs.
- Every rule governs the `/qfai-migration-spec-to-story` skill or one of its
  step scripts, run against a project on the spec-pack layout.

## Granularity (required)

- One BR expresses one independently falsifiable rule.
- A rule that names several steps states one property all of them share.

## Reference Column Conventions

- `AC-Refs` and `NFR-Refs` hold comma-separated IDs and nothing else.
- `NFR-Refs` names the NFR IDs of the discussion pack
  `discussion-20260923063306456`, as listed in `01_Spec.md`.
- `Contract-Refs` is `-` on every row. The contracts this spec follows are
  CLI contracts, which are not one of the three traceable contract kinds. Each
  rule names the contract file and section it follows in its `Rule` cell.
- New-layout IDs appear as placeholders (`BF-NNNN`, `US-NNNN-NNNN`,
  `AC-NNNN-NNNN-NN`, `EX-NNNN-NNNN-NN`, `BR-NNNN`, `DEC-NNNN`, `OQ-NNNN`).
- `Notes` is free prose. Every obligation is also in the `Rule` cell.
