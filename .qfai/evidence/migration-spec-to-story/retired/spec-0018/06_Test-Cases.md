# 06 Test Cases

## Purpose

- Verify examples and acceptance criteria with explicit refs.
- Include both `AC-Refs` and `EX-Ref` whenever possible.
- Require normal path and declared valid boundaries per AC; require failures only for kept failures.
- Every case names the example it proves, and runs on the fixture that
  example describes (`05_Examples.md#Conventions`).

Derive each row's `Level` with
`.qfai/assistant/catalog/test-layers.md#layer-derivation-procedure-normative`.
One oracle per TC; a multi-valued `Level` is illegal.

## How `Level` was derived

- **L3, the default here.** A case copies the fixture into a temporary
  directory and runs a step on it in process, through the harness's `runStep`,
  the same call the step script makes. The four entry-point cases,
  `TC-0018-0001` to `TC-0018-0004`, spawn the real script instead, because
  what they observe is the loader. Either way the oracle reads what the step
  left on disk: files, directories, links, `qfai.config.yaml`, `.gitignore`,
  the tree hash. Where the oracle also reads the exit code or the report, the
  parent rule ties that value to the state of the tree ("before the first
  write", "the paths the real run changes", "the step exits 3 when it listed an
  item"), so the tree is what falsifies it. Real file-system state is L3.
- **L3, the two asset cases.** `TC-0018-0069` and `TC-0018-0072` read a file
  the package ships, `SKILL.md` and `references/migration-guide.md`. Their
  parent rules own the content of that file, and no function returns it, so the
  oracle reads a file on disk: L3.
- **L1, three pure mappings.** `TC-0018-0030` and `TC-0018-0031` observe only
  the value the decision status mapping returns for a record status, which is
  all `BR-0018-0023` owns. `TC-0018-0041` observes only the IDs the numbering
  returns for a plan, which is all `BR-0018-0032` owns. Writing those values
  into files is observed at L3 by `TC-0018-0028`, `TC-0018-0033` and
  `TC-0018-0043`.
- **Each L1 case compares its whole result in one assertion.** The mapping or
  the numbering is checked as one value, so every entry is observed on the
  first failing run and the case is not split per entry.
- **No case lands at L4 or L5.** The steps have no service boundary.
- **Every story also owes an E2E test.** No spec in this project declares a
  user-facing surface by any signal `test-layers.md` lists, so surface typing
  is not in use and `QFAI-ATDD-111` applies to every story. `tdd/test-list.md`
  therefore holds one `E2E` row for each of `US-0018-0001` to `US-0018-0010`.

## Level vocabulary

`Level` holds exactly **one** layer code from the crosswalk in
`.qfai/assistant/catalog/test-layers.md#layer-vocabulary-crosswalk-normative`:

- `L1` — Unit
- `L2` — Component
- `L3` — Integration

(Deliberately a list, not a table: `collectTestCaseIds` and the TDD coverage
report both read `parseFirstMarkdownTable`, so the **Test Case Table below must
be the first markdown table in this file**.)

`L1` and `L2` are TDD coverage targets — each needs a `tdd/test-list.md` row.
`L3` is not a coverage target, and still needs one: Phase 2b seeds it a
`Layer = Integration` row whose test `/qfai-atdd` authors.

`<testsDir>` is `paths.testsDir` from `qfai.config.yaml` (default `tests`); the
traceability scan follows the configured value.

### Type column values

- `normal` — Happy path / expected successful behavior.
- `error` — Error, failure, or invalid input path.
- `boundary` — Boundary value (min, max, just-outside-range).
- `edge` — Edge case (null, empty, concurrent, timing, max payload, etc.).

The failures kept here are the ones the contract names: the exit-2 refusals,
and every item a step lists under `## For a person` instead of settling it.
Each has a case of its own.

## Quality depth guideline

Each AC should have at minimum:

- One `normal` test case.
- Tests for every declared valid boundary.
- Failure tests only for kept failures.
