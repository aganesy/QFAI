# Migration Guide: v1.4.37 → v1.4.38

## 概要

v1.4.38 は **uiFidelity マーカーの SSOT 整合性修正**パッチリリースです。
v1.4.37 で導入された marker ベース hard gate（QFAI-PROT-242）の期待値生成が `elements[].label` ベースだった矛盾を修正し、`elements[].id`（安定 ID）ベースに統一します。

既存の evidence / contracts との後方互換を維持しています。

## 変更点

### マーカー SSOT の統一: `CONTRACT_ID:ELEMENT_ID`

v1.4.37 では autogen が `CONTRACT_ID:ELEMENT_LABEL` 形式でマーカー期待値を生成していましたが、ドキュメントと UI Contract README は `elements[].id` を安定 ID として推奨していました。

v1.4.38 でこの矛盾を解消し、以下に統一します:

| 項目                      | v1.4.37                     | v1.4.38                  |
| ------------------------- | --------------------------- | ------------------------ |
| autogen 期待マーカー      | `CONTRACT_ID:ELEMENT_LABEL` | `CONTRACT_ID:ELEMENT_ID` |
| `data-qfai` 推奨値        | 曖昧（label/id 混在）       | `CONTRACT_ID:ELEMENT_ID` |
| `expected.ids` フィールド | なし                        | 追加（任意）             |
| validator PROT-242        | label ベース固定            | ids 優先、旧形式も許容   |

### `expected.ids` フィールドの追加

`uiFidelity.screens[].expected` に `ids` フィールドが追加されます:

```jsonc
{
  "expected": {
    "elements": 2,
    "actions": 1,
    "labels": ["検索", "テーブル"],
    "ids": ["search_input", "orders_table"], // NEW in v1.4.38
  },
}
```

- autogen を再実行すると自動的に `ids` が含まれます。
- 手動で追加する場合は contracts/ui の `elements[].id` を列挙してください。

### QFAI-PROT-242 の評価ロジック変更

autogen が evidence を生成する際、各 element について id ベースのマーカー（`CONTRACT_ID:ELEMENT_ID`）を期待します。DOM に id ベースのマーカーが見つからない場合、autogen は対応する label ベースのマーカー（`CONTRACT_ID:ELEMENT_LABEL`）も後方互換でチェックします。

| 条件                                                        | 結果              |
| ----------------------------------------------------------- | ----------------- |
| DOM に `CONTRACT_ID:ELEMENT_ID` マーカーあり                | found（推奨）     |
| DOM に `CONTRACT_ID:ELEMENT_LABEL` マーカーのみ（旧形式）   | found（後方互換） |
| どちらのマーカーも DOM にない                               | missing → error   |
| 旧 evidence（`expected.ids` なし）で `missing.markers` 非空 | error（従来通り） |

validator は evidence の `missing.markers` をそのまま評価します。後方互換の label-to-id フォールバックは autogen 側で処理されるため、validator の判定ロジックはシンプルに保たれます。

## 後方互換

- v1.4.37 以前の evidence（`expected.ids` なし）では v1.4.38 の新ロジックは発火せず、従来通り動作します。
- 旧形式のマーカー（`CONTRACT_ID:ELEMENT_LABEL`）を貼っている画面でも、validator は後方互換で許容します。
- 新形式への移行は段階的に実施可能です。

## 最小移行手順

1. `pnpm install qfai@^1.4.38`
2. 既存の evidence はそのまま動作します（後方互換）。
3. 新形式に移行するには:
   - `qfai prototyping --autogen-ui-fidelity --base-url <URL>` を実行して evidence を再生成
   - 画面のマーカーを `data-qfai="CONTRACT_ID:ELEMENT_ID"` 形式に更新（推奨）
4. contracts/ui の `elements[].id` が安定 ID として使われます。`label` はランタイム検査対象テキストです。

## 将来の計画

- v1.5.0 以降で旧形式（`CONTRACT_ID:ELEMENT_LABEL`）の段階的廃止を検討します。
- 移行中は新旧両形式が許容されます。
