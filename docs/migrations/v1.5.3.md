# Migration Guide: v1.5.2 → v1.5.3

## 概要

v1.5.3 は layered spec の上位ディレクトリを **`.qfai/specs/_shared/` から `.qfai/specs/_policies/` へ変更する破壊的変更**です。

合わせて、Execution 系 skill の入口を各 spec ディレクトリ配下の `01_Spec.md` に固定し、`_policies` は **Escalation Hook が必要なときだけ読む判断基準レイヤ**として扱います。

後方互換は維持しません。既存リポジトリは本ガイドに従って移行してください。

## Breaking Changes

### 1. 上位ディレクトリ名: `_shared` → `_policies`

| v1.5.2                                  | v1.5.3                                    |
| --------------------------------------- | ----------------------------------------- |
| 上位ディレクトリ名: `_shared`           | 上位ディレクトリ名: `_policies`           |
| `03_Capabilities.md` は `_shared` 配下  | `03_Capabilities.md` は `_policies` 配下  |
| `04_Business-Flow.md` は `_shared` 配下 | `04_Business-Flow.md` は `_policies` 配下 |
| `05_Contracts.md` は `_shared` 配下     | `05_Contracts.md` は `_policies` 配下     |

validator、skill 文書、wrapper reminder、README、命名規約も `_policies` 前提に変わります。

### 2. Consumer View 固定

- Execution の Primary SSOT は各 spec ディレクトリ配下の `01_Spec.md` です。
- `01_Spec.md` は以下を copy-down で保持する必要があります:
  - Applicable NFR
  - Applicable Policy
  - Evidence Summary
  - Relevant Requirements
  - Escalation Hook

### 3. Execution skills の Read Set Contract 変更

- Default Mode:
  - `01_Spec.md` と必要な spec/contracts のみ読む
- Escalation Mode:
  - `01_Spec.md` の Escalation Hook が発火したときだけ `_policies` を読む

## 移行手順

### Step 1: init assets / skill 文書を更新

```bash
npx qfai init --force
```

これにより init scaffold、skill 文書、wrapper reminder が v1.5.3 の `_policies` 前提に更新されます。

### Step 2: 既存ディレクトリをリネーム

```bash
mv .qfai/specs/_shared .qfai/specs/_policies
```

PowerShell の場合:

```powershell
Move-Item .qfai/specs/_shared .qfai/specs/_policies
```

### Step 3: spec 参照を置換

既存 spec / skill / review メモなどに残っている `_shared` 参照を `_policies` 参照へ置換します。

最低限、次の参照は更新してください:

- 各 spec ディレクトリ配下の `01_Spec.md` にある Escalation Hook
- skill / wrapper / review checklist の上位参照パス
- 手書きの migration / runbook / review notes

### Step 4: validate 実行

```bash
npx qfai validate
```

`_shared` を前提にしたパスが残っていると、`_policies` 必須ファイル不足や Business Flow / Capabilities 参照エラーとして検出されます。

## 確認ポイント

- `.qfai/specs/_policies/` が存在する
- `.qfai/specs/_shared/` が存在しない
- 各 spec ディレクトリ配下の `01_Spec.md` に Escalation Hook がある
- skill 文書が `_policies` を参照している
- `qfai validate` が通る
