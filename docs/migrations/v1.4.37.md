# Migration Guide: v1.4.36 → v1.4.37

## 概要

v1.4.37 は **uiFidelity validator の hard gate 強化**と **autogen の運用安定化**を行うパッチリリースです。
既存の evidence / contracts との後方互換を維持しています。

## 新しいバリデーションルール

### QFAI-PROT-241 (error)

`uiFidelity.screens[].expected.labels` が存在する場合、`missing.labels` が空でなければエラーになります。

**適用条件**: `expected.labels` フィールドが存在する場合のみ。旧形式の evidence（labels なし）では発火しません。

**対処法**: contracts/ui の `elements[].label` をすべて画面に描画してください。描画が難しい要素は `data-qfai` マーカーで代替できます。

### QFAI-PROT-242 (error)

`uiFidelity.screens[].expected.elements > 0` かつ `missing.markers` が空でない場合にエラーになります。

**対処法**: 画面の各要素に `data-qfai="CONTRACT_ID:ELEMENT_LABEL"` 属性を追加し、autogen を再実行してください（例: `data-qfai="CON-UI-0001:search_input"`）。

### QFAI-PROT-243 (warning)

`expected.elements > 2` だが `observed.elementsPlaced <= 1` かつ `found.labels` が 1 件以下の場合、プレースホルダーページとして警告します。

**対処法**: contracts/ui の全要素を画面に配置してください。

## autogen の変更点

### route hints の自動取得

`qfai prototyping --autogen-ui-fidelity` は、既存の evidence から以下の順で route hints を自動取得します:

1. `runtimeGate.ui[].route`
2. `specs[].missing.uiRoutes`

contracts/ui に route が不足していても、runtimeGate に記録があれば autogen が動作します。

### no-op 防止

- `--autogen-only` が指定されているが `--autogen-ui-fidelity` / `QFAI_PROTOTYPE_FIDELITY_AUTOGEN=1` がない場合、exit code 2 を返します。
- autogen 未有効時は `uiFidelityAutogen.status=skipped` が evidence に書き込まれ、doctor/report から検知可能です。

### label 抽出の厳格化

- body テキスト全文のトークン化はデフォルト無効になりました（`QFAI_AUTOGEN_BODY_TOKENS=1` でオプトイン可能）。
- label 一致判定は正規化完全一致のみ（部分一致を廃止）。
- `data-qfai` 属性からのマーカー抽出を追加。marker ベースの fidelity を主軸に。

## 最小移行手順

1. `pnpm install qfai@^1.4.37`
2. 既存の evidence に `expected.labels` / `found` / `missing` がなければ、v1.4.37 の新ルールは発火しません（後方互換）。
3. 新ルールを有効にするには:
   - `qfai prototyping --autogen-ui-fidelity --base-url <URL>` を実行して evidence を再生成
   - または手動で `uiFidelity.screens[].expected.labels` を追加
4. 画面要素に `data-qfai="CON-UI-0001:search_input"` マーカーを追加すると、marker ベースの fidelity チェックが有効になります。
   - マーカーの値は `CONTRACT_ID:ELEMENT_LABEL` 形式です（例: contracts/ui で `elements[].label: search_input` なら `data-qfai="CON-UI-0001:search_input"`）。
   - autogen は contracts/ui の `elements[].label`（重複排除・ソート済み）をそのまま使用して期待マーカーを生成します。
   - contract に要素を追加・変更しても、ラベル名が変わらない限り既存マーカーは有効です。
