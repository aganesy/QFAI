# Migration Guide: v1.4.35

## Overview

v1.4.35 does not add new hard gates or change thresholds.
This release focuses on Ops/Docs quality and better diagnostics for existing
`QFAI-PROT-232` findings.

## What changed from v1.4.34

1. UI contract guidance now clarifies:
   - stable naming and change policy for `elements[].id`
   - `elements[].label` handling as inspection-target text
   - minimum `actions[]` writing for L2 mockable flows
   - `prototype.mode` and `mockPaths[]` examples
2. Reviewer checklist templates now include prototyping triage order and
   fail-to-fix workflow.
3. `QFAI-PROT-232` diagnostics now expose actionable refs in JSON output:
   - `contract_id=...`
   - `route=...`
   - `contract_element_labels=...` (primary ref when element label coverage mismatch is detected)
   - `contract_element_labels_by_contract_route=...` (element label mismatches grouped by contract+route)
   - `missing_labels=...` (backward-compatible alias of `contract_element_labels`)
   - `required_actions=...` (when actions are declared but not wired)

## Migration action (recommended)

1. Re-check `.qfai/contracts/ui/*.yaml` for stable IDs and labels.
2. Re-run prototyping and refresh the prototyping JSON evidence file under `.qfai/evidence/`.
3. Run:

   ```bash
   qfai validate --fail-on error
   ```

4. If `QFAI-PROT-232` appears, follow refs in `validate.json` to fix contract,
   route, label rendering/markers, and action wiring.
