# Migration Guide: v1.4.35 → v1.4.36

## Overview

v1.4.36 introduces **uiFidelity auto-generation** via `qfai prototyping --autogen-ui-fidelity`.
This feature reduces manual evidence maintenance by automatically crawling UI routes and collecting DOM labels.

## What's new

- New CLI command: `qfai prototyping --autogen-ui-fidelity --base-url <url>`
- New env vars: `QFAI_PROTOTYPE_FIDELITY_AUTOGEN=1`, `QFAI_PROTOTYPE_BASE_URL`
- New dependency: `jsdom` (added to runtime deps)

## Breaking changes

None. Existing workflows continue to work without modification.

## Migration steps

### 1. Update dependency

```bash
pnpm install qfai@^1.4.36
```

### 2. (Optional) Enable autogen in CI

If you want to auto-generate `uiFidelity` evidence in CI:

```yaml
- name: Start app
  run: npm start &
  env:
    DISABLE_AUTH: "true"

- name: Wait for app
  run: npx wait-on http://localhost:3000

- name: Run uiFidelity autogen
  run: npx qfai prototyping --autogen-ui-fidelity --base-url http://localhost:3000
```

### 3. (Optional) Update local workflow

For local development, you can use env vars:

```bash
export QFAI_PROTOTYPE_FIDELITY_AUTOGEN=1
export QFAI_PROTOTYPE_BASE_URL=http://localhost:3000
npx qfai prototyping
```

## Autogen prerequisites

For autogen to work well:

1. **Labels must render in DOM**: UI text should appear as `textContent`, `aria-label`, `placeholder`, `alt`, or `title` attributes.
2. **Routes must be reachable**: If your app requires auth, provide a bypass or fixture mode.
3. **Contract files must exist**: `contracts/ui/**/*.yaml` with `screens[].route` and `screens[].elements[].label`.

## Failure behavior

- If autogen fails, `uiFidelityAutogen.status=failed` is written to evidence.
- Existing `uiFidelity` data is NOT removed (safe fallback).
- Use `--autogen-only` to fail the command (exit 1) when autogen fails.

## Rollback

To rollback, simply revert to v1.4.35:

```bash
pnpm install qfai@1.4.35
```

The autogen feature is opt-in; removing v1.4.36 has no side effects on existing evidence or validation.
