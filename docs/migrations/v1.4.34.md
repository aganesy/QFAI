# Migration Guide: v1.4.34

## Overview

v1.4.34 turns `uiFidelity` into a hard gate for interactive prototyping evidence.

- `QFAI-PROT-231` (`error`): `uiFidelity` is required when mode is interactive (default).
- `QFAI-PROT-232` (`error`): `uiFidelity.screens[]` must satisfy referenced UI contract expectations.
- `QFAI-PROT-233` (`warning`): interactive evidence should include at least one `mockPaths.status=pass`.

## What to update from v1.4.33

1. Add `uiFidelity` to the prototyping evidence JSON (`prototyping.json` in the evidence directory) for interactive flows.
2. Ensure each screen references a valid `uiContractId` and matches contract route coverage.
3. Ensure `observed.elementsPlaced` matches `expected.elements`.
4. Ensure at least one action is wired when the referenced contract screen defines actions.
5. Add at least one `mockPaths` entry with `status: "pass"` (warning in v1.4.34).

## Minimal fix examples

### A. Keep L2 interactive (recommended for mockable prototype)

```json
{
  "uiFidelity": {
    "version": "0.1",
    "mode": "interactive",
    "screens": [
      {
        "route": "/orders/new",
        "uiContractId": "CON-UI-0001",
        "expected": { "elements": 3, "actions": 1 },
        "observed": { "elementsPlaced": 3, "actionsWired": 1 },
        "mockPaths": [{ "id": "mp_create_to_list", "status": "pass" }]
      }
    ]
  }
}
```

### B. Use L1 skeleton temporarily

If your current project is not ready for interactive fidelity evidence, switch mode to skeleton until interactive evidence is prepared.

```json
{
  "uiFidelity": {
    "mode": "skeleton",
    "screens": []
  }
}
```
