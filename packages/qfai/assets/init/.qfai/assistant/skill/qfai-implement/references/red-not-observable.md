# RED Not Observable

## Classify a passing test

A first test may pass because existing code already meets the example. Inspect the assertion and its exact target before calling that result a completed cycle. An unrelated pass, a skipped selector, or a weak assertion takes the ordinary RED repair path.

When the behavior already exists, record the example ID, the code that satisfies it, the test command and its passing result. Then change the smallest predicate that supplies that behavior, rerun the same test, and capture the assertion failure. Restore the predicate and rerun the test to confirm the original pass. Record both revisions and outputs as falsifiability evidence.

The mutation is a probe and is removed before any review or commit. Its target is the predicate identified as satisfying the example, even when that predicate lives in a shared module. The cross-flow ownership check determines which other flows must be revalidated.

A test that cannot be made to fail through its named behavior has no valid proof. Improve its oracle, or raise the upstream contract gap through the drift protocol. The report must say which route was taken.
