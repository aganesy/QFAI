---
name: commit
description: 本セッションの変更のみを適切な粒度でコミット（変更が無ければ差分全体をコミット）
---

> **言語**: 出力は全て日本語
>
> **目的**: 本セッションで行った変更を、意図が伝わるコミットメッセージ付きで、適切な粒度に分割してコミットする。

---

## 完了条件

- [ ] **本セッションで修正したファイル**がコミットされている
- [ ] 本セッションで**修正が一切ない**場合、`git status` の差分がすべてコミットされている
- [ ] 本セッションで修正したファイル以外の差分がある場合、それらは**未コミットのまま**になっている
- [ ] コミットが適切な粒度で分割されている（下記「粒度の判断基準」）
- [ ] 各コミットメッセージが「何を/なぜ/効果」を端的に説明している

---

## 粒度の判断基準

以下を優先して、自然に分割する（迷う場合は「小さめに分ける」を優先）:

1. **関連するファイル単位**（同一目的の変更は同一コミット）
2. **本セッションにおける作業フェーズ単位**（調査/リファクタ/仕様対応/バグ修正など）
3. **QA指摘やPRコードレビュー指摘単位**（指摘ごとに分ける）

追加の目安:

- 仕様変更（振る舞い）と、機械的変更（フォーマット/リネーム等）は混ぜない
- 依存更新・生成物の更新は、可能なら他と分ける

---

## 実行手順

### Step 1: 前提確認

```bash
git branch --show-current
git status --porcelain
```

---

### Step 2: 「本セッションで修正したファイル一覧」を確定

- このセッション中にあなたが行った `apply_patch` / 追加 / 更新 / 削除の対象ファイルを、会話ログから列挙して **`SESSION_FILES`** として確定する
- **直接編集していなくても**、本セッション内の作業に起因して生成・変更されたファイル（ツール導入による設定ファイル生成、コマンド実行による自動生成物など）も `SESSION_FILES` に含める
- **95% 以上の確信が持てない場合は、ここで停止してユーザーに確認**（推測で進めない）

---

### Step 3: コミット対象を決定

1. `SESSION_FILES` が **1件以上**ある場合

- `git status --porcelain` の差分のうち、`SESSION_FILES` に含まれるものだけをコミット対象にする
- `SESSION_FILES` 以外の差分が存在しても、**ステージングもコミットも絶対にしない**

2. `SESSION_FILES` が **0件**の場合

- 現在の `git status --porcelain` の差分を **すべて**コミット対象にする

差分が0件の場合は「作業なし」として完了。

---

### Step 3.5: 確信が持てない差分の確認（必要時）

コマンド実行や MCP ツールによって間接的に生成・変更されたファイルは、完璧に追跡することが難しい場合がある。

以下のいずれかに該当する差分がある場合は、**コミット前にユーザーに確認を求める**:

- `SESSION_FILES` に含めるべきか判断がつかない差分
- 本セッションの作業に起因するか確信が持てない差分
- ツール実行や MCP によって生成された可能性があるが、明確に追跡できていない差分

**確認の形式**:

```markdown
## 確認依頼: 以下の差分の扱いについて

本セッションの作業に起因するか確信が持てない差分があります。どのように対処すべきか判断をお願いします。

| ファイル/ディレクトリ | 状態           | 推測される原因 | 対処案                   |
| --------------------- | -------------- | -------------- | ------------------------ |
| `<path>`              | 新規/変更/削除 | <推測>         | コミットする/しない/不明 |

ご指示ください:

1. すべてコミット対象に含める
2. 一部のみコミット対象に含める（対象を指定）
3. すべてコミット対象外とする
```

---

### Step 4: （必要時）TypeScript変更の品質チェック

コミット対象に TypeScript（例: `*.ts` / `*.tsx`）が含まれる場合は、コミット前に必ず以下を実行して結果を報告する。

```bash
pnpm format:check
pnpm lint
pnpm check-types
```

- 失敗した場合は、根本原因を修正して再実行する
- 同じ失敗が3回以上続く/原因特定が不確実な場合は、現状（ログ要点/試行/判断点）をまとめて停止

---

### Step 5: コミット分割案を作る（実行前に短く提示）

- コミット対象の差分を `git diff --name-only` / `git diff --stat` で把握
- 上の「粒度の判断基準」に従い、**コミット分割案（コミットごとのファイル一覧）**を作成して提示

---

### Step 6: ステージング → コミット（分割した順に繰り返す）

原則は「必要なファイルだけを `git add -- <files...>` でステージ」。
削除/リネームを含む場合は、対象ファイルに対して `git add -A -- <files...>` を使う。

```bash
git add -- <files...>
git diff --cached --stat
git commit -m "<何を/なぜ/効果>"
```

注意:

- `SESSION_FILES` があるケースでは、`git add -A` や `git add .` での一括ステージングは禁止（意図せず他差分が混入するため）

---

### Step 7: 事後確認

```bash
git status --porcelain
git log -n 5 --oneline
```

- `SESSION_FILES` があるケースでは、`SESSION_FILES` 以外の差分が残っていることを確認（残っていてOK、むしろ正）

---

## コミットメッセージのルール

- 1行で「何を/なぜ/効果」を端的に書く（冗長にしない）
- 例:
  - `search: 空文字クエリを無視して不要な取得を防ぐ`
  - `docs: セットアップ手順を追記しオンボーディングを短縮`

---

## 報告フォーマット

```markdown
## コミット結果

- 対象: SESSION_FILESあり/なし（対象ファイル数: N）
- 作成コミット: N件
  - <hash> <message>
- 未コミット差分: <有/無>（SESSION_FILES外の差分は残してOK）
```
